# 原题直搜与首次 Observation：来源笔记节点设计

版本：first_observation_v1。状态：实现与离线验证完成，真实 BC+ / 模型实验尚未执行。该节点是独立实验，不替换默认 Agent，不重写历史报告。

## 1. 这轮为什么这样收窄

已有讨论担心：在没有外部观察时，生成式 Query 改写、选材或初始 goal 会引入未经证实的实体、时间和关系；即使不改 Query，先生成 candidate/criteria 也可能把相同错误写进后续状态。当前仓库默认 Agent 仍让模型生成 search(query)，并没有强制 query 等于原题。本实验明确增加一个独立入口，而不是声称旧默认已经如此。

本轮约定：

```text
完整原题 Q
  → harness 直接执行 search(query=Q, k=5)
  → 第一次真实窗口 O1
  → 可选的来源笔记 N1
  → 同一 O1 上的一次下一决策 A/B
```

首搜前语义状态为空；模型初始化调用为零。不先生成 goal、source_clues、候选、条件表或 gap；不要求模型复制原题，而是程序直接传入同一个字符串。普通空白、换行与 Unicode 字符不规范化、不摘要。检索器自身已有的查询指令前缀不属于语义改写，计入 embedding token 检查。

采用原题直搜是本轮固定上游条件，不是“原题在所有问题上最优”的结论。原题过长、首搜无关、词法定位失准都可能出现，不能要求笔记节点凭空补救。

## 2. 只证明两件事

**H1：局部保真。** 给定 Q 和实际 O1，来源笔记是否准确保留主体、关系、时间、否定及必要限定，而不把题目条件、检索相关性或模型记忆写成候选事实？

**H2：即时使用价值。** 在相同 Q、原题首搜记录和 O1 下，增加实际生成的笔记，是否减少下一决策的证据误用或帮助合理取证，且成本值得？

H1 成立不代表 H2 成立。H2 改善是“新增一次来源整理及其交接”的总干预效果，包含额外推理与信息突出，不能直接归因于存储格式。它不是跨步记忆、自动长期 State、完整 gap、最终答题准确率或原题首搜最优性的证明。

## 3. 节点输入与输出

笔记模型只看到 `question / first_query / observation`。qid、标准答案、预设候选、旧 s21/s29/s53 长历史、人工笔记、未来工具结果和未见全文均不进入请求。qa.jsonl 由程序解析后只投影 query_id 和 query；其他字段不保存、不用于提示词或筛选。

输出是严格 JSON，零到三条：

```json
{"notes":[{"statement":"来源实际表达的关系。","source_ref":"实际window_ref","quote":"窗口正文的连续逐字引文"}]}
```

三条上限与 statement 长度保护是首版工程设置，不是已优化参数。每条仅引用一个实际窗口；第一版不做跨来源拼接。正文内可利用同窗上下文解析主体。只在标题中出现的词不满足本版 quote 合同；标题仍原样提供给 Actor，不被删除。不能强迫每篇结果生成一条笔记；无相关内容时允许 `{"notes":[]}`，但漏掉明确有用关系也要记为错误。

原始来源不保证世界事实正确；statement 是模型可错的解释。程序只验证格式、实际窗口成员关系、引文连续子串、范围和长度。`status=ok` 表示结构可消费，不代表语义证实。已加入“错误statement也可能通过quote校验”的测试，防止混淆。

不新增 candidate、confidence、gap、next_need、goal、plan、answer_ready。也不声称新笔记相对于整个未来研究具有信息增益。

## 4. 首搜采集与可追溯性

`select` 在取证前锁定题目及 qa.jsonl 散列；重复ID、缺题、重复数据记录直接报错。建议首批六个已知开发题 517、546、776、519、191、71；不称未见题或独立验证集，不能按首搜结果重新选择“好例子”。

`collect` 不创建生成客户端，不调用生成模型。实际适配器复用 `ObservedTools(variant='baseline')`、`RawWindowBuilder` 和现有 BCPlusSearcher；不改检索器、排序、窗口、提示词或默认 Agent。每题一个新 ObservationStore，保存真实窗口及原文版本，供将来明确授权的 Open 恢复；模型阶段只读取捕获的 O1，不访问 SQLite 全文。

固定默认 top5，每窗口标题＋正文最多400 tokens。每题只调用一次 Search，不执行 Open。先用实际 tokenizer、metadata.query_prefix 与 special tokens 计算完整查询长度，`truncation=False`，超过1024 tokens或现有工具16000字符限制则记录 query_over_budget，不裁剪、不生成替代词。检查的是现有检索调用边界；更换外部 BCPlus 脚本时须重新核查其内部前缀与截断设置。

采集前保存计划；保留实际 search_request/search_response；输出源中每个 query 必须严格等于 question。语料/索引文件、查询模型权重与 tokenizer 配置、检索脚本及窗口实现记录 SHA256；运行期间检查文件大小/修改时间未变。哈希会产生额外I/O，不计入模型token。哈希是完整性记录，不是来源真实性签名。不要对仍在写入的语料或索引采集。

合法空返回是 ok + []；检索边界异常是 search_error，保留异常类型但不泄露可能含凭据的错误原文。它不是“无关”的语义标签。窗口格式不符合冻结协议、运行中资产变化等是 harness/环境问题，停止并保留未运行分母。

## 5. 分阶段实验，不自动推进

### 阶段一：O1 → 来源笔记

六题各一次首搜和一次笔记调用：最多6次Search、6次模型调用、0次初始化调用。首搜失败题仍留在选择分母，模型节点标 skipped_first_search；不伪称模型已尝试。对所有实际笔记做来源复核；空、截断、API失败都单列。发现系统性读错时先停在此节点。

复核不修改实际输出。若以后要测试人工正确笔记，单独标注为人工诊断条件，不混入自动节点结果。没有“反复抽样直到一批全成功”的准入门槛。

### 阶段二：固定 O1 的 A/B 下一决策

显式执行新命令才开始此阶段，默认每题每组一次，最多12次Actor。A看Q、实际query、全部O1；B只多一个标为模型生成可错解释的notes消息。两组system、工具定义、采样/预算和原文完全相同。两组都没有初始goal。

笔记结构有效且非空才注入B。空笔记、无效格式/引用和笔记API失败均执行无笔记回退，B请求与A逐对象相同；分别记录原因和memo_injected。这样可评估实际策略，包括失败回退，但回退后的成功不归功于笔记。笔记发生不可恢复的本地错误/中断/漏跑时，不允许用缺失记录悄悄生成Actor计划。

同一笔记生成结果只使用一次，按题供后续重复Actor共享。笔记成本只计一次；当增加Actor重复时，须说明这是固定笔记下的动作采样，不是重新运行完整链路。报告同时列出完整策略、实际注入后的描述性子集与新增错误，不能只汇报成功笔记子集。

第一版只保存下一工具意图，不执行任何提议。Open只能指向本次已见窗口。普通最终回答/弃答保留原文，由评阅区别；不靠关键词自动判答案正确。多工具批次完整保留并一起评价。

## 6. 评阅与归因

先依据Q和O1写多种合理下一动作，再看笔记和Actor，记录是否已知旧病例/输出。导出卡片遮盖部分分组元数据不等于盲评，笔记本身会暴露处理组。单代理辅助评阅不是独立人工金标。

最小评价轴：来源支持、主体/关系/限定保真、关键局部信息覆盖、下一动作是否使用O1、是否新增无据断言、完整动作是否合理。各轴分别使用 yes/no/unknown/not_applicable，并附实际窗口依据和说明。没有可消费输出不是来源理解0分；失败仍保留运行分母。

来源笔记不得用模型常识补成“原文事实”。Actor的合理背景推导和探索假设可用于构造查询，不能一概按“原文没有这个词”判幻觉；但不能将其冒充已读来源或最终答案证据。例如题目条件经规则推导的年份，与无依据断言某候选出生年，应分别记录。事前约定口径，保留边界敏感性，不事后改标签求涨分。

相似query不是自动坏例；同文档不同窗口也不等于重复。未执行新工具，不报告新证据获取率。A本来合理、B也合理，不能证明笔记必要；B修复A的具体错误才是局部正向信号，还需要独立重复/新题检查。B引入的错误同等重要。

六题第一轮是开发诊断，不做统计显著性或BC+准确率宣传。有正向信号后才考虑原文摘录控制，区分关系整理和简单重复强调；之后再研究跨步保留与修订。若即时无收益，不把模块升级默认，也不据此否定所有State设计。

## 7. 失败后只修改对应节点

| 观察到的问题 | 下一次要隔离的因素 |
|---|---|
| 首搜没有有用信息 | 原题入口/召回/窗口，不让State制造知识 |
| 原文明确、笔记错绑 | 来源解读 |
| 笔记正确但漏掉关键关系 | 内容选择 |
| 笔记正确但Actor忽略或过度相信 | 交接及证据使用 |
| 两组都正确且B更贵 | 暂不启用笔记 |
| 截断/超时 | 交付配置与职责边界，保留未知成本 |

不自动添加 hypothesis、binding graph、attempt memory或stop字段。原始实验材料继续保留；新节点不复写旧Notebook方案。
