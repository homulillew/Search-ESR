# Query 探索原则提示词两步对照实验

本轮比较当前 Agent 提示词与追加三句探索原则后的提示词。两组都由模型直接生成 Search/Open 动作，没有独立 Selector、Compiler 或 ResearchState。实验复用前一轮的 20 道开发题，每题每组两次，共 80 条短轨迹，观察范围为首搜及其后一次行动。

**新提示词改善了部分题目的搜索入口，但没有改善整体第二步的新增依据获取。当前保留原提示词，结束这一轮 Query 优化。** B 组首搜可见依据率从 A 组的 35% 到 40%，两步累计可见依据率从 40% 到 45%；第二步严格新增依据率则为 A 组 35%、B 组 32.5%。局部改善与退化同时存在，不需要据此继续增加 Query 模块。

完整记录见[正式运行与轨迹索引](../experiments/query_initialization/exploratory_policy/runs/20260918T092827.910487Z/README.md)。

## 1. 这次比较的增量

此前实验表明，额外选材和编译没有取得足以支持默认采用的稳定收益。本轮只检验一个更小的变化：模型已经能够自主调用 Search，在提示词里明确首搜与后续行动的目标，是否有帮助。

A 组使用当前 Agent 提示词，B 组仅追加：

> Begin with a distinctive, independently searchable entry into the question; you do not need to cover every condition in the first search.
>
> You may omit conditions, but preserve the subjects, relationships, negation, and time scope of those you use, and treat unverified identities as hypotheses.
>
> After observing the results, choose the next search or open from what the returned text actually establishes and what remains unresolved.

这三句分别引导入口选择、所用条件的忠实表达，以及观察后的下一步行动。本轮比较整段提示词，不将结果归因到其中某一句。它借鉴模型自主探索的思路，不是 AREX 模型或完整评测系统的复现。

为控制预算，两组都增加了相同的实验说明：首步必须执行一次 Search，第二步可 Search、Open 或在依据足够时回答。首步强制工具选择，第二步为 auto；一次响应最多一个工具调用，不实施多 query。因此，A 是受控的短链对照，不能称为不受限制的完整默认 Agent。

## 2. 配置与执行

| 项目 | 设置 |
|---|---|
| 题目 | 前轮相同的 20 道开发题，不称未见验证 |
| 重复 | 每题每组两次，共 80 会话 |
| 模型 | qwen3.7-flash，thinking=false |
| 输出上限 | 每次请求 1536 tokens |
| 最大动作 | 两次，不追加最终强制回答调用 |
| Search | top6，每个原文窗口含标题最多 400 tokens |
| Open | 沿用 before/after/around，未新增 focus |
| 观察上限 | 每动作 2400、每会话 4800 个标题与正文 tokens |
| 查询上限 | 含 embedding 前缀及特殊 token 最多 1024 tokens |
| 并发 | API 实际峰值 8，检索实际峰值 2 |

不进行格式修复、结果驱动重试、隐式回退或静默截断。两组使用相同检索器、索引、窗口构建、工具 schema、预算说明和调度规则；差异仅为 B 的三句提示词。

正式运行共 155 次 API、147 次 Search、1 次 Open，报告用量为 485,427 tokens。42 项契约测试通过；独立机械审计核对了实际请求差异、第二步消息历史、执行参数、预算、原文区间、标题、引用及观察账本。检索副本的 6 次预检单列，不混入正式 Search。

### 接口兼容性诊断

正式批次之前有一个单独保留的 v001 技术失败批次。服务端在强制首搜时，将完整工具调用的结束标记返回为 `stop`；初版校验器只接受 `tool_calls`，因此没有执行任何实验检索。该批次共 80 次 API、95,490 tokens，其中 73 次为 stop、7 次为 length。

v002 只修正接口适配：允许 stop 或 tool_calls，仍须同时满足唯一工具调用、完整 JSON 和合法参数；length 继续拒绝执行。题目、提示词、预算及调度未根据结果修改，全部 80 会话统一重新运行。原批次没有覆写，也不与正式效果合并。

本任务两批合计 235 次 API、580,917 tokens。诊断记录见[v001 归档](../experiments/query_initialization/exploratory_policy/runs/20260918T092448.634346Z/README.md)。该兼容修正仅用于实验代码，默认 Agent 未改动。

## 3. 怎样判断推进

来源效用与窗口可见性分开：一篇文档在全文中有依据，不代表本次模型已经读到。第二步新增依据还要满足更严格的条件：它提供了首步没有展示的新事实或关系，而且与原题研究有关。新字符、新 URL、换一个来源复述同一事实，都不自动计为推进。

本轮审阅覆盖全部 80 会话、420 个题目—文档组合、527 个不同窗口，记录 42 个池内确认来源，156 个证明区间经数据库原文、散列及实际可见范围核对。所有返回窗口均已筛查；窗口外的查阅范围逐项记录，没有将未读全文判为无关。另一个代理以独立字符覆盖方法复算了六题的 24 会话，结果一致。

定性判断由协作代理完成，部分非盲，不是独立人工金标准，也不是完整 qrels。指标描述这批开发题中的已确认收益，不称为全库召回率或完整解题正确率。

有些材料只有在当前会话已识别对象后才有价值。例如，qid=519 首步确认传记作者是 Niyazi Kizilyurek，第二步读到其 1990 年博士学位，才构成有依据的条件核验。这样的条件性收益只记在该会话，不把这篇简短人物简介自动算成所有会话的有效入口。

首步失败保留在分母内；第二步失败仍保留首步实际取得的依据。先计算每题每组两次的均值，再汇总 20 题，不取 best-of-two。

## 4. 结果

### 4.1 运行与效用

| 指标 | A 当前提示词 | B 探索原则 |
|---|---:|---:|
| 完成两步工具执行 | 38/40 | 35/40 |
| 首步有用来源 | 15/40，37.5% | 17/40，42.5% |
| 首步可见有用依据 | 14/40，35% | 16/40，40% |
| 两步累计有用来源 | 16/40，40% | 19/40，47.5% |
| 两步累计可见有用依据 | 16/40，40% | 18/40，45% |
| 第二步严格新增相关依据 | 14/40，35% | 13/40，32.5% |
| 第二步使可见依据从无到有 | 2/40 | 2/40 |
| API tokens | 244,607 | 240,820 |

七条未完成会话中，六条结束标记为 length；另一条在要求首搜时直接回答，没有工具调用。没有传输错误。没有会话在合法首搜后于第二步正常停止回答；本轮也未继续到最终提交。

B 的累计可见依据比 A 高 5 个百分点，但首步也正好高 5 个百分点。两组第二步使依据从无到有的次数相同，说明目前较明确的收益在于部分题目的初始入口，不能将累计差异解释成后续研究能力提升。

第二步严格新增按题比较为 B 两胜、三负、十五平。qid=519 是两次重复均改善，qid=191 则是两次重复均退化。仅看完成两步的会话，A 为 14/38，B 为 13/35，也很接近；这个描述性结果不替代含失败的主分母。

### 4.2 行为与重复

| 第二步行为 | A | B |
|---|---:|---:|
| Search | 37 | 35 |
| Open | 1 | 0 |
| 未到第二步或第二步失败 | 2 | 5 |
| 审阅为依赖观察的动作 | 14 | 15 |
| 审阅为回到另一题内入口 | 4 | 7 |
| 审阅为重复同一信息需求 | 14 | 11 |

其余行为包括带有未支持前提的动作、意图无法判断及协议失败，完整分类在 `review_summary.json`。没有显式解释时，不仅凭 query 出现新名字就判断模型捏造事实；探索待验证候选与断言候选已成立分开记录。

第二步完全重复窗口占比约为 A 的 38/223、B 的 36/210，均约 17%。正文重叠比例约为 19.0% 和 21.2%。这些机械指标不能替代语义推进判断，但也没有显示出 B 明显减少重复投喂。

单独提示“根据观察选择 Search 或 Open”，没有在这批短轨迹里带来更多 Open。它既不证明必须强制 Open，也不能说明 Open 本身无用。

## 5. 关键轨迹

### qid=519：B 能依据来源纠正猜测，A 两次继续确认错误人物

A 两次在首搜前的 `assistant.content` 中都认定政治人物是 Margaret Thatcher，并尝试解释原题“一名孩子”“双方超过六十岁”等条件为何可能不准确。第二步仍围绕 Thatcher 或其传记作者搜索。

B 首步也出现过 Thatcher 的猜测，但实际 query 使用了题目中 BBC 总部、Vienna Café 等具体线索。两次都取得 62838，将人物、相遇地点与传记作者相连；第二步转而核验 Niyazi Kizilyurek 的生日、博士年份和书籍出版信息。

这说明提示词可以改善某些入口，并帮助模型在有用观察出现后改换候选。但它没有消除首搜前的无依据推断。该案例更值得带到后续状态设计中：模型的早期猜测不能覆盖原题条件，也不能直接被保存为确认事实。

### qid=191：A 两次进一步取得电视制作依据，B 没有同样推进

两组都获得 Tim Ellis 的相关入口。A 两次第二步围绕该候选继续查，读到其共同制作具体电视节目的原文，为核验题设中的电视制作背景提供了新材料。它还不足以证明“受过训练”这个完整条件，审阅没有作此升级。

B 两次第二步没有取得同样的新依据。该题提醒我们，泛化的探索原则未必比当前模型行为更善于利用已识别的对象。

### qid=854：提示词中的忠实要求没有消除关系压缩

B 两次首 query 都把本人及家人共同修建的道路数量压成了 road builder 自身 built 28–40 roads。原题中的共同主体被弱化；将文章年份当作事故年份推算婚期，也带入了未经确认的时间假设。

这些 query 仍可取得有用来源。因此，“搜到了东西”不能反过来证明表达忠实。本轮没有针对该题再补一条规则，也没有重新引入 Compiler。

### qid=1000：真正的 Open 与首搜前直接作答

A 的一次第二动作使用 Open，获得了进一步可读的原文。B 的一次尝试却在没有工具返回的情况下直接认定 Easmon，并展开推断，未按要求执行首搜。这条被保留为失败，而不是从成功子集里删除。

它表明，增加三句探索原则不能保证工具协议或来源意识稳定执行。单次发生也不足以证明这些原则导致了失败，报告只记录本批实际结果。

## 6. 决策与后续范围

本轮满足“累计可见依据有净改善且存在一个可重复改善题”的数值部分，但存在另一题的可重复新增依据退化，整体第二步新增没有提高，关系压缩与无依据断言也仍存在。因此，数值部分通过不等于默认采用。

当前决定是：

1. 保留默认 Agent 提示词，不推广本轮三句追加内容。
2. 保留实验代码、完整轨迹和标注，作为后续节点的开发材料。
3. 不再为 Query 增加 Selector、Compiler、多 query 或针对这些案例的提示词补丁。
4. 下一节点转向观察如何形成可修正的研究判断，以及这个判断如何驱动下一步动作。

这次结果不支持取消模型自主生成 query，也不评价长链路的提交能力。它支持的是一个更具体的取舍：当前额外提示没有带来足够一致的研究推进收益，可以停止这一轮局部优化。

后续状态设计需要继承原文可追溯性，同时区分来源陈述、模型解释和候选假设。qid=519 里“为了候选而修改题意”的行为，不能仅通过保存一份模型摘要解决。
