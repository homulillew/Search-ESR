# Selector 原文选材与整题检索对照实验

本轮在 20 道本地既有实验未使用的问题上，比较整题原文检索与模型选材后的原文检索。真实调用已经完成：40 次模型请求、60 次正式 Search，全部保留完整轨迹。

**选材与原文提取的工程链路通过了验收，但当前结果还不足以支持默认增加 Selector 调用。** 确认有用来源率从 45% 到 47.5%，实际窗口中的有用依据率保持 45%。Selector 在一题上两次改善，也在另一题上两次退化。数值门槛通过与默认采用是两个不同判断；预注册协议要求单独审阅重复退化，不能只看汇总比例。

完整记录见[本轮运行目录](../experiments/query_initialization/selector_verbatim/runs/20260918T085353.300461Z/README.md)，逐题标注和确定性计分见该目录的 `review_part_*.json` 与 `review_summary.json`。

## 1. 这轮要回答什么

此前 Query 改写容易把完整关系压成关键词，造成主体、时间范围和关系漂移。将选材和编译分开以后，来源边界更清楚，但仍需回答一个更基本的问题：对于当前 dense retriever，是否有必要让模型重新表达这些原文？

本轮进一步移除 Compiler，只留下一个语义动作：模型选择本次使用哪些原文单元。Harness 校验局部编号，按原文顺序提取文本，保留片段边界，规范单元内空白，然后直接执行 Search。模型不复制原文，不计算偏移，不维护后续 attempt 或窗口编号。

这种结构能够避免生成式改写引入新措辞，但选择本身仍可能删除重要条件，或留下含混的指代。因此，本轮分别检查原文提取正确性、选材可理解性和实际检索效用，不能用其中一项代替其他项。

## 2. 实验设置与并行执行

样本由固定种子 20260923 一次抽取。准备脚本扫描本地既有实验和报告，排除已有使用记录的 159 个 qid，再锁定 20 题。这里的“新题”只指本地实验记录未使用，不代表模型训练未见。

| 项目 | 整题原文 | Selector 原文选材 |
|---|---|---|
| 输入构造 | 使用全部原文单元 | 模型只输出 `selected_units` |
| query 构造 | Harness 按原序拼接 | 相同逻辑拼接选中单元 |
| 每题次数 | 1 | 2 |
| 正式 Search | 20 | 40 |
| 真实模型调用 | 0 | 40 |

两组使用同一个 Search/Open 实现、Qwen3-Embedding-8B 索引、top6 和每窗口 400 tokens 的预算。查询含 embedding 前缀及特殊 token 最多 1024 tokens，超限记失败，不静默截断。空选择不自动改成全文检索；最多一次格式修复，不根据检索结果重新选材。本轮没有发生空选、超限或修复。

Selector 使用 qwen3.7-flash，`thinking=false`，输出上限 1536 tokens。API 线程池配置为 8，实际请求重叠峰值为 5。检索由两个独立进程并行执行，实际重叠峰值为 2；每个进程调用原检索器的单条查询方法。运行前以三条历史查询分别检查两个副本，6 次技术探针均通过结果顺序、正文、URL 和分数一致性检查，未混入正式实验。

实现、抽样、审计和来源审阅由子代理并行分工。并行调度提高了资源利用，但没有串行对照，因此不报告加速倍数。

## 3. 评价方法与限制

评价围绕初始搜索是否提供有依据的下一步入口，不要求一次搜索完成整题。确认正例必须在原文中提供与原题关系相连的中间实体、事实组合或可继续阅读的具体来源，仅有主题词重合不算。

两个效用指标分开统计：

- **确认有用来源**：top6 内至少一篇来源提供上述依据，包括审阅时从该来源全文确认的内容。
- **可见有用依据**：该次实际返回窗口及标题已经包含所需依据。全文其他位置的内容不能借给当前窗口。

本轮覆盖全部 20 题、166 个去重题目—文档组合和 193 个不同窗口。共记录 19 个确认来源，44 个引文区间已与数据库原文及来源哈希逐项校验。所有池内返回窗口均已筛查；只有记录在审阅文件中的来源被额外定向阅读或阅读全文。未确认不代表全文绝对无关，正例池也不是完整 qrels，因此下文不称为全库召回率。

**审阅方法存在一项需要明确披露的协议偏差。** 冻结协议写了“不使用 LLM judge”，实际定性审阅由本轮协作编码代理完成，没有另发 API judge 请求，但编码代理本身也是模型，不能把这些标注称为独立人工判断。部分审阅者还参与了工程审计，且整题文本可以暴露对照组身份，因此也不是双盲。此次结果适合作为开发诊断；严格独立验收还需要独立复核。

整题对照每题为 0/1，Selector 取同题两次的均值，再在 20 题上汇总。没有把两次中任意成功计为该题成功，也没有把 40 次调用当成 40 道独立问题。

## 4. 结果

### 4.1 工程和选材

| 检查 | 结果 |
|---|---:|
| Selector 首次合法、非空且预算内 | 40/40 |
| 格式修复 / API 错误 / 隐式回退 | 0 / 0 / 0 |
| 正式 Search 完成 | 60/60 |
| Query、来源版本、窗口及账本机械审计 | 通过 |
| 从保存账本恢复并执行 Open | 60/60 |
| Selector packet 可理解性审阅 | 40/40 |

最后一项来自上述代理辅助审阅，不能解释为架构保证语义正确。恢复后的 Open 是不调用大模型的接口验证，也不代表 Agent 已经学会主动 Open。

Selector 平均保留 73.5% 的原文单元、80.5% 的原文字符、83.2% 的 embedding 查询 tokens。40 次选择中有 11 次全选，其中 6 次来自只有一个单元的三题：719、1249、191。它们结构上无法细选，不能解释为模型主动偏好全文。其余 5 次才是多单元问题中的全选。

20 题中有 7 题两次选择不同。这种变化本身不等于错误，需要看各个入口是否有用。

## 5. 四个能解释差异的例子

### 5.1 qid=71：没有改错关系，仍然丢失入口

题目描述一个爱尔兰水上构筑物，建筑年代存在不同记载，附近酒店的餐厅以它命名，其中还有一句：

> It was used to help with stability.

Selector 两次都选择 q1、q3，删除这句 q2。保留的历史与命名关系没有被改写，因此语义审阅通过；但两次都未返回已确认的 Ballast Bank 入口。整题检索返回的 10907 明确连接 Ballast Bank、为船只提供稳定性、酒店命名和 1905 年记载。

这揭示了选材层的独立风险：一个条件即使不是完整句子的主干，也可能比其他条件更有辨识度。局部关系忠实不能保证选中的信息组合适合当前检索器。删除 stability 与此次退化直接对应，但本轮没有单独增加该句的干预实验，尚不能把具体排序变化完全归因于这个词。

### 5.2 qid=1147：集中身份线索，两次取得新入口

整题包含 rapper、被同学欺负、最小的孩子、2017 年首次受到关注，以及询问 real name 等内容。Selector 两次都保留前两句，返回 72658，其中把 Kid Trunks 与被欺负、最小孩子和 2017 年发布 Talk 相连。整题的返回池主要落在通用艺人真名列表，没有确认同样的入口。

这支持选材可以改善特定题目的检索方向。它只证明取得一个有依据的候选入口，不代表已经确认全部条件或读到了最终真实姓名。

### 5.3 qid=1035：同样忠实，入口组合的效用不同

题目通过移民创业者、城市、应用和企业同名关系寻找 Company A，同时包含运动员代言和演唱会等条件。第一次选择 q2、q3，保留多个方向，未确认有用入口。第二次选择 q1、q2，返回 38647，将 Jan Koum、Mountain View、WhatsApp 和收购金额相连，提供了可继续核验的城市候选。

两次都保留了所用原文关系，差别在于选择的事实组合。这说明后续要观察“这次搜索有没有带来可继续调查的对象”，仅检查 query 忠实不足以判断进展。它也只是一次收益，不能按两次中最好结果汇报。

### 5.4 qid=978：找到同一来源，不等于看到同一依据

三次检索都返回 70422。该文包含 Tatsuya Endo、Spy X Family、助手经历，以及漫画 2019 年和动画 2022 年等信息。整题和第一次 Selector 的窗口展示了这组关系，第二次 Selector 的窗口定位到另一位漫画家 Yuji Kaku，因此来源仍有用，但可见依据不通过。

这次差异提醒我们：query 同时影响文档排序和文内定位。后续 Harness 应保留来源与已读窗口之间的区别，使模型能够继续阅读或重新定位。本轮没有据此修改 Search/Open，也没有将全文里确认的事实记成模型已读。

## 6. 根因与后续边界

取消生成式 Compiler 后，原文关系不再经过一次自由压缩，来源记录也由 Harness 自动完成。这部分职责分配已经落地。但初始搜索仍有另一项不确定性：模型需要在未见结果时预测哪些事实组合更有检索价值。该预测既可能删除干扰，也可能删除最有辨识度的条件。

当前切分粒度进一步限制了选择空间。有些原文单元本身包含多跳关系，Selector 只能整段保留；只有一个单元的问题则完全无法选择。由此不能认定“所有选材方法无效”，但也没有理由仅为改善本轮指标就加入更细切分、语义解析和新的修复环。本轮已经足以说明，全题原文是必须保留的有效基线。

现阶段适合固定的接口是：原始问题保留为源；每次执行记录实际输入来源与确定性的 query；返回的来源、窗口和已读范围可恢复。Selector 可以继续作为实验策略，Compiler 不加入默认链路。需要选择时，模型使用本次局部 handle；编号、来源版本和关联记录仍由 Harness 维护。

预注册的工程、语义和效用**数值门槛均通过**，包括至少一个可重复收益和来源指标净提升。但改善幅度小、可见依据未提升，且存在重复退化；定性评价还存在前述方法偏差。因此，本轮决策是**保留整题原文基线，不自动推广 Selector，不宣称统计意义上的稳定优势**。可以带着已验证的原文构造与观察接口进入后续 Harness 节点，把搜索后的进展判断、缺口形成和换入口放到对应阶段设计。

默认 Agent 本轮未变更，搜索预算未提高，也未增加根据 gold 或检索结果修复输入的分支。
