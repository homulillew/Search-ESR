# Query 初始化首轮对照实验

本轮完成了真实 API 与本地 BC+ 检索对照。结构化初始化能更稳定地产出可执行 query，双方向也出现了明确的互补案例；但检索入口的改善尚不稳定，关系改写和严格摘录校验还引入了新的失败。目前保留实验实现，不替换默认 Agent 的首搜方式。

## 1. 原始方案与这次改动

原始方案由 Agent 读取整题，自主发起第一次 Search。它可能选择一个有效线索，也可能提前补入猜测、把条件堆在一起，或者直接回答而不检索。

这次实现独立的初始化节点：模型从原题生成 `goal / source_clues / query`，harness 检查结构和摘录来源，最多修复一次，然后执行固定的首轮 Search。搜索方向在任何检索结果返回之前全部确定。交接内容包括原题、方向、原始窗口及观察账本。

节点停在首次观察，没有继续 rollout，也没有加入候选确认、gap、重规划或提交控制。Search–Open 的窗口算法、工具描述和原 Agent 系统提示词保持冻结；B/C 使用新增的初始化提示词。

|组别|生成方式|展示配额|
|---|---|---|
|A|现有 Agent 首次响应中的第一个 Search query|top6|
|B|结构化单方向初始化|top6|
|C|结构化双方向初始化|每方向 top3|

每个窗口的原文标题与正文合计最多 400 tokens，每次初始化最多 2400 tokens。C 多调用一次检索，所以这是相同展示上限对照，并非严格相同计算成本。没有跨方向去重补齐或重排。

三组均使用 `qwen3.7-flash`，`enable_thinking=false`，输出上限 1536 tokens，超时 120 秒，SDK 自动重试为零。API 使用四线程并行，本地检索单线程共享 Qwen3-Embedding-8B 和索引。A 也受本轮输出上限约束，因此不能把它的截断率推广到以前未使用同样上限的运行。

## 2. 开发与留出过程

先在 1034、645、905、387 四题上完成 v001 的 12 次联调。发现父系关系被改成母系、被引用文献的作者被当作目标研究作者、长摘录不再逐字连续等问题。

v002 在提示词中加强了入口选择、关系归属和短摘录要求，再完成同样 12 次联调。运行链路全部完成，但 qid=645 的作者归属问题仍在。这里没有把“12 次执行完成”解释为语义通过，而是将 v002 锁定为待评估候选。

随后按固定种子，从本地排除清单之外抽取 20 题，A/B/C 各重复两次，共 120 次尝试。排除清单共 19 题；它表示本地未用这些新题调参，不代表模型预训练未见过。提示词、源码、抽样清单及执行顺序均在请求前保存。留出运行开始后，没有依据其结果修改初始化提示词。

|批次|尝试数|实际 API 请求数，含修复|API total tokens|

|v001 开发|12|14|14,675|
|v002 开发|12|14|18,009|

## 3. 执行可靠性与成本

|指标|A 原始首搜|B 单方向|C 双方向|
|---|---:|---:|---:|
|尝试数|40|40|40|
|首次即得到可执行计划|34|32|33|
|修复调用|0|8|7|
|最终完成检索|34|39|37|
|最终失败或无 Search|6|1|3|
|实际 Search 调用|34|39|74|
|返回窗口|204|234|222|
|标题与正文 tokens 合计|75,728|85,655|81,761|
|API total tokens，含修复|53,706|56,502|60,573|

A 的六次未执行检索包括四次输出达到上限，以及两次直接回答而没有 Search。B/C 的四次最终失败均来自原题摘录校验，修复后仍未满足约束。没有 Search 执行错误，也没有 underfilled 或零方向的合法输出。

B/C 的最终完成数更高，但首次成功数并未超过 A；一次格式修复贡献了部分改善。它们使用独立指令要求输出 query，而 A 仍允许自主回答，这也影响执行率，不能将差异全归因于搜索表达更好。

机械审计覆盖全部 120 次尝试，其中 110 次取得窗口。660 个窗口的原文区间、来源哈希、标题、边界标记、预算以及工具返回与账本的一致性均通过检查。两路计划都先于 Search 完成。相关测试为 57 passed，三条依赖弃用警告。

## 4. 如何判断取得了研究入口

本地 QA 文件没有完整相关文档标签。本轮把各组返回结果汇入联合池，共 381 个“题目—文档”组合，结合原题核查标题、正文片段及候选来源全文。离线核查可参考标准答案；在线初始化与检索均未输入标准答案。

本次完成的是单人审阅的正例核查，没有完成全部文档的穷尽式 0/1/2 分级，也不是独立盲评。最终保存了 18 个带原文引句和字符位置的确认入口。未确认文档保留为“尚未核实”，不能一律视为无关。这是相对于原设计中完整相关性标注的限制。

确认入口分为两类：一类直接连接目标研究对象，例如目标作者的论文记录；另一类只建立中间线索，例如洛杉矶博物馆的开馆年份。后者有研究价值，但不等于找到了目标作者。

窗口检查使用这些原文依据，同时承认独立返回的标题。一个入口可有多个等价参考片段。没有覆盖已标注片段，只表示尚未展示这份参考依据，不能证明窗口完全没有其他有用信息。因此下表是**已核实入口的保守计数**，不命名为全库 recall，也不能据此计算最终答题准确率。

|每 40 次尝试中的确认计数，失败仍留在分母|A|B|C|
|---|---:|---:|---:|
|取得至少一篇已核实入口文档，含中间线索|15|13|13|
|窗口实际覆盖至少一份参考依据，含中间线索|11|13|13|
|取得直接连接目标对象的入口文档|12|12|11|
|窗口覆盖直接连接目标对象的参考依据|10|12|11|

按题目汇总两次重复，再比较窗口参考依据的出现次数：B 相对 A 为 6 题改善、11 题持平、3 题退化；C 相对 B 为 4 题改善、12 题持平、4 题退化。两个重复没有当作两个独立题目处理。

B 的可见参考依据计数略高，但发现已确认文档的次数没有增加。C 与 B 总数相同，题目之间互有得失。这些结果不足以支持替换默认方案，也不能排除补全相关性标注后计数发生变化。

## 5. 有效案例与退化机制

### 5.1 qid=478：两个方向确实补充了不同证据

题目要求从 Blantyre Telegraph 文章取得日期，并从 Pro Wrestling Books 书评取得体育场名称。C 的两个重复均将两处来源分开搜索：第一路返回文档 47437，包含夫妇养熊的书评及 Eldorado Stadium；第二路返回文档 24964，包含 2019-12-06、相识 46 年及养熊 25 年。

这不是简单多出一篇文档。两篇来源分别支持不同的指定信息。B 两次取得书评；A 一次取得书评，另一次未确认入口。C 在这个案例中提供了明确的补充。

C 的 37 次完整运行中，第二方向每次都返回三篇第一方向未返回的文档，文档集合没有重叠。但在全部 40 次 C 尝试中，第二方向只有 9 次确认增加了可见的不同有效线索，其中 5 次是第一方向没有已核实可见入口、第二方向取得了入口。范围仅限本次标注，不能将其他 31 次全部判断为无价值。这 9 次也不能自动证明“两路 top3 优于一路 top6”。

### 5.2 qid=551：找到文档和展示对应线索仍需分开

A 的两次查询都围绕 2007 年杯赛救出替补球员射门，返回文档 37025。这篇文章确实含有 Paul Rachubka 在 2011 年对 Blackpool 比赛中被半场换下的内容，但 A 返回的窗口从更后面开始，没有呈现这段依据。

C 第一次重复直接选择 2011 年被换下的线索，返回同一文档的前部，展示了该段文字。这里的改善发生在 query 与定向窗口的配合，而非新增召回文档。C 第二次重复又未取得确认入口，说明这一效果还不稳定。没有据此修改窗口规则。

### 5.3 qid=786：引用原题不等于保留了关系

原题的主体是某位演员：他出演过一部由知名导演执导的电影，也曾与自己的侄子拍短片。B 和 C 的第一次重复，把后一个线索接到了前一部电影的导演身上：

```text
director English-produced dinosaur sci-fi adventure films short film nephew
```

goal 也明确准备寻找这位导演与侄子合作的短片。source_clues 即使都是原题片段，组合之后仍改变了人物归属。确定性来源检查只能验证字面出处，不能验证组合后的语义。

类似问题还包括：qid=551 把“截至 2020 已退役”写成“2020 年退役”；qid=1072 把“2004 年到 2010 年之前”写成“2004 to 2010”；qid=1209 在 goal 中将“查明真相”改成“复仇”，尽管 query 没有继承这项动机。

全部 147 条已执行方向均做了原题对照阅读。A/B/C 分别标出了 5/34、5/39、13/74 条存在明确改动或歧义的方向。这里混合了严格错误和风险表达，详见逐条标注，不作为统一错误率。C 输出方向更多，本身也增加了可能出错的位置。

### 5.4 qid=1117：严格摘录契约也会消耗有效尝试

C 两次重复均在修复后停止。原题的军衔写成 `"Major,"`，生成摘录却写成 `"Major"`，逗号与引号位置不一致；一次修复仍原样保留错误。

qid=985 的一次输出把 seminary 写成 seminal，qid=551 把原题中的 They 改成 He，也在修复后被拒绝。harness 正确执行了已约定的契约，但这些失败说明：逐字摘录机制自身存在可测成本，不能因其可校验就默认值得。

另一方面，8 次修复涉及摘录数量超过上限，7 次涉及非原文子串。继续要求模型同时概括目标、选择多条线索、准确抄写和生成 query，会增加初始化的负担。这次未在留出结果出来后放宽校验。

### 5.5 qid=583：更短、更规整仍可能退化

A 两次均取得文档 996《Circle of life – interview with Cuore》，其中有艺术家别名、童年经历和圆形图案。B 的两个改写均未在 top6 中取得这篇已确认来源；C 只有一次取得。

这说明简化表达和明确 goal 都不是检索提升的充分条件。当前证据只能确认具体 query 对应的结果不同，尚未通过独立的词语增删实验确定是哪一个词、语义组合或排名变化造成退化，不能直接归因于“短 query 不好”。

## 6. 当前判断与下一步

工程链路可以保留：独立调用、计划先于检索、原文交接、失败记录和完整轨迹都已验证。默认行为暂不切换，尤其不将双方向作为固定要求。

下一步宜优先收窄初始化本身的负担，分开检验两个问题。

第一，关系能否保持。以 qid=786、551、1072 等作为开发材料，比较当前概括式改写与保留主体、关系词和区间的较少改写版本。检查 query 之前的 goal 是否已经改错关系。先不增加语义裁判、候选状态或 gap 模块，避免同时改变多个因素。

第二，来源审计是否必须依赖模型逐字抄写。在独立版本中比较当前摘录字段与更轻的原题线索定位方式，既记录失败成本，也检查是否失去可追溯性。不能单纯删除校验后将执行率提升宣称为语义质量提升。

双方向是否保留，放在表达稳定之后判断。qid=478 支持“独立来源线索有时需要两个入口”，本轮总体结果不支持“所有题都应先生成两个方向”。若继续依据这批留出题调方案，它们应转为开发材料，下一次推广判断需另抽新题。
