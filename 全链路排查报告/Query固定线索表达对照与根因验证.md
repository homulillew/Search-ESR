# Query 固定线索表达对照与根因验证

本轮固定原题线索和搜索对象，对照完整关系表达、模型压缩和整体删除。结果说明：入口固定以后，关系或时间仍可能在表达阶段发生变化；完整地删除一个条件虽然避免了关系改错，也可能丢掉关键检索线索。因此，初始化不能把“更短”或“少一个条件”作为统一优化方向。

实验已完成，默认初始化与 Search–Open 未修改。本轮属于已知问题的局部诊断，不能作为新题泛化或最终答题效果证明。

## 1. 本轮如何隔离问题

此前各组既选择入口，又生成 query。关系错误消失，可能只是换了入口；检索退化，也可能是线索选择不同。本轮先人工固定搜索对象与对应原题位置，模型负责表达，不再负责重新选择。

|组别|输入查询|每题次数|
|---|---|---:|
|full|运行前确定的完整关系表达|1|
|delete|从 full 严格删除一整段指定关系或辅助信息|1|
|model|模型根据相同原题线索生成紧凑 query|3|

7 道开发题为 1117、551、645、786、1072、583、591。控制查询与删除字符范围在 cases.json 中预先保存。模型只能看到完整原题、选定原文单元及固定搜索对象，不看到手工控制查询、答案、其他重复或检索结果。完整原题保留用于指代消解，不允许引入未选条件。

full/delete 是人工诊断干预，不是可直接部署的生成策略；人工查询也不是形式化语义金标准。例如 qid=591 将庆祝年份放在句尾，仍可能有日期修饰范围歧义。本轮不在结果出来后修改控制查询。

全部使用相同本地检索、top6、每窗口标题加正文最多 400 tokens、总上限 2400。模型仍为 qwen3.7-flash，thinking=false，输出上限 1536 tokens，超时 120 秒，SDK 自动重试为零。API 四线程并行，本地检索共享一个工作线程。

## 2. 执行结果与评估边界

共 35 次 Search、210 个窗口，全部执行完成。模型组 21 次初始请求，其中一次需要格式修复，合计 22 次 API 请求、14,006 API tokens。没有检索执行错误。查询生成时序、控制查询未变、模型未见控制查询、原文/标题/引用/预算及账本一致性均通过审计。相关测试 77 passed，三条既有依赖弃用警告。

沿用运行前保存的旧正例区间，得到以下保守计数：

|指标|full|delete|model|
|---|---:|---:|---:|
|尝试数|7|7|21|
|取得已有确认入口文档|5|3|14|
|窗口展示已有参考依据|4|2|11|

model 每题重复三次，不能将 11 直接与控制组的 4 或 2 比较。按题查看参考依据：

|qid|full|delete|model 三次中出现次数|
|---|---:|---:|---:|
|1117|1|1|3/3|
|551|0|0|0/3|
|1072|1|0|2/3|
|583|1|0|3/3|
|591|1|1|3/3|
|645、786|原参考池无正例|原参考池无正例|原参考池无正例|

这些是旧标注复核，未命中不等于无关；没有全库相关文档标签，也没有最终回答评分。qid=645 本轮另做原文核实，放在补充附件中，不回写运行前的参考计数。

## 3. 固定线索以后，仍会发生哪些表达错误

### qid=551：时间界限仍被省略

模型三个重复中，两次写出 retired 2020，只有一次保留 retired as of 2020。原题是截至 2020 已退役，前两条查询存在被解释为确切退役年份的风险。

这次搜索对象、原题线索都固定，因此不能再把这个现象全部归因于“选错入口”。问题至少部分发生在表达阶段。

不过三个重复都召回文档 37025，full/delete 也召回它。这个检索结果没有反映出语义风险；各组窗口又都没有覆盖之前标注的目标球员 2011 年被换下的片段。因此不能用“召回同一文档”证明时间表达正确，也不能根据当前参考片段缺失就宣称完全没有可读信息。

### qid=1117：关系链可以写对，但其他属性仍可能接错

三个重复均未再次把评论者直接写成 Major 的兄弟姐妹。其中两个明确保留“Major 私奔对象的兄弟姐妹”，说明模型在这个任务配置下可以正确表达关系。

但另一次生成：

```text
whose sibling eloped with a Major in 1828
```

原题的 1828 属于刊物购买和父亲去世，并未提供私奔年份。模型把完整问题中的年份重新附到了另一个事件，同时省略了所选线索里的学位年份。

这表明错误不只是删除连接词，也包括跨事件移动属性。保留完整原题有助于指代理解，但也给了模型引入未选信息的机会。

### qid=645：关系简写与检索命中可以同时存在

三个重复中，两个保留 Farjon authors the first reference，另一个只写 Farjon 2020 study。后者丢失参考文献关系，容易被读成研究作者；这里记录为归属表达不充分，而非声称模型明确输出了 by Farjon。

本轮核实文档 28183 的正文：日期为 2020-05-12，讨论地中海松树叶片蜡质化合物，首篇参考文献确为 Farjon。full 把它排第一，删除 Farjon 整段信息后，它未进入 top6。模型三个重复分别排第 4、6、1。

即使简写后的关系有风险，相关文档仍可能被找到。dense 检索取得相近材料不等于验证了 query 的关系。

文内窗口还有差别：full 返回首篇参考文献附近，模型三个重复返回研究说明和 Results and Discussion 附近。前者支持论文定位线索，后者提供进一步阅读材料。这说明文档排序、窗口落点、语义忠实性需要分别记录。

### qid=786：格式修复后，固定入口也可能被突破

其中一次首次响应只返回了查询字符串，没有外层 JSON，触发格式修复。修复后增加了出生年代、移民背景和 Perfectly formed。这些信息来自完整原题，但不在预先选择的 q4/q5 里。

因此，本次固定线索设计仍然只是模型指令，代码没有执行语义范围约束。该重复完整保留并标记为 scope violation，没有静默重跑或删除。其他两条压缩 query 的长片导演从句与短片执导动作仍有主体附着风险，但未标为确定人物接错。

## 4. 整体删除是否更好，取决于删掉了什么

### qid=1072：论文主题在这个表达中有实际作用

full 包含出生年、议员任期，以及国际组织论文，已核实文档 69382 排第一。delete 只删除最后一句关于论文的信息，该文档未进入 top6。

模型组中，保留国际组织信息的两个重复都将它排第一；省略论文主题的那个重复没有找到它。

这比之前的跨版本比较更直接：在预定的 full/delete 文本对上，唯一删掉的一段确实改变了 top6 结果。它支持“这段信息对当前查询有检索价值”，但不证明每个问题都应增加论文主题，也不能拆分出 research paper 与 international organization 各自的作用。

### qid=583：童年经历不能因为看似附加就删掉

full 将艺术家采访文档 996 排第一。只删除 The same artist faced tough challenges growing up 后，这篇文档未进入 top6。三个模型重复都保留童年经历，也都将该文档排第一，其中两个还省略了 2012 年。

这说明当前 query 中“辅助条件”的地位不能只凭句子长度或是否是核心名词判断。一些描述虽然不像实体名，却能显著影响检索匹配。

### qid=591：有些信息确实可以省略

删除大学成立时间后，海外校区周年文档 37403 仍然出现，排名从第二变为第一。三个模型重复保留两个时间区间，均排第二。

因此，本轮同时出现了删除后丢失、删除后保持、删除后排名改善。不存在“整体删除总是更好”这一统一规则。排名变化也不等于后续解题收益已经提升。

## 5. 本轮能支持的根因判断

第一，错误不完全来自入口选择。固定对象与原文线索之后，仍出现时间界限丢失、年份附错事件、参考作者关系省略。表达阶段本身存在不稳定性。

第二，模型能够在部分重复中表达正确关系。因此更合适的描述是行为不稳定，尚不能据此认定模型完全不具备理解这些关系的能力。固定对象、显式原文及指令同时变化，不能单独归因于某一项。

第三，语义正确与检索有效是不同维度。关系有风险的 query 可能仍命中文档；关系完整的 query 也可能没有取得已核实入口。检索返回不是语义校验器。

第四，缩短 query 的收益依赖具体被删信息。qid=1072、583、645 提供了删除后失去特定来源的局部证据，qid=591 则显示可以省略一段信息。把所有辅助条件统一删掉会损害部分入口。

这些结果支持下一步测试“原题线索或关系完整短句直接检索”的较少改写基线，再判断是否需要压缩。人工 full 控制不能直接升级成自动方案；指代和跨句上下文仍需处理。当前不增加语义 verifier，不改变窗口规则，也不把生成失败移交给 gap 机制。
