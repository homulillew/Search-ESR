# Query 通用原则提示词落地与对照实验

本轮将 Query 初始化提示词收敛为五条通用原则，并完成了 112 次真实 API 调用：8 道开发题、20 道未用于本地调参的新题，两组每题各重复两次。

精简版降低了约四分之一的生成 token 成本，接口和检索链路正常。但开发题上的检索改善没有在新题上形成一致优势，关系表达与引用覆盖也没有随提示词缩短而稳定改善。因此，`entry_v1` 保留为实验候选，当前默认 `minimal` 不变。

## 1. 为什么做这次对照

此前的提示词已经强调保留关系、不猜未知身份，但真实调用仍出现关系压缩、时间范围丢失和条件取舍不当。继续为每个 bad case 加一句禁令，会让运行提示词逐渐承担历史错误清单的职责，同时难以判断哪些要求有效。

本轮把任务分成三件事：选择一个可独立搜索的对象或来源；从原题选取帮助定位它的一组事实；忠实表达为一条独立查询。亲属错配、参考文献作者误读和日期归属等具体问题保留在离线审阅规则中。

运行提示词见 [ENTRY_PROMPT.txt](../experiments/query_initialization/single_entry/ENTRY_PROMPT.txt)，审阅规则见 [ENTRY_EVALUATION.md](../experiments/query_initialization/single_entry/ENTRY_EVALUATION.md)。后者在本轮首次调用前保存并随开发实验归档。

## 2. 实际改动与实验边界

新增 `entry_v1` 分支，与 `minimal` 共用 `intents → basis_refs + query` 契约。最多生成一条查询；空输出不强制补齐；格式或非法引用最多修复一次。代码仍只检查结构，不判断事实是否忠实。

Search–Open、原题编号、原文窗口、观察账本和 handoff 结构没有修改，已与上一批存档核对源码摘要。新增的留出测试入口只负责核对开发决定、题目清单、源码和 API 参数是否与锁定记录一致。离线重启检查扩展到两组全部会话，在账本副本上恢复引用并执行 Open。

本轮只运行初始化和一次 Search，没有运行最终回答、ResearchState、gap 或 Replan。

|项目|两组共同设置|
|---|---|
|生成模型|现有 DashScope OpenAI 兼容接口，`qwen3.7-flash`|
|Thinking|显式 `enable_thinking=false`|
|联网搜索|未启用；实际检索为本地 BC+|
|生成上限|1536 tokens|
|超时与重试|120 秒；SDK 自动重试为 0；格式修复最多 1 次|
|检索|一次 Search，top6|
|观察预算|单窗口标题与正文最多 400 tokens，总上限 2400|
|输入|完整原题、原文编号，不包含标准答案或检索反馈|
|归档|实际请求响应、提示词、源码摘要、计划、原始窗口、观察账本和 handoff|

两组都自由选择入口。`minimal` 还包含“优先具体且有辨识度的线索”等更细的指令，`entry_v1` 将其压缩为通用要求。因此，本实验比较两套提示词，不能将结果单独归因于长度、某一句原则或是否使用自然语言。

## 3. 测试分两阶段进行

开发题使用 786、551、1072、1117、583、591、645、183，每组每题两次，共 32 次请求。全部完成后审阅原题与查询，记录了一次明确关系错误及若干歧义。该明确错误未在同题第二次重复，历史正例检查也没有出现可重复退化，因此按预设规则允许扩大测试，但不升级默认版本。

扩大前保持两组提示词不变，扫描历史实验的题号、任务清单和记录，共排除 39 个已用题号。从剩余 791 题中，以固定种子 `20260921` 抽取 20 题：

```text
416, 67, 319, 127, 81, 1196, 265, 650, 598, 314,
1201, 568, 556, 119, 611, 499, 1172, 116, 694, 950
```

每组每题两次，共 80 次请求。清单、排除来源和源码摘要在请求前锁定。这里的“新题”指未用于本地调参，不保证模型预训练未见。后续若依据这批题调参，它们应转为开发材料。

## 4. 工程链路正常，成本确实下降

|阶段|指标|minimal|entry_v1|
|---|---|---:|---:|
|开发|首次格式合法 / 执行完成|16/16|16/16|
|开发|API 总 tokens|17,429|13,208|
|新题|首次格式合法 / 执行完成|40/40|40/40|
|新题|API 总 tokens|40,599|30,215|

全部 112 次尝试都只调用了一次 API，没有格式修复、空计划或执行错误，总计 101,451 API tokens。精简版在开发题、新题分别减少约 24.2%、25.6% 的 API tokens。两组相同原题下，输入 token 差固定为每次 259；主要节省来自提示词正文缩短。

672 个返回窗口全部通过原文区间、来源摘要、预算、引用与账本一致性检查。112 个会话均在独立进程中，通过临时账本副本恢复首个窗口并执行 Open。实际请求与保存的提示词、原题输入一致，没有将标准答案输入生成模型。

相关测试原有及新增参数覆盖共通过 79 项；留出锁定新增 7 项测试通过。最初直接递归整个实验目录时，pytest 将历史源码快照也当作测试收集，出现同名模块冲突；改为显式指定当前测试文件后通过，没有改动旧存档来消除冲突。

这些检查证明接口能够工作，不证明查询语义正确或入口有效。

## 5. 开发题的改善不能直接推广

开发题沿用实验前已有的正例及原文区间：

|历史正例检查|minimal|entry_v1|
|---|---:|---:|
|命中已确认来源的尝试|7/16|10/16|
|窗口展示已标注依据的尝试|6/16|9/16|

增加主要来自 qid=1072 的两次尝试和 qid=1117 的一次尝试。这是既有正例覆盖范围内的结果，不是全库召回率。qid=645 不在这份历史标注范围内，不能把未计入的结果判为失败。

新题汇总两组共 235 个不重复的“题号—文档”组合。逐条审阅全部 80 条查询后，对有明确线索的来源进一步核对正文，形成 12 个正例入口标注，涉及 6 道题；每个标注保存原文引句、字符区间和来源摘要。这是事后、非盲审的有限正例集合，没有完成 235 个来源的穷尽相关性标注。

|题号|已核实入口线索|minimal 文档 / 可见|entry_v1 文档 / 可见|
|---|---|---:|---:|
|119|电梯的年代及历史用途|2/2；2/2|1/2；1/2|
|127|奖项创立年与科技公司创办者的关系|2/2；2/2|2/2；2/2|
|416|植物研究论文及作者资料|2/2；2/2|2/2；2/2|
|499|Verity 的争议与旅游背景|0/2；0/2|2/2；2/2|
|556|音乐家 Victor Ntoni 的履历和皇家演出|2/2；2/2|0/2；0/2|
|598|Afrigo Band 的创始成员或四十周年音乐会|0/2；0/2|1/2；1/2|

在这份有限标注中，两组都为 8/40 次命中入口文档、8/40 次看到入口依据。这个相等结果不能证明整体等效；其余 14 题没有完成充分的正例标注，零计数不等于结果无关。qid=127 的来源只支持一个符合局部描述的奖项候选，也没有确认最终作者身份。

两个方向相反的案例更能说明入口选择的影响。

**qid=499：精简版选择作品与旅游事件，获得可继续阅读的来源。** 原题描述作品引起争议，并在首月带来超过 4500 名额外游客。`entry_v1` 两次围绕作品和旅游事件搜索，返回 Verity 的报道。一次窗口中实际出现“首月额外 5000 人”，满足原题的数量下界。`minimal` 两次选择作者出生年代、宗教成长背景和首次个展，没有命中这组已核实来源。

**qid=556：精简版直接寻找论文，入口反而变宽。** `entry_v1` 两次查询“1990 年代、某社区历史、硕士论文、海洋学系朋友”，返回中出现通用论文致谢材料。`minimal` 两次选择爵士音乐家的出生年代和皇家演出，均返回 84412《Victor Mhleli Ntoni》。窗口包含 1947 年出生、2013 年去世和 1975 年皇家演出，全文还提供成长地 Langa，可以支撑下一次检索。

两个入口都来自原题。差别在于这些事实组合与语料中的具体材料是否相符。提示词变短并没有自动改善这项选择能力。

## 6. 通用原则仍存在执行失真

对照完整原题逐条审阅，明确错误、表达歧义和引用缺失分别记录：

|阶段 / 项目|minimal|entry_v1|
|---|---:|---:|
|开发：明确语义错误的尝试|0/16|1/16|
|开发：存在表达歧义的尝试|7/16|9/16|
|开发：缺少所用依据编号的尝试|4/16|4/16|
|新题：明确语义错误的尝试|0/40|1/40|
|新题：存在表达歧义的尝试|7/40|12/40|
|新题：缺少所用依据编号的尝试|6/40|9/40|

这些是编码助手完成的非盲审结果，没有独立评审者。歧义判断含有解释空间；同一尝试可以同时存在歧义和缺引，不能相加成为失败率。未标明确错误也不代表查询已被证明完全正确。

开发题 qid=786 的一次输出为：

```text
Who directed the English-produced dinosaur, sci-fi, and adventure films
series featuring a film that is 1 hour and 31 minutes long?
```

原题只说这部 91 分钟电影的导演以某系列闻名，没有说该电影属于这个系列。`series featuring a film` 新增了成员关系。同题第二次输出表达为导演同时执导该系列和该电影，没有重复这一错误。

新题 qid=1172 的一次输出为：

```text
movie name same as island name released 2008
```

原题给出 2008—2011 年的闭区间，输出无依据地收窄为 2008 年。另一重复保留了完整区间。这说明“保留限定范围”的原则已经写入提示词，但执行仍有波动。当前样本也不足以判断这种错误是否由精简本身引起。

其他问题主要表现为关系连接缺失：`retired 2020` 没有保留截至该年的含义；`eloped with sibling BA...` 不能清楚恢复私奔对象与获学位者的亲属关系；“约十年前”丢失原题的 2023 年时间锚点。这些情况单列为歧义，没有直接全部计作确定事实错误。

`basis_refs` 也存在独立问题。例如 qid=1172 的基线查询引用 q14，却使用 q2 的上映年代；qid=556 的精简查询引用 q2，却使用 q3 的海洋学系朋友信息。事实仍在完整原题中，因此缺引不等于编造，但后续 Harness 不能把这些编号直接当作精确的约束集合。

## 7. 当前决定与后续接口

本轮支持保留“单入口、事实组合、忠实表达”的设计，接口已能交付完整原题、实际 query、原文观察与可恢复引用。但它没有证明精简提示词在入口质量或语义忠实度上优于当前版本。

因此，保留 `entry_v1` 和完整对照记录，不替换默认 `minimal`，也不根据本批错误立即往运行提示词追加禁止条款。新的失败进入回归材料。若继续诊断，应分开比较同一入口下的表达，以及不同入口的选择效果，避免同时调整多层后无法解释结果。

后续状态设计可以使用已验证的原文观察与来源引用，并保留完整原题。查询文本是一次检索尝试，`basis_refs` 是模型提供的依据定位；二者都不应直接升级为已证实事实、精确约束图或未解决问题清单。
