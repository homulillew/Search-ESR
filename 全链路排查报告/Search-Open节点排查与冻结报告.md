# Search–Open 节点排查与冻结报告

本阶段围绕 BC+ 检索后的原文交付过程，完成了从固定前缀、文内片段定位，到统一 Search–Open 窗口接口的设计与验证。当前实现冻结为 `v002_raw_windows_mechanical`，供后续 harness 研究使用。

冻结版本的目标是：**为模型提供适量、相关、可追溯且可继续读取的原文，支撑后续研究。** 它不负责拆分原题、生成 gap、判断候选是否正确或决定何时提交，也不保证一次搜索就覆盖完整证据。

局部测试中，新窗口比固定前缀更容易展示后文相关信息；原文引用、预算和连续读取已经完成验证。但人物别名、复杂表格和文内定位仍有局限。当前结论支持将其作为研究基线，尚不足以证明在 BC+ 上普遍提高最终正确率。

本文是本节点的阶段总报告。此前逐轮记录保留在 [Search 动作优化记录](01_Search动作优化.md)，具体原文、配置和源码快照通过文末索引复核。时间目录采用 UTC，文中的阶段日期按北京时间理解。

## 1. 原始方案与问题来源

### 1.1 原始 Search 如何返回内容

原方案使用 Qwen3-Embedding-8B 编码 query，在约 10 万篇文档的预计算向量中进行 FAISS 检索，默认召回五篇文档，再从 SQLite 读取全文。模型实际看到的是每篇文档的前 1600 字符，以及 docid、URL、分数和截断信息。

```text
query → 文档向量检索 → top-5 文档 → 每篇前 1600 字符
                                      ↓
                          get_document 按字符位置读取
```

`get_document` 默认返回 8000 字符，单次最多 12000 字符。模型需要自行决定是否读取以及从哪个位置读取。Search 的返回位置不随 query 改变，同一篇长文档重复命中时，经常返回相同开头。

文档级向量并不意味着编码阶段覆盖了整篇原文。本阶段没有重建向量索引，也没有改变 BC+ 的事实内容和标准答案，主要修改文档召回后的定位、展示与读取方式。

### 1.2 三类真实案例

**546：召回了文档，但相关后文未被展示。** 旧 64 轮轨迹反复命中 84585《2023 British Open》，全文 52,592 字符，部分相关比赛记录位于末尾。模型没有读取后文，最后五次搜索没有新增 docid，最终错答 Mark Selby。这里只能确认前缀交付不足与重复搜索并存，不能据此认定改善片段必然改变候选判断。

**1094：比赛文档可见，具体事件不可见。** 旧轨迹召回 23800《2005 UEFA Champions League final》，前缀主要介绍赛事背景，比赛过程位于后文。模型未继续读取，后续搜索也没有形成充分核查。

**517：读取确实可以补充角色信息。** 旧轨迹在人物线索之外转向电影角色，调用 get_document 阅读 67431，看到角色表，最终识别 Peter King。该例提供了可以保留的成功阅读路径，而不仅是失败样本。

原始记录见 [64 轮 bad case 分析](../experiments/batches/20260917T090903.022551Z/bad_case分析.md)。本文对旧 546 的判断以 [原始回答](../experiments/runs/v000_baseline/qid_546/20260917T090903.079976Z/answer.md) 为准；此前一处后续对照表误写为未确认答案，已更正。

### 1.3 为什么不能把“没有 Open”直接当成失败

没有 Open 至少包含三种不同情况：Search 已提供足够原文；Search 返回局部内容但读取不方便；相关文档根本没有召回。它们需要不同处理。

因此，本节点不以 Open 次数增加为目标。真正需要检查的是：模型获得了什么原文，这些内容是否便于理解，需要继续读时是否有可靠入口。对已全文返回的短页面再调用 Open，即使调用成功，也不代表新增了有效信息。

## 2. 诊断方法与职责边界

### 2.1 固定输入，逐项比较

最初离线实验冻结历史 query、召回 docid、顺序与文档分数，只改变返回文本。原始全文保留，片段必须能映射到原文字符范围，标准答案不参与工具选择。

这一方法可以隔离工具返回的变化，但不能直接预测完整 rollout：模型看到不同文本后，下一条 query 和停止时机也可能改变。因此，冻结轨迹中的后续结果不能当作新方案一定会出现的行为。

### 2.2 当前 query 与整道题分开评价

用户明确将当前阶段收窄到单次信息需求。例如 query 询问电影角色时，不要求 Search 同时覆盖原题中的家庭背景、出生年份等其他约束。

但当前片段能否正确理解仍在评价范围内。角色表属于谁、比分对应哪一行、页面日期是什么字段，都会影响本次信息的使用。工具可以保留原文和结构，不能据此承担实体消歧、事实确认或缺失约束推断。

### 2.3 明确留给后续模块的工作

| 当前节点负责 | 留给模型或后续 harness |
| --- | --- |
| 文档召回、文内定位、原文窗口构造 | 原题拆分、information need 与 gap |
| 字符位置、结构边界、读取预算 | 别名对应、指代、事实关系与候选判断 |
| 不可变引用与连续展开 | 研究状态更新、纠偏、验证与提交 |
| 完整工具结果和审计信息 | research state 统一组织模型可见上下文 |

讨论中曾提出自动补充“身份说明”。虽然说明可以摘自原文，但判断哪句话解释两个名字属于同一个人，仍是额外语义操作，因此没有纳入最终设计。当前只提取明确的原文标题，不生成或选择语义身份摘要。

模型可见字段精简也暂不单独实现，避免与后续 research state 的统一上下文组织重复设计。

## 3. 片段实验如何推动设计收敛

最初五轮离线实验采用同一批 27 次 Search、135 条文档返回、59 篇去重文档，主要来自 546、1094、517。各轮版本号属于离线实验命名，不等同于当前在线工具版本。

| 离线轮次 | 改动 | 主要观察 | 结论边界 |
| --- | --- | --- | --- |
| v001 | 固定 400-token 块，文内 BM25 选一个块 | 部分后文提前可见，也会丢失身份或匹配错误事件 | 能改变可见信息，未证明在线收益 |
| v002 | 句子/行定位后向相邻内容扩展 | 517 保留角色表；1094 偏向文末分类词 | 候选粒度变化也改变 BM25，扩展不能补救错误定位 |
| v003 | 原排序下返回最多两个不重叠块 | 105/135 条增加第二块；补出赛事年份，也增加分类噪声 | 总文本量增加约 82.9%，不是等预算比较 |
| v004 | 允许纯空白重叠，并比较双块总上限 400 | 517 可同时保留姓名和角色；部分正文被裁断 | 上限相同，实际文本量仍比单块多约 15.3% |
| v005 | 固定父块和额度，在块内重新定位短窗口 | 部分边界改善；517 第二块移到职业经历，丢失姓名 | 文本量减少约 6.4%，不等于信息质量提高 |

### 3.1 多块能补信息，也会占用预算

1094 的第二块补出赛事年份，可以帮助检查 query 中年份与文档是否一致。但 546 的人物文档第二块主要是分类和外部链接，没有补充所需赛事结果。

517 还暴露了一个机械问题：身份块与角色块只共享一个换行，严格不重叠规则仍排除了身份块。允许纯空白交集后，这类误删得到修正。它说明去重需要处理真实文本边界，不能把任何字符交集都视为内容重复。

### 3.2 相关性更强的窗口，组合后未必更容易理解

v005 为每个块独立选择最匹配 query 的位置。角色窗口变得更集中，但另一个窗口也移向电影经历，丢掉人物姓名。两个窗口各自围绕电影词匹配，却失去了“身份＋角色”的互补关系。

这里并不要求工具理解两个人名是否等同。实验揭示的是一个限制：单纯局部词面排序无法保证最终观察保留理解所需的上下文。因此，没有继续叠加自动身份识别或复杂互补规则，而是转向统一的原文阅读接口。

## 4. 统一 Search–Open 设计

### 4.1 Search 完成第一次定向读取

最终设计定义为：

```text
Search(query)
  → 文档发现
  → 文内定位
  → 从完整原文构造窗口
  → 文档标题、原文、window_ref、继续读取信息

Open(window_ref, direction)
  → 根据已有位置确定范围
  → 使用同一窗口机制继续读取
  → 返回新观察及引用
```

这与 [原型讨论](../指令提示词/原型讨论.md) 中“Search 直接交付相关原文，继续读取可选”的方向一致。它减少必须额外 Open 才能接触后文的障碍，但不保证模型会正确理解或继续读取。

“定位单位”和“展示单位”分开：块用于找到位置，最终窗口可以跨过该块边界。当前实现仍先选 top-1 父块、再选择局部锚点，所以定位候选尚有父块限制；不能表述为已完全实现全篇任意位置的锚点竞争。

### 4.2 当前接口与预算

| 接口 | 行为 | 标题＋正文上限 |
| --- | --- | ---: |
| Search | 默认五篇文档，每篇一个原文窗口 | 每篇 400 tokens |
| Open before | 读取旧窗口之前，末尾接旧窗口起点 | 1200 tokens |
| Open after | 读取旧窗口之后，起点接旧窗口末尾 | 1200 tokens |
| Open around | 包含旧窗口并向两侧扩大 | 首次通常 1200，逐步增加，最多 2400 tokens |

标题只从明确的 `title:` 或 Markdown 一级标题提取，最多 48 tokens，计入总预算。URL、引用和 JSON 等结构开销另计。标题缺失时留空，不生成摘要。

before/after 采用不重叠连续读取；around 不重新排序。第一版没有 focus。未来若加入文内重新定位，必须与连续阅读区分，避免请求“向后读”时跳到另一处内容。

### 4.3 引用与状态

窗口内部记录文档 ID、全文哈希和原文范围。相同文档版本的同一范围复用引用，展开生成不同范围时产生新引用，旧引用不变。

| 状态 | 含义 |
| --- | --- |
| document_complete | around 的原窗口已经覆盖全文 |
| document_boundary | before/after 已到所请求方向的文档端点 |
| no_expansion_within_budget | 仍有原文，但当前预算或结构单元限制了继续扩大 |
| prefix_fallback | 定位没有词面命中，回退前缀 |

引用注册表当前在进程内保留。日志保存完整文本、范围和来源，进程重启后尚不能仅凭引用自动恢复。旧 get_document 仍供历史离线检查使用，不再暴露于当前模型工具 schema。

## 5. 在线试跑与局部诊断

### 5.1 在线轨迹没有证明长链路改善

统一接口初版对三题进行了最多 64 轮的完整试跑：

| qid | Search / Open | 结果 |
| --- | --- | --- |
| 517 | 5 / 0 | 人物正确，具体角色及部分解释未充分核实 |
| 546 | 3 / 0 | 错答 Judd Trump |
| 1094 | 7 / 1 | 未确认答案；Open 无新增原文 |

三题均自然结束。调用量减少不能单独作为收益：546 提前错答，1094 打开的短页面已经全文展示。新旧轨迹是独立采样，query 与召回结果不同，不能将差异全部归因于窗口。

因此后续评价收回工具节点，不继续用整题正确率驱动每一处片段调整。详见 [在线深测](../experiments/batches/20260917T181920.573676Z/README.md)。

### 5.2 固定真实输入后，定位问题更加明确

冻结上述 15 次 Search 的 75 条返回、53 篇去重文档，全部精确复现，并完成 225 次离线 Open 探测。

**517 的角色词没有保证角色块胜出。** 对 query `Peter King actor The Constant Gardener role policeman`，简介块 BM25 为 5.872428，角色块为 4.927818。姓名和电影词使简介块优先，局部锚点又选中人物介绍。一次 after 或 around 可以读到后方角色表，说明 Open 具备补齐原文的能力，但不证明模型会使用它。

**546 的数字和年份关系在词袋匹配中丢失。** 4–3、4–0 被拆成独立数字，0–3 等统计也可贡献分数；另一高分块没有 2023，却因 decider、centuries 等词胜出。词项相关并不表示比分、年份属于同一条记录。

**17 条返回已经覆盖全文。** 原 around 将其误报为预算内无法展开。该状态错误已单独修正，排序和原文不变。详见 [固定输入诊断](../experiments/offline/search_open_diagnosis/20260917T182655.718687Z/README.md)。

### 5.3 两个排序候选保留为实验，未并入冻结版

扩大到前三个父块后，517 能定位角色表，但其他文档出现 `next: 2023` 等元信息抢占锚点。保留完整比分可以区分 4–3 与 0–3，却仍可能将 2010、2013 年的记录匹配到 2023 年 query。

这些结果说明候选范围和词法有改进空间，但尚不支持直接替换默认排序。数字对原型还会处理年份区间，不是成熟的比分解析器。冻结版没有加入上述两组方案，也没有加入年份硬过滤、角色权重或实体消歧。详见 [定位消融](../experiments/offline/locator_ablation/20260917T183320.381757Z/README.md)。

## 6. 按“适量信息支撑”进行局部验收

### 6.1 测试设置

准备 20 个局部需求，来自九篇固定文档：11 个正向回归需求、一个信息不足控制、八个未用于窗口调优的新需求。19 个正向需求各预先标注一处支持原文，仅用于离线测量，不输入模型。

两组共 40 次会话。模型收到旧前缀或新窗口，可以继续读取最多两次，再交接观察到的信息、引用和局限。明确没有新 Search，不要求完成原题或解决所有缺失信息。

首次试运行使用合成 Search 历史，但 schema 只开放阅读，导致模型请求不存在的 Search。该轮单独保留。正式结果来自明确固定文档范围后的完整成对复跑，40 次会话均完成，无工具错误。

### 6.2 结果与证据边界

| 指标 | 旧前缀＋分页 | 新窗口＋Open |
| --- | ---: | ---: |
| 首次展示指定参考片段 | 13/19 | 16/19 |
| 八个新增需求首次展示参考片段 | 6/8 | 8/8 |
| 自主读取后展示指定参考片段 | 15/19 | 16/19 |
| 实际继续读取次数 | 3 | 1 |
| 首次完整观察 payload tokens | 9,505 | 12,015 |
| 包含继续读取的观察 payload tokens | 14,422 | 13,098 |
| API 总 tokens | 37,039 | 28,519 |

参考片段可见性不是语义支持率。Shevchenko 的例子中，新窗口提供了同一事实的另一处描述，没有包含预标注段落，因此自动指标漏计了有用信息。模型也可能看到相关文本后过度解释，不能把引用出现等同于理解正确。

首次 payload 增加约 26.4%，计入继续读取后约减少 9.2%。payload 使用本地 tokenizer 估算完整观察对象；API 统计包含上下文和模型输出，两者不可混用。旧方案按字符、新方案按 token 限额，不是严格等预算比较。

具体收益包括 Riise 任意球描述、What-a-Mess 正式姓名、扑克决赛对手更早可见。局部不足包括标题与查询别名不一致、角色表仍落在窗口外、占位页标题被过度解释。它们作为回归项保留，不强制当前工具自动识别全部缺失条件。

这批样本是手工选择，同一文档多题不独立。结果支持继续使用当前接口，不能外推到全部 BC+。详见 [局部信息支撑测试](../experiments/local_support/runs/20260917T184725.353925Z/README.md)。

## 7. 最终机械修复与性能验证

冻结前只处理机械问题，保持排序与语义职责不变：

- 空 title 不再跨行吞入正文。
- 原锚点选出后，按全文识别的句子/行边界尝试补齐范围；放不下时保留原锚点。
- 明确的 Markdown 管道表格，在连续原文范围满足预算时带回表头。
- 注册文档时预存边界数组，token 计数采用每实例最多 256 项的缓存。

33 项测试通过，覆盖原文、预算、引用不变性、前后连续翻页、around 饱和、空白、Unicode、长文本和新增结构处理。规则式边界不保证所有句子、HTML 或比赛记录完整，测试通过也不代表语义排序改善。

四篇真实文档的机械修复前后 Search 范围一致。重复 Search 的中位耗时约从 16–74 毫秒降至 4–65 毫秒；重复相同 around 的收益主要来自计数缓存，不能推广到每次都读取新位置的轨迹。约 115 万字符 HTML 的首次处理仍约 6 秒，没有稳定冷启动收益。

最长文档的注册对象图估算约 5.92 MiB，不包含 tokenizer、原生内存和计数缓存闭包，不是 RSS 或内存上限。文档和窗口注册表仍随访问增长，没有贸然加入会破坏旧引用的淘汰策略。

最终机械版未重新进行完整 API rollout；局部模型实验发生在它之前，四篇同范围检查与测试只能证明这些已检查场景未改变。详见 [机械修复与性能报告](../experiments/mechanical/runs/20260917T190036.604272Z/README.md)。

## 8. 冻结范围与后续使用

### 8.1 为什么当前可以冻结

接口职责、原文保真、预算、引用与连续读取已经明确，局部测试也提供了信息交付有效性的初步依据。继续为少数病例调整窗口，容易同时改变定位、呈现和模型行为，使后续 research state 实验失去稳定工具基线。

因此冻结的是一个可复现的研究条件，而不是最优搜索方案。后续模块应在同一版本下比较，避免把工具改动与研究状态收益混合归因。

### 8.2 冻结内容

| 项目 | 当前约定 |
| --- | --- |
