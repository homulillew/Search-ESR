# BasisPacket 固定原文与保守编译对照实验

本轮已完成六道开发题的四组真实 API 对照。输入隔离、来源记录和后续 Open 交接通过检查，但保守 Compiler 尚未表现出稳定收益：18 次调用中有 6 次放弃生成查询，成功输出中仍有关系表达含混。原文直送取得了四题的已核实来源，不需要额外的编译调用；另有一道题只有生成查询取得了部分有效入口。因此，可以保留 BasisPacket 的输入边界和原文路径，暂不将 Compiler 升级为默认方案。

完整产物：[本批运行目录](../experiments/query_initialization/basis_packet/runs/20260918T082045.350198Z/README.md)。设计依据：[BasisPacket 与保守查询编译设计](BasisPacket与保守查询编译设计.md)。本轮固定人工选择的原文，不包含自动 Selector，也没有完成最终回答。

## 1. 本轮要验证的问题

此前模型同时看到完整原题，负责选择依据、生成 query 和回填 refs。qid=645 出现查询使用多个原题单元、却只引用一个单元的情况；qid=786 则在引用位置正确时仍改变作品关系。

本轮将这两件事分开：Harness 从原题中提取固定片段并记录来源，Compiler 只接收文字。模型输出只包含 query，不再同步编号。实际发送范围由请求构造保证，查询是否忠实仍需审阅。

|组别|输入与处理|每题次数|
|---|---|---:|
|A 原文直送|固定片段按原文顺序拼接，只规范空白|1|
|B 保守编译|仅 packet，允许整体省略条件，保留所用事实关系|3|
|C 现有表达指令，仅 packet|适配此前完整线索表达指令，要求保留实质条件|3|
|D 现有表达指令，完整原题|与 C 相同的 system prompt，额外提供完整原题|3|

C/D 仅在是否提供完整原题上不同。B/C 比较的是整套表达指令，不能归因到其中一句提示词。C/D 是适配后的新诊断组，不是旧实验的原样重跑。

六题为 1117、551、645、786、1072、1172。原文选择、提示词、代码、参考标注和审阅规则均在请求前固定。查询共同上限为 1024 个本地 embedding tokens，包含检索前缀与特殊 token；六个原文查询实际为 64–146 tokens，无需裁剪。该实验契约与旧版 512 字符限制不同，不合并历史统计。

模型为 qwen3.7-flash，thinking=false，输出上限 1536 tokens，无 SDK 自动重试，格式错误最多修复一次。API 四路并发，本地 Qwen3-Embedding-8B 检索共享单线程。Search–Open、索引、top6、每窗口 400 tokens 和总观察预算 2400 均保持不变。

## 2. 执行与工程检查

|指标|A|B|C|D|
|---|---:|---:|---:|---:|
|计划尝试|6|18|18|18|
|API 请求|0|18|18|18|
|实际 Search|6|12|15|15|
|合法返回 null|0|6|3|3|
|API 总 tokens|0|6,303|9,807|12,678|

合计 54 次 API、48 次 Search、288 个窗口、28,788 API tokens。无格式修复、API 错误或检索错误。从首个会话事件到最后一个检索事件约 58 秒；这是并发批次时间，包含检索与模型加载影响，不能当作单次 API 延迟。

14 项核心测试和六题真实输入预检通过。归档审计进一步核对了：原文切片与来源版本、C/D 单变量输入、实际初始请求边界、API 响应到 query 的对应、查询预算、Search 时序、窗口原文、标题与引用、观察账本和 handoff。修复输入边界由单元测试覆盖，本批没有真实修复请求。48 个完成会话在临时账本副本上恢复后，Open 全部成功；恢复检查没有新增 API 调用，也没有修改原始账本。

这里通过的是执行与交接。来源记录可以证明模型接收了哪些文本，不能证明生成查询的关系正确。

## 3. 输入隔离与语义表达的结果

语义审阅逐条对照原题、packet 和 query，将明确改变、歧义、完整省略、使用未选原题内容分别记录。1072/1172 和 551/645 的审阅隐藏了组别；1117/786 的主审阅此前看过部分带组别输出，因此不称为盲审。审阅由本次协作代理完成，没有额外 API 裁判，也没有人工金标准；边界判断保留引句和复核记录。

|指标，按出现该现象的尝试计|A|B|C|D|
|---|---:|---:|---:|---:|
|有 query 可审阅|6/6|12/18|15/18|15/18|
|明确关系改变，严格口径|0|0|1|0|
|关系含混或改变，合并去重|0|5|10|15|
|使用 packet 外、原题已有的内容|0|0|0|10|

弃答不计为忠实度成功。A 的零改写问题只适用于这六个人工 packet，不证明任意片段选择都完整合理。D 的额外内容确实在其输入中，因此属于使用未选依据，不是凭空捏造，也不是运行时泄漏。

### 3.1 限制输入确实减少了未选内容的进入

C 的 18 次尝试没有观察到使用 packet 外原题事实；D 有 10 次。具体包括：

- qid=1117 的三次 D 加入 1853 年死后出版信息，来自未选 q4。
- qid=645 的三次 D 加入“最主要化合物”和 Results and Discussion，来自未选 q5。
- qid=786 的三次 D 加入出生年代、移民背景与 Perfectly formed，来自未选 q2/q3。
- qid=1072 的一次 D 加入 scholarship，来自未选 q7。

这支持输入边界的作用。它不保证未来模型不会从记忆补信息，也不说明这些额外线索必然损害检索。

### 3.2 正确的输入仍可能被错误压缩

qid=1117 的 C 第三次输出包含：

```text
eloped with sibling who received B.A. in 1821 M.A. in 1824
```

原文是 Major 与某人私奔，获得学位的是这个人的 sibling。query 将学位获得者直接变成私奔对象。C 第一次的 `Major eloped with sibling B.A. 1821 M.A. 1824` 也有同类问题，但关键词式表达使判断存在边界。初审记两条关系改变，复核后的严格口径只记一条明确改变，另一条保留为含混；总体结论不依赖这条边界判断。

qid=551 的四条模型生成查询都写成 `retired 2020`，没有保留 as of。这里没有明确的 `in 2020`，因此记录为时间含混，不直接判成确切年份错误。qid=645 的五条查询使用 `Farjon 2020 study`，没有表达第一篇参考文献作者的关系，也按归属含混记录。

这些现象说明编号与输入隔离解决了部分来源管理问题，关系表达仍取决于生成行为。B 在部分题目上保留长句，C/D 则较多退回关键词并置；提示词中的“保留关系”没有稳定转化成输出结构。

### 3.3 保守组的弃答成为新的可用性问题

B 在 qid=551、786 上各三次返回 null。C 的三次弃答来自 551 一次、786 两次；D 来自 551 一次、1072 两次。

12 次响应均正常 stop，正文只有 `{"query": null}`，没有拒绝原因或推理字段。因此，不能断言模型明确认为“缺少实体名所以无法搜索”。目前能确认的是：这些 packet 可以构造原文查询，部分也由其他组成功生成查询，但该 Compiler 配置选择了不输出。

一个待验证的解释是，`usable query` 的判断边界过宽，模型将检索尚未确定对象的不确定性当成了生成障碍；保守约束与 null 出口也可能共同影响这一行为。本轮没有隔离这两个因素，不将其写成已证实根因，也没有自动 fallback 隐藏弃答。

## 4. 检索效用：旧参考计数与补充审阅分开

运行前正例池覆盖四题；786、1172 没有已确认标注。冻结池的原始计数如下：

|指标|A|B|C|D|
|---|---:|---:|---:|---:|
|取得与 packet 对应的已确认来源|4/6|9/18|11/18|9/18|
|窗口展示冻结参考依据|3/6|7/18|6/18|7/18|

这里的分母保留全部尝试，包含弃答；A 每题一次，其他组每题三次，不能直接比较总次数。未命中有限正例池不等于无关，也不是全库召回率。

本轮随后补充了两类核实。qid=645 的一些窗口返回研究摘要，已经展示 2020 日期、叶片蜡质分析与地中海物种，只是没有覆盖冻结标注中的研究目的或参考作者。因此新增摘要证据组合，避免把“旧参考区间未出现”误写成“窗口无用”。qid=786 新确认 doc75245 为导演与改编系列的部分入口：它连接 Kevin Connor、Amicus 改编计划及恐龙电影，尚不证明片长、目标演员或侄子合作关系。

补充审阅后的逐题结果如下，每格为“有用来源次数 / 依据可见次数”；模型组每题三次，A 一次：

|qid|A，1 次|B，3 次|C，3 次|D，3 次|
|---|---:|---:|---:|---:|
|1117|1 / 1|3 / 3|3 / 3|3 / 3|
|551|1 / 0|0 / 0|2 / 0|2 / 0|
|645|1 / 1|3 / 3|3 / 3|3 / 3|
|786|0 / 0|0 / 0|1 / 1|1 / 1|
|1072|1 / 1|3 / 3|3 / 3|1 / 1|
|1172|0 / 0|0 / 0|0 / 0|0 / 0|

这些补充标注形成于运行后，不能与预先冻结的标注混称。786 的 17 个池中文档进行了筛查，其中 6 个全文阅读、11 个定向检查，后者没有据此标成负例。审阅使用了离线标准答案辅助姓名检查，答案没有进入在线请求。1172 的 9 个池中文档全部阅读全文，未核实符合上映区间与同名关系的有效入口；其中有旧电影的 DVD 发行日期，不能替代电影在原产国的上映日期。这仍不证明全库没有有效来源。补充来源审阅不称为盲审；1172 审阅在初次查看文档池结构时看到了组别与排名，其此前独立语义审阅仍未查看这些信息。

逐题结果揭示了不同问题：

- 1117、1072 的原文已经提供可用入口。生成调用没有稳定增加材料，1072 的 D 还因弃答损失两次搜索。
- 551 的 A/C/D 找到了同一篇相关文档，但窗口落在其他门将的段落，未展示目标 2011 年事件。这是来源已找到、阅读尚未到位的情况，不能归为 Query 没有完成任何任务。
- 645 的来源在各组均能找到，区别主要在文内观察位置。关系简写有风险，但摘要也能提供有用阅读内容；文档命中不能反过来证明简写关系正确。
- 786 的 C/D 各有一次获得 A 没有取得的部分入口。因此不能据此永久取消所有查询表达；当前 B 在该题全数弃答，也不能作为这项收益的证明。
- 1172 的各组都没有核实入口，说明忠实表达本身不能保证辨识度或检索匹配。本轮没有改变所选信息，尚不能区分入口选择与检索器匹配各自的影响。

## 5. 本轮决策与下一步

保留已经实现的 BasisPacket、原文提取、来源记录和独立请求边界。它们减轻了模型同步编号的负担，也能明确区分选定依据和实际可见输入。

Compiler 继续作为实验路径，不替换默认初始化器，不因少数正确表达而宣布稳定。当前证据支持将 Verbatim 作为下一阶段的主要基线：它没有额外的编译 API 成本，在四题已有确认来源上均取得入口。不过，人工选择 packet 的质量尚未转化为自动选择能力，当前结果也没有覆盖新题泛化。

下一步优先单独测试 Selector：模型只选择原文片段，Harness 提取并直接搜索。先检查是否选中可独立检索、上下文足够的材料，以及这些材料是否能提供入口。若仍保留 Compiler 对照，应对同一次选择结果分叉，继续保留弃答，不引入隐藏 fallback。Compiler 的 null 边界和关系表达方式可以另做小实验，但不能与选择策略同时修改后再解释收益。

本轮没有新增 gap、候选验证、重规划或最终提交机制。查询节点的结论仍限于能否形成忠实、可执行且有检索价值的入口。
