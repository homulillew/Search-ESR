# 认证失败批处理短路修复

**这是 execution harness reliability 的独立修复，与 Evidence Pointer 语义实验
分开归因。** 本修复不改变任何语义结论，也不改变任何历史失败批次的记录。

---

## 问题（`750257d` 的实际数据）

直接读取两批历史 events：

| 批次 | 发送请求数 | 响应数 | api_error | 类型 | 单次耗时 |
|---|---|---|---|---|---|
| `model/` | 12 | 0 | 12 | AuthenticationError | 0.06–0.31 s |
| `model_retry_071500Z/` | 12 | 0 | 12 | AuthenticationError | 0.06–0.24 s |

`run.execute` 的发送循环对每个 job 无条件 `emit('request')` 然后
`client.chat.completions.create(...)`。**没有任何短路**：凭证已被明确拒绝
（401，亚秒级返回），仍把剩余 11 个请求逐个发给同一端点。两批共
**24 次明确无效的 API 请求**。

## 修复

`experiments/research_state/first_observation/run.py`：

1. `execute` 新增关键字参数 `auth_error_types=()`。
2. 发送循环在捕获到该类型异常后记录 `auth_failure`，后续 job 直接
   `emit('blocked_by_auth')`，不再发送。
3. `audit` 识别 `['blocked_by_auth']` 事件序列 → status `blocked_by_auth`。

为什么是显式类型而不是字符串匹配：`openai.AuthenticationError` 是 SDK 的具体
异常类（`APIStatusError → APIError`），可直接 `isinstance` 判定，不需要猜错误
消息体。默认 `()` 表示旧行为完全不变（见 regression 测试）。

## 分母语义（刻意保留）

- `blocked_by_auth` 计入 `scheduled`，**不计入** `attempts` / `responses`：
  未发出的请求不是 API 尝试。
- 那次**确实发出**的请求没有响应，usage 真正未知，因此
  `unknown_usage_requests = 1`，`cost_accounting_complete = false`，退出码 2。
- 这与历史批次 `cost_accounting_complete=false` 的语义一致：**交付不完整就是
  交付不完整**，不因少发请求而变成"完成"。
- 历史两批 12/12 AuthenticationError **原样保留**，未被重算、未被删除、未被
  改判。

## regression 测试

`tests/test_evidence_pointer_regression.py`（AuthShortCircuitTests，5 项）：

| 测试 | 断言 |
|---|---|
| 认证失败停止 notes 批次 | 1 次请求；`statuses = {api_error:1, blocked_by_auth:3}`；`attempts=1` |
| 默认行为不变 | 不传 `auth_error_types` 时仍逐个发送（复现旧行为），不出现 `blocked_by_auth` |
| journal 序列正确 | `('request','api_error')` ×1 + `('blocked_by_auth',)` ×3 |
| 导出仍记账 | review mapping 的 status 计数与执行一致 |
| 无隐式 resume | 对已存在目录重跑 → `FileExistsError` |

`tests/test_evidence_pointer_ab.py` 另有 3 项覆盖 evidence_pointer stage 上的
同一行为，包括"blocked job 不产生虚假 usage"与"确实发出的请求 usage 未知"。

## 为什么不做这些

- **不新增付费 smoke request** 来探测凭证是否有效。短路只在 SDK 已经抛出
  `AuthenticationError` 之后触发，不产生任何额外调用。
- **不重试**。凭证对整个 `execute()` 调用是固定的（同一 endpoint、同一 key、
  同一 profile），重试同一配置没有信息增益。
- **不把未发送项记为 `skipped_first_search`**。那是"首轮检索失败、无观察可用"
  的语义；这里是"有观察可用、但凭证阻止了模型调用"，必须区分。

## SDK 限制

`openai` 1.109.1 的 `AuthenticationError` 继承自 `APIStatusError`，由 401 响应
触发，可直接识别。若将来端点把凭证错误包成 200 + body 错误码，或 SDK 改变异常
层级，本修复不会触发——那时应记录为限制并重新设计，而不是猜测。
