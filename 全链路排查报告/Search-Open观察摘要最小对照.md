# Search–Open观察摘要最小对照

## 要验证的问题

上一轮已经能够记录 Search/Open 返回过哪些原文，以及每次调用增加了哪些区间。但记录保存在后台，模型仍可能将旧内容称为新增，或继续搜索相同内容。本轮测试一个最小干预：将机械生成的观察摘要交给模型，能否改善新旧判断、减少重复搜索，并保留取得必要证据的能力。

结果显示，这一版摘要对识别完全重复的返回有局部帮助，但没有减少自主轨迹中的零新增搜索，还在需要继续阅读的控制题上出现退化。因此保留观察账本，将摘要留作实验版本，暂不接入默认运行时。

## 实验设计

两组使用相同的 baseline 原文窗口、检索器、系统提示词和工具描述。工具返回不改动，后台观察账本均启用。无摘要组只接收原有对话；有摘要组在每次 API 请求末尾额外接收一条观察摘要，以独立 user-role 消息传递。摘要不会不断累积到保存的对话历史中。

摘要列出上一请求之后返回的窗口、输出窗口引用、正文区间、新增正文区间、重叠字符数、重复引用状态，以及最近三次 Search 的新增来源字符数。它明确说明新增原文不代表新证据或研究进展，不要求 Search、Open 或停止。摘要没有读入参考答案，也不判断候选是否正确。

这次干预同时引入了观察信息和额外消息的呈现方式，没有设置同长度的占位消息组。因此结果只评价当前摘要方案，不能把全部行为变化归因于某一个字段。

|样本|设置|会话数|
|---|---|---:|
|自主轨迹|此前预选新题 580、905、1034、593、177、387；每题两组各两次|24|
|局部控制|完全重复、部分新增、信息充分、需要继续阅读；每类两组各两次|16|

自主轨迹沿用此前真实首轮 query 及 top5 返回，从相同的首轮观察继续。控制题使用真实文档和窗口构造器生成相同历史；其中重复调用是人为预置，用于诊断，不代表自然发生频率。后续 Search/Open 均实际执行，模型为 qwen3.7-flash，thinking 关闭。

每次最多四轮后续工具调用，再要求终答；每次 API 输出上限为 2048 tokens，超时 120 秒，无 SDK 自动重试。两组预算相同。问题、任务顺序与方案在结果产生前保存。本轮没有改变生产的 64 轮默认预算。

## 执行与机械验收

40 次尝试中，33 次取得完整回答。7 次返回 `finish_reason=length`，被原有运行时作为不完整回答拒绝保存为成功终答。无摘要组 5 次，有摘要组 2 次，均发生在自主题目中；16 次局部控制全部完成。失败尝试的完整请求响应及观察仍保留，没有补跑覆盖。

全部 530 个返回窗口通过原文一致性检查，已发送的工具对象与账本记录一致。所有实际注入的摘要都能从当时的账本重新生成；无摘要组没有混入摘要。工具执行错误为零，最终回答中出现的窗口引用均存在于本会话。这不等于每个引用都支持其旁边的具体主张。

摘要最长 833 个本地 tokenizer tokens，没有触发 1200-token 明细省略上限。包含既有测试的 51 项测试全部通过；冻结文件哈希不变。本轮未修改生产窗口或默认对话入口。

## 局部控制：新旧判断改善，但阅读不足出现退化

|检查|无摘要|有摘要|
|---|---:|---:|
|完全重复时正确判断没有新增|1/2|2/2|
|部分新增时摘录确属新增区间|2/2|2/2|
|前三类控制的 5TB 核心事实正确|6/6|6/6|
|单独的信息充分控制中，额外工具调用|0|0|
|需要继续阅读时取得角色片段并正确回答|2/2|0/2|

完全重复场景先返回 Search 窗口，再两次读取同一 after 窗口。无摘要组一次将已经返回过的软件配置句称为新增；有摘要组两次都正确指出没有新增。不过，结论正确不表示整段叙述都正确：无摘要组另一次用“后方没有更多内容”推导“本次没有新增”，理由不成立；有摘要组一次把返回窗口引用误写成 Open 的输入引用。

部分新增场景使用 around 扩展原窗口。两组均从实际新增区间摘录软件配置原文，保持了 5TB 的事实回答。这说明摘要没有在这一小组样本中造成新旧混淆，但不存在组间优势。

需要继续阅读的控制题仍问 Peter King 在《The Constant Gardener》中饰演什么角色。两组预置完全相同、重复两次的 Search 结果，窗口没有展示 Policeman 1。该设计用于检验：当最后一次返回为零新增，模型是否仍会阅读未展示的相邻部分。

无摘要组第一次先 Search 再 Open，第二次直接 Open，两次都取得角色行并回答 Policeman 1。有摘要组两次都没有后续工具调用，直接回答 minor role，或表示来源没有提供具体角色名。这个结果构成当前候选的明确回归警报。每组仅两次，还不能推断稳定的总体退化幅度，但足以阻止将此版直接设为默认。

## 自主轨迹：搜索减少，重复率没有改善

以下统计包含所有 24 次尝试中实际完成的后续工具调用，排除预置首轮。失败尝试已经生成的观察也计入行为统计，不能将它们混同于恢复后保留的有效会话覆盖。

|指标|无摘要|有摘要|
|---|---:|---:|
|完整回答|7/12|10/12|
|后续 Search|41|29|
|后续 Open|1|0|
|零新增 Search|2/41（4.9%）|4/29（13.8%）|
|相邻连续零新增 Search 对数|0|2|
|返回正文中已展示字符的比例|40.2%|52.2%|
|发起强制终答请求的会话|10|7|
|API 总 tokens|542,365|463,634|

有摘要组调用和 tokens 较少，但重复率更高，不能解释为搜索效率提升。输出截断在两组间不均衡，且调用减少可能来自较早停止，因此这些汇总是描述性结果。

只保留两组都成功完成的 7 对自然轨迹，方向也没有改变：Search 为 21 → 13，零新增比例为 9.5% → 30.8%，正文重叠比例为 37.7% → 63.4%。这只是补充检查；按成功状态筛选会产生选择偏差，不能消除全部实验限制。

qid=1034 提供了直接坏例。有摘要组两次运行都在后续第三次 Search 得到零新增，之后再次提交完全相同的 query，第四次仍是零新增。模型发起第四次调用前已经收到包含零新增事实的摘要。这说明当前形式的状态信息没有可靠驱动下一步行为调整。

另一方面，qid=387 的首轮窗口已经包含 5TB。有摘要组两次都直接给出这个存储容量，无摘要组继续调用工具后也给出相同数值。但题目还包含公司、游戏和动画作者的多跳对应关系，回答中仍有不可靠的关联说明。这里只能确认核心数值已可见，不能将提前停止算作整题正确率或全部验证成本的改善。

## 如何理解这些结果

观察账本与模型决策之间还有一层转换。账本可以准确指出某次 Search 没有增加原文，但这个事实同时兼容多种情况：已有信息已经足够，尚未展示的相邻段落值得阅读，query 一直围绕错误候选，或同一段原文需要重新解释。摘要没有提供区分这些情况的语义判断，模型也没有稳定地自行完成区分。

角色题中的停止过早与这一缺口一致，但当前实验不能证明具体心理机制。额外 user-role 消息的位置、机械字段对注意力的影响，以及模型自身的随机性，都可能影响行为。即使摘要写明“不代表研究进展”，也不能假定模型已正确理解其适用边界。

qid=1034 则说明另一种失败：知道重复仍然重搜。没有证据支持将一个零新增阈值直接升级为强制 Open 或切换候选的规则；这样会把不同原因的重复混在一起处理。

## 当前处理与下一步

保留现有 Search–Open、后台观察账本和恢复机制。观察摘要代码、预设方案、完整轨迹与审计独立放在实验目录，默认运行时保持不变。

下一步应把“原文是否新增”与“当前问题是否得到证据支持”分开。前者继续由 harness 计算；后者需要模型围绕当前研究问题判断，并引用支持窗口。是否给出候选、继续阅读或重新搜索，不能只由新增字符数决定。

在扩大研究状态之前，可以用这组局部控制检查更小的修订：明确区分输入引用与返回引用，调整摘要在上下文中的呈现位置，并验证它不会诱导模型把零新增当成停止依据。各项修订应独立版本化，以便区分呈现问题和语义状态问题。本轮没有把这些假设追加为窗口规则，也没有加入强制动作。
