# Research State qualification protocol

Historical experiments remain append-only. This branch tests when a visible candidate judgment merits promotion to a descriptive control card. Evidence is observed prefix content; a hypothesis is an unverified candidate; a qualified control state is a prefix-supported judgment useful for selecting the next source. Neither a hypothesis nor partial evidence automatically becomes persistent state.

Only three statuses are used: `no_target`, `hypothesis_only`, and `inspectable`. `Inspectable` means a source is a reasonable place to test the stated immediate need, not that the candidate is the final answer. Current need, supported part and missing prerequisite must be recorded separately. All R1/R3 tools stay available; no backend, localizer, reranker, AtomicNeed prompt or action mask is changed.

R1 reuses all 13 frozen P1 broad-plan checkpoints and their historical H0 response. A single reviewer reads only each original question, checkpoint prefix, broad plan and already visible handles. The annotation and R1 request construction are frozen before calls. New H1 adds one descriptive qualification card after the unchanged broad-plan card and samples one Actor response without executing tools. If the card produces no material paired action/target difference, stop before R2. R2, if reached, tests no-tool self-qualification against frozen R1 annotations. R3, if reached, compares historical Orthogonal+Plan rollouts against new Orthogonal+Plan+Qualification rollouts. R4 Workspace Directory and R5 Guard require their separate gates and are not presumed.

Primary R1 outcomes are candidate inspection in `hypothesis_only`, candidate utilization in `inspectable`, random inspection in `no_target`, and scope appropriateness. A Find(D#) or Open(W#) targets the same document if the window is mapped to that D# in the prefix. Mixed batches retain all calls and first call. A broad Plan and the curated qualification card differ in more than one field, so R1 estimates the effect of the full qualification message, not the isolated status token.

All calls use DeepSeek `deepseek-flash`, unchanged Search/Find/Open schema, 240-second timeout, zero retries, one sample per cell. Provider/parse/validation errors are preserved. Freeze manifests include git HEAD, source and historical hashes, prompts, schema, selection, annotations, request hashes, horizon and failure policy. No gold, future trajectory, post-checkpoint tool result or final answer informs annotations.

Failure codes: QF1 unsupported candidate promoted; QF2 observation over-interpreted; QF3 stale target retained; QF4 suitable source not promoted; QF5 correct qualification ignored; QF6 correct qualification but wrong D; QF7 correct D but ineffective local query/window; QF8 useful evidence with no belief update. One-step R1 cannot observe QF7/QF8.
