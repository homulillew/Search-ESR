# 工具描述单变量对照：第二轮预设方案

第一轮仅追加系统阅读约定，Gardener未获改善，Estate由Search转Open但核心答案原本已取得。第二轮独立比较当前description与候选description；系统提示词一律使用原始版本，不叠加第一轮阅读约定。

保持第一轮6个用户问题、定位query、初始窗口、每例每组3次、4轮后续工具预算、采样默认值不变，共36个新会话；重新运行基线，避免只用较早一批结果作为对照。固定种子918打散任务顺序。仅修改工具及参数的description文字；参数类型、必填项、枚举、范围、工具实现均不变。去掉description后Schema必须逐项相同，API请求也保存实际tools。

候选描述说明工具功能、使用场景、能力边界、输入语义、重要输出和可选衔接；无答案专属文本，无强制Open，无research state。设计在第二轮API开始前冻结为tools_candidate.json。

评价沿用第一轮：取得未展示细节的实际证据、最终核心答案依据、已有充分信息时的额外调用、全文不足时的错误结论、引用与执行错误、预算耗尽和token成本。Open数量不是优化目标。从其他文档取得直接证据也计入。新增事实的正确性与核心答案支持分开审阅。

这是在既有坏例上设计的局部诊断，非独立泛化测试。第二轮不能与第一轮交叉拼成完整因子实验，也不能用Open增加替代答案质量。两轮均不自动替换生产实现或提示词。
