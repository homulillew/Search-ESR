# 统一 Search/Open：首轮在线深测

本轮运行 qid=517、546、1094，模型 qwen3.7-flash，最多 64 轮工具请求，三题 API 并行、共享串行检索。工具实现保持运行开始时的源码版本，窗口标题与正文预算、Open 方向和引用机制见各题源码快照。未在运行中修改工具。

标准答案仅在运行后人工核对。实体层面 1 题正确、1 题错误、1 题未作答；没有整体改善的证据。

## 517：身份可见，但具体角色仍未核实

事件 16 的 Search 返回 67431 [0,1299)，包含姓名、家庭背景、电影名和早期职业经历。事件 20 使用更具体的 `Peter King actor The Constant Gardener role policeman`，仍返回同一窗口，而角色表位于后方，没有显示在该窗口中。

模型没有 Open。最终实体 Peter King 正确，但将角色描述为“often cited as a policeman or local authority figure”，没有通过实际可见的角色表确认。还对生肖差异及编剧信息给出无依据解释。事件 16 的 89082 提供演员名单，但不能据此验证最终回答中的所有导演与编剧陈述。

这说明单次离线 query 能命中角色表，不保证真实模型生成的另一条 query 也会命中。文档身份得到保留，但定位和是否继续阅读仍然影响证据充分性。

## 546：正确候选已出现，模型仍提前错答

模型在第一次工具调用前就提出 Judd Trump。事件 4 的 Search 已返回标题为 Ding Junhui 的 38231，但正文窗口落在 2017/2018 附近，未定位到题目要求的 2023 年比赛链。

事件 8 又返回 84118，明确提到 Ding 在 2023 年 English Open 以 4–3 获胜。该片段并未证明题目完整比赛链，但至少提供另一个真实候选。模型没有进一步读取或核查，而是在第三次搜索转向 Judd Trump，随后提交错误答案，并反复猜测题目年份是否记错。

失败包含两层：窗口的局部词面匹配未选中所需年份关系；模型对已有不同候选线索没有充分核查。增加 Open 可用性并未自动改变其候选选择和提交行为。

## 1094：Open 被调用，但没有新增信息

模型进行了 7 次搜索，随后对 39918 调用 around。该文档只有 372 字符，内容为 YouTube 标题、占位符和导航项；Search 已返回全文，has_more_before 和 has_more_after 都为 false。

事件 32 的 Open 返回相同引用、相同原文，新增字符为 0，状态为 no_expansion_within_budget。引用机制符合实现，但该状态没有区分“全文已读完”和“预算限制”，诊断信息可以更准确。

模型最终未作答，并声称 corpus 不包含所需信息。有限检索只能支持“本轮没有找到”，不足以证明整个语料库不存在。该轨迹没有召回此前相关的 23800；因此本题还存在上游 query/召回差异，不能只归因于窗口展示。

## 工具和边界检查

新增 6 组边界测试全部通过：纯空白、长标题、Unicode 长段、表格、连续 before/after、重复 around 饱和。验证的是预算、原文位置与引用一致性，不证明标题提取或语义边界总是正确。

在线审计未发现工具异常、可变引用或 Search 预算超限。三题没有完全相同的重复 query，每次 Search 至少带来一个新 docid；但新 docid 不等于新证据。1094 的第六次 Search 只有 443 个新增正文字符，仍可能主要重复旧内容。

Open 仅发生一次，新增原文为 0。因此当前不能宣称“只 Search、不有效阅读”已解决。

## 下一步优先级

先做冻结在线 query 的定位诊断：517 的第五次搜索为什么仍选中简介而非角色表，546 为什么定位到不匹配年份。按同一 query 检查窗口和可读上下文，避免通过换 query 掩盖工具问题。

随后明确完整文档的返回状态和展开提示，使已全文返回的短文档不被误认为仍可扩展。是否加入阅读提醒，应作为另一个变量，不与窗口定位修改混在本轮结论中。

完整轨迹与离线实体核对见各题目录；本轮没有增加强制 Open、gap、replan 或验证器。
