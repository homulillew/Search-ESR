# 64 轮预算 bad case 分析

分析范围：20260917T090903.022551Z 批次，qid 311、776、324、546、517、1094。模型为 qwen3.7-flash，enable_thinking=false，最多 64 轮工具调用；本次全部主动结束。未修改运行策略，未重跑模型。分析依据为实际 API 请求、响应与工具返回，并在运行结束后对照本地数据集的 gold_docs、evidence_docs。下文的事件号对应各题 events.jsonl 中的 seq。

## 1. 核心判断

这批主要问题不是预算耗尽。六题在 6–19 次工具调用后全部主动结束，结果为一题实体正确、一题错误、四题弃答。模型经常在研究过程中反复搜索，但没有把检索到的材料转化为可检查的关系；最后或者宣称找不到，或者把自己的猜测写成结论。

不能将所有失败都归为候选锁定：546 有清楚的候选/赛事锁定，776 更像检索方向和表述打转，311 还出现长篇无依据枚举及基本约束判断错误。不同问题需要不同干预。

| qid | search / read | 结果 | 主要失败位置 |
|---|---:|---|---|
| 311 | 6 / 0 | 弃答 | 无证据枚举、错误排除入口、未召回标注证据 |
| 776 | 19 / 0 | 弃答 | 问题条件被擅自缩窄、相似查询循环、未召回标注证据 |
| 324 | 18 / 0 | 弃答 | 已见答案端线索，但没有建立中间实体—事件—年份关系 |
| 546 | 10 / 0 | 错误 | 猜测赛事与候选，反复看到相同片段，最后无依据补全比赛链 |

| 1094 | 10 / 0 | 弃答 | 未证实的球队假设限制查询，正确比赛文档未被深入阅读 |

“主动结束”仅表示模型返回了无工具调用的普通回复，不代表证据充分或回答有效。自然弃答不是技术上的“不提交”，也不证明语料库不存在答案。

## 2. 量化：重复文档、命中证据和读到证据是三件事

| qid | 返回文档条目 / 去重后 | 没有新增 docid 的搜索序号 | 命中的标注 gold docid |
|---|---:|---|---|
| 311 | 30 / 16 | 无 | 无 |
| 776 | 95 / 49 | 12、13、16、19 | 无 |
| 324 | 90 / 40 | 17、18 | 85213 |
| 546 | 50 / 12 | 6、7、8、9、10 | 4975、84585 |
| 517 | 35 / 30 | 无 | 67431 |
| 1094 | 50 / 17 | 5、9、10 | 23800 |

776、1094 各有 2 次完全重复 query；其他题没有完全重复 query，但仍可能在语义上打转。311 每轮都有新 docid，依然没有找到目标。因此“新文档数”只能用于诊断，不能等同研究进展。

这里的 gold/evidence 命中只使用数据集标注做离线交集统计：未命中不证明其他文档完全无用；命中也不证明实际返回的前 1600 字符已经包含关键证据。完整数据见 [bad_case_metrics.json](bad_case_metrics.json)。

## 3. qid 546：最清楚的“猜测逐渐变成事实”

[完整轨迹](../../runs/v000_baseline/qid_546/20260917T090903.079976Z/trajectory.md)

### 首次偏离和持续过程

- 事件 2：检索之前，模型已经列出多名球员和职业年份、赛事成绩等“背景事实”，但这些内容尚没有工具证据。
- 事件 12：第三次搜索返回 84585《2023 British Open》。片段明确是 British Open，开头是决赛和半决赛结果。
- 事件 14–19：模型转向猜测 Players Championship，并开始搜索该赛事下的 Bingham、Selby。没有先证实赛事名称与赛制。
- 事件 20：55516 的片段明确提供 Selby 的职业起点 1999、6 次满分杆和超过 800 次破百。模型在事件 22 修正了此前猜测的职业起点。这说明它会利用部分证据纠错。
- 搜索 6–10：连续五次没有新增 docid，也没有调用 get_document；不同 query 一直重放相同开头。
- 事件 38：模型用问号猜测 Selby 击败 Liang Wenbo、David Gilbert，再负于某位球员。
- 事件 40：最后一次检索返回的片段并不提供这条比赛链。
- 事件 42：模型去掉问号，把比赛链写成“verification”，给出错误答案 Mark Selby。标准答案是 Ding Junhui。

复核全部模型可见工具文本，没有出现 `Liang` 或 `Players Championship`。这不是仅凭最终答案错而推测幻觉：最后一轮返回内容与最终具体断言之间存在可直接检查的证据缺口。

### 不是单纯召回失败

84585 全文长 52,592 字符；在约 51,783 处有 Ding Junhui 对 Julien Leclercq 的 4–0，约 52,182 处有 Mark Williams 对 Ding Junhui 的 4–2。模型多次命中文档，却始终只看到前 1600 字符。

这些后文能推进关系链，但仅凭它们仍不能说原题所有条件都已证实。该例支持“对已命中文档进行相关段落定位”，也支持“未证实的赛事名称不能成为持续搜索的固定前提”。

### 最小干预假设

在连续返回相同片段后，明确剩余问题是“哪份 2023 赛事记录具有原题所述的连续四场关系”，允许从已命中文档深读或返回不带候选的赛事检索。最终检查必须要求比赛关系的实际引文，不能仅核对球员一般统计。

## 4. qid 324：答案名称出现了，但关系链没有形成

[完整轨迹](../../runs/v000_baseline/qid_324/20260917T090903.066977Z/trajectory.md)

事件 2 正确写出了最终目标是“X 获胜两年前的同一赛事冠军”，但也把原题的 `third major tournament` 改写成了 `third major tournament win`。这是额外增加的含义，不应当作已知条件。

第一次搜索的事件 4 已返回 85213，其可见开头明确写着：Svetlana Gromenkova 是 2008 年 WSOP 女子无限注德州扑克冠军。该文后来又在事件 12、44、60 出现。

这并不表示模型此时已经有充分理由直接答 Svetlana：还缺少 X 的比赛年份、赛事同一性和线索匹配。但是，它已经拥有一个可以继续检查的答案端线索。后续却主要在“web design”“piano”“third major tournament”“animal rights”等原始短语之间切换，没有沿“2008 女子赛事 → 两年后 2010 同赛事 → X”探索。

另一个已召回的标注证据文档是 54231。其全文为约 115 万字符的 HTML，前 1600 字符是页面代码，关于 Shaun Deeb 的祖母参加主赛的信息出现在约 10,856 字符处及后面的正文/重复结构中。当前工具把原始开头当作片段，实际没有交付这条有用线索。

离线标注材料 42885 提供 Vanessa Hellebuyck、2010 年女子赛事、钢琴、网页设计及从兄弟学牌等关系；它没有被本次检索召回。这是分析时查看的参考信息，不能说模型当时已经知道。

结论：这是“部分召回成功 + 未利用可见线索 + 片段质量不足”的混合失败。适合做文档阅读和关系保持实验；不适合标成单一的错误候选锁定。

## 5. qid 776：没有明确候选也会打转

[完整轨迹](../../runs/v000_baseline/qid_776/20260917T090903.033709Z/trajectory.md)

19 次搜索没有命中标注的任何 gold/evidence 文档。模型在 shaman、1886、居住 35 年、期刊和 1940 年报告之间反复切换。

具体问题：

- 事件 31 将原题“early 1910s”擅自缩窄为 `1912`。1912 恰好与标注作者年份一致，但这个数值在当时不是由已见证据推出的；推理过程仍然不稳健。
- 多个 query 加上 `anthropologist`，这是模型的职业假设，不是题目直接给出的事实。
- 事件 51 重复事件 19 的 query；事件 75 重复事件 47 的 query，均重新返回相同内容。
- 多次宣称“换一个角度”，但没有沉淀此前尝试的结果，也没有明确下一次查询为何更可能区分目标。
- 最终由“这些搜索没有找到”推到“文档没有直接对应这些事实”。后者不能由一次有限检索证明。

离线标注路径是 Diamond Jenness → Graham Westbrook Rowley → 1940 年文章 The Dorset Culture of the Eastern Arctic。61556 中文章题名出现在约 1,723 字符处。注意：本次根本没有召回该文，因此这不是仅扩大 search 片段长度就能直接解决的已证实案例。

该例的主要方向是检索策略：保留题目原始范围、把额外假设标为可撤回、基于失败结果改变线索组合。没有相关文档时，强制打开百科泛文也未必有用。

## 6. qid 311：初始化后大量枚举，基本约束判断也失真

[完整轨迹](../../runs/v000_baseline/qid_311/20260917T090903.053907Z/trajectory.md)

这次没有复现前批次围绕 Los Lunnis 的固定候选搜索。六次 query 在英、西、法语的角色描述和 TV5 之间变化，但没有召回标注证据。

更突出的行为发生在可见 content 中：模型长篇列举国家、电视台、节目，反复否定，并把 `TF1` 标为不符合“三个字符、其中一个数字”。TF1 字面上就满足这个条件；这是可直接检查的推理错误，不需要引用外部知识。

事件 15 于是把 `TV5` 放进 query，未经证实的入口影响了检索。最终回复仍在大段枚举频道，其中多处判断自相矛盾，之后弃答。

本题输出 token 合计 11,678，只有 6 次搜索；问题并非工具次数多，而是模型用大量无依据的枚举代替证据判断。每轮都有新文档，也没有形成有效信息增益。

离线参考 14444 的开头就给出 Cocomiel/Cococinel、TF1、导演、两位编剧等信息，但本次没有召回它。因此需要分别测试初始线索选择与召回；不能只归因于“不 open”。

还需注意原题的世界杯计数口径可能存在时间/范围歧义。本轮没有独立核验这个条件，不把它作为硬性国家过滤规则。初始化时应保留这种歧义，而不是用模型记忆直接否定整个方向。

## 7. qid 1094：猜测球队限制搜索，长文档命中后没有阅读

[完整轨迹](../../runs/v000_baseline/qid_1094/20260917T090903.061270Z/trajectory.md)

事件 2 在搜索前猜测多个决赛及进球过程，最终把“born out of discord”暂定为 Inter Milan。第一次 query 直接包含 Inter Milan，尚未验证俱乐部起源关系。

事件 8 已返回 23800《2005 UEFA Champions League final》，但只有前 1600 字符，包含双方、比分和背景。后续模型继续在记忆中的球队和比赛之间猜测，没有 get_document。最终在 2001/2005 决赛间摇摆，并弃答。

本次应与 12 轮轨迹区分：不能照搬前次“围绕 2014 决赛”的描述。共同点是未证实的比赛假设占据搜索，且没有用已召回文档检查关系。

离线全文 23800 约 15,630 字符处写到加时赛初期 Pirlo 的射门；另一标注文档 73209 在 ET 6 处回顾 Pirlo 射门越过横梁。本地两份材料并未直接提供完整的“95 分钟 + 任意球执行者”原句：一份没有精确分钟，另一份还注明漏了一段解说。

因此有两层结论：模型错过了可推进判断的后文，这是明确的阅读机会；精确约束是否充分可证，仍有材料缺口，不能仅凭 gold 标签认定 verifier 必须通过。

## 8. qid 517：保留这个对照例，避免只从失败推出设计

[完整轨迹](../../runs/v000_baseline/qid_517/20260917T090903.064285Z/trajectory.md)

事件 2 先猜 Idris Elba，并生成未经证实的出生年份与影视经历。随后数次围绕该方向搜索仍没有支持。

关键转折是事件 23：query 变为 `actor played policeman in The Constant Gardener 2005`，不再绑定 Idris Elba。它返回 67431，片段中的家庭信息与题目高度相关。

事件 26 明确指出片段没有给出演员具体角色；事件 27 调用 get_document，事件 28 的完整文档包含 Policeman 1 的影视表格。模型在看到具体的信息缺口后，主动阅读并得到所需关系。这是我们希望保留的行为。

但本题只能记为答案实体正确：67431 正文是 1978 年出生，分类却是 1979 births，来源内部不一致。模型的生肖判断也前后不一致，最终把 1978 写成 Tiger。不能要求 verifier 无视来源冲突，也不能把实体正确扩展成所有解释正确。

该对照例支持一个具体假设：让模型识别“已命中文档中还缺哪一项关系”，可能比笼统要求多阅读更有效。单题不能证明因果收益。

## 9. 对原型设计的修正

### 阅读：应优先解决“可见内容是否适合检查关系”

5/6 题没有阅读调用，但不能统一强制 open。546、1094 有明显长文阅读机会；324 还有 HTML 噪声；311、776 首先需要改善召回。相关片段定位、可选深读、HTML 正文提取值得独立测试，保留原始来源和视图快照。不要先同时更换 embedding、索引和提示词，否则很难归因。

### Information Need：必须描述待判定的关系

好的需求示例：

- 546：哪份原始赛事记录支持这四场按顺序发生？Players Championship 是否只是猜测？
- 324：已看到 2008 女子赛事冠军，是否与 X 的赛事是同一项、相差两年？
- 517：这份演员文档是否把 2005 年角色明确列为 Policeman 1？

“继续核实候选”“再找更多证据”不够具体。本批次没有独立的 gap 机制，所以只能提出它可能有帮助，不能声称已经验证有效。

### Replan：检查不成立的前提，不只是改写 query

546 连续五轮无新增文档，是很明确的低成本触发信号；但 311 每轮都有新 docid，照样停滞。应结合当前待解决关系、已见证据与查询结果判断，文本差异或文档新颖性都只能作为代理。

### 停止：当前先区分弃答、无依据回答和证据充分回答

64 轮全部主动结束，没有观察到“验证已通过仍不提交”，当前也没有 verifier。扩大预算把此前部分强制终止变成了主动弃答。最终验证对于 546 可能阻止无依据答案，但不自动让 776 找到证据，更不能把所有弃答强行转换成答案。

Compact Memory 仍是待测假设。当前轨迹有重复自说自话，压缩可能减少这些干扰；本批次没有发生已记录的上下文溢出，也没有压缩对照，不能把失败归因于上下文长度本身。

## 10. 下一步优先实验

建议先做局部干预，不直接加入整套 harness：

1. **546 的同前缀深读/片段实验**：冻结已命中 84585 后的状态，比较原始前缀片段和查询相关片段；观察能否撤回未经证实的赛事假设。片段选择不能使用 gold 答案。
2. **324 的关系提示实验**：冻结第一次见到 85213 后的状态，只要求区分目标答案与 X，并考虑已有年份线索；不提示正确候选或年份计算结果。比较是否产生可验证的新关系。
3. **776 的停滞重规划实验**：冻结循环出现后的状态，要求检查额外加入的年份/职业假设，选择新的信息需求。与等额调用预算下的继续搜索比较。
4. **保留 517 为回归检查**：不能让新流程破坏模型已经能完成的“发现具体缺口 → 阅读 → 更换候选”。

所有这些题都已进入设计讨论，应视为开发诊断题。后续效果结论需要新的固定题集和重复运行。本次 12/64 两批是重新采样，前缀不同，无法用 1/6 对 1/6 证明提高预算没有作用。
