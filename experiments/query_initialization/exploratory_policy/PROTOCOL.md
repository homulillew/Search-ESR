# 探索原则提示词：两步 Search/Open 对照协议

本轮只检验一个轻量增量：在当前 Agent 提示词后添加三句探索原则，是否改善首搜及观察之后的下一步行动。独立 Selector、Compiler 均不接入，也不再为了过线调整这些模块。实验借鉴 AREX 的模型自主行动思路，不声称复现 AREX；不比较模型权重、远程搜索服务或完整 AREX 系统。

本协议在真实 API 请求前冻结。若实现与协议有差异，应在发起请求前修订并冻结；运行后的偏离单列披露，不根据结果修改采用标准。

## 对照条件

A 使用当前 Agent 的系统提示词与 Search/Open 工具描述。B 使用相同内容，只追加以下英文段落：

> Begin with a distinctive, independently searchable entry into the question; you do not need to cover every condition in the first search. You may omit conditions, but preserve the subjects, relationships, negation, and time scope of those you use, and treat unverified identities as hypotheses. After observing the results, choose the next search or open from what the returned text actually establishes and what remains unresolved.

运行时保存实际发送的完整系统提示词、工具 schema、请求参数和文件散列。B 是一个整体提示词处理，本轮不能区分其中三条原则各自的贡献。模型仍然自由决定具体语义；Harness 只约束实验预算、执行工具与记账。

两组都使用相同的受控运行条件：首个模型动作必须调用单个 Search；第二个模型动作允许单个 Search、单个 Open 或直接回答。因首搜被实验强制，本轮不评价默认 Agent 是否自发调用 Search，也不把 A 称为不受限制的原始完整运行。第一步的 `tool_choice` 固定为 `{"type":"function","function":{"name":"search"}}`，第二步为 `auto`；两步均设置 `parallel_tool_calls=false`。两组共有的预算提示说明首搜 top6、总计最多两次动作、第二步可 Search/Open/回答。第二步不强制 Open，不要求模型输出额外 state、gap、依据编号或解释字段。

## 样本与调度

复用 `selector_verbatim/selection_lock.json` 的二十题：719、520、605、760、519、854、1000、435、60、1249、71、1039、446、1035、1147、124、978、191、134、692。逐题核对原题散列，保持原文。每题两组各两次，共八十个独立会话；每个会话最多两次模型请求、两次工具执行。

这批题已经用于本地开发和审阅，明确属于开发对照，不称未见验证或泛化证明。既有题目表现、答案、人工选择和来源标注不得放入模型请求。按预先保存的调度交错组别与重复，API 和检索可并行；并行只改变调度，不改变单次输入、工具语义、模型参数或窗口策略。记录实际并发、延迟和资源配置，不在缺少顺序运行对照时声称加速倍数。

## 共同预算与失败处理

- 模型为现有 `qwen3.7-flash` OpenAI-compatible API；`thinking=false`、输出上限 1536 tokens，SDK 自动重试关闭。其余实际请求参数完整保存，两组一致。
- 首搜固定 `k=6`，每个返回窗口沿用现有 400-token 预算。第二步若 Search，仍为同样配置；若 Open，使用现有 before/after/around 行为及预算，不实现 `Open(focus)`；Open 原有预算为 1200 tokens，around 上限 2400 tokens。每次工具返回的标题与正文合计预算上限统一为 2400 tokens，全会话最多 4800 tokens，未用满不补。按现有 tokenizer 审计，其他元数据开销另报，不能为达上限偷偷截断正文。
- 查询上限 1024 个 embedding 输入 tokens，包含实际 prefix 和特殊 token。记录原始 query、实际计数、最终执行参数；不静默截断或改写。
- 两组用同一套实验工具 schema 固定单 Search 的 top6。若模型显式提交与固定预算不符的参数，不静默覆盖后继续；按协议失败记录。缺省参数应由共同 schema 清楚规定。
- 一次请求返回多个工具调用即为协议失败，不挑选第一个，不拆成多个预算外动作。非法 JSON、未知工具、非法引用、空 query、超预算、非完整停止、API 错误等均保存原始响应并记录状态，不 repair、不 fallback、不另补请求。
- 第二步若正常直接回答，视为合法停止。无需为得到最终答案增加第三次模型请求；第二次工具返回后即截断实验。两组实际工具次数因此可能不同，必须一起报告。

失败会话保留在全部八十个会话分母中。第二步失败不能抹去首步已经真实获得的依据；首步失败后的累计依据为零，行为项标为失败或不可评，不伪装成语义负例。传输故障和模型/协议错误分别报告，不用成功子集代替主结果。

## 保存与机械审计

保存每一步完整请求、assistant content（如有）、工具调用原文、解析参数、工具返回、模型用量、停止原因、执行时间、query token 数，以及实际送入下一请求的 messages。工具执行使用独立会话的来源版本和观察账本，保存 SearchAttempt、窗口引用、字符区间及新增/重复区间。

工程检查覆盖：两组唯一预定差异、题目锁定、请求与调度可重建、调用/预算上限、窗口与原文一致、引用可解析、第二步实际看见的信息边界、无隐式修复和静默裁剪。机械合法不等于语义正确。Open 能执行也不等于带来研究收益。

## 内容审阅与效用定义

这是代理辅助的内容审阅，不是独立人工金标准，不声称双盲或“未使用模型判断”。优先按题聚合去重来源和窗口后审阅，映射组别时仍可能识别 query 或既有案例；最终报告如实说明实际盲法限制。既有来源标注可以复核复用，但必须校验来源版本、原文摘录和当前窗口位置。所有新增返回窗口和文档都要筛查，不能只给已知案例计分。未审阅不得记成无效。

仅评估实际返回的来源池，不用 gold 反向检索扩充。全文中窗口外的段落可用于确认“这篇来源值得继续读”，必须记录全文查阅范围；不能将其借给模型的可见依据或行动依据。来源正例需有原文摘录、字符区间、与完整原题的关系，以及允许的中间判断或下一步行动。主题相似、裸候选名称和满足被挑选的容易关键词，不足以判正。

每次会话分别记录：

1. **首步有用来源**：top6 中是否至少一篇有明确原文支持原题相关的中间事实或值得继续阅读的关系。
2. **首步可见有用依据**：首步实际返回的原文标题（`title_span`）或正文是否已经展示该依据；标题也必须可映射原文，不借未返回区间。
3. **第二步之后累计有用来源与可见依据**：前两步的并集；不得把累计成功当作第二步的新增贡献。
4. **严格新增、与原题相关的依据**：第二步实际可见的原文标题或正文提供了第一步未展示的新事实或关系，对原题研究有价值。仅新字符、新 URL、改述同一事实、重复引用均不计。记忆中或其它会话中见过的内容不能补入本会话。
5. **下一动作的依据**：第二步 query、Open 或回答是否与原题/已见窗口相容。区分依赖观察推进、合理转向另一个题内入口、重复探索、无法解释、与已见材料冲突、协议失败。没有显式解释不自动判为无依据；不能仅从“发生在观察之后”断言模型实际利用了观察。若可见 content/调用不足以判断，则记录 `unobservable`；不推测内部推理。
6. **不支持的假设与关系误用**：记录未由题目或已见窗口支持的具体实体/属性、主体或关系置换、时间范围收窄、否定改变，以及把候选当成已确认事实。主动搜索待验证候选不自动判错，须区分假设探索和错误前提。
7. **机械重复与成本**：第二步重复 docid、完全相同窗口及正文重叠比例；原始/规范化 query 重复；Search/Open/回答比例，API 请求与 tokens、延迟、返回正文 tokens。重复来源和 Open 次数均不是单独的效用结论。

首步合法而第二步直接回答的会话，累计可见依据仍为首步已有内容，严格新增依据为零；回答中的新增主张不算新增检索证据。可以审阅其断言是否得到已见内容支持，但不评分最终答案正确率。两步实验不足以评价长期循环、提交能力或完整解题成功率。

## 汇总与轻量决策

每题每组先对两次重复取均值，再在二十题上汇总；同时公开逐题、逐次值。不能使用 best-of-two，也不能把四十次组内重复当成四十道独立题。报告首步、累计、严格新增依据三个阶段，来源和可见依据两个维度，以及可评/失败/审阅不足分母。第二步工具分布和实际观察 tokens 不同，要解释收益是否只是多取了一次大窗口，不能把每个新增字符都算成研究进展。

本轮只作采用简短提示词的工程决策，不设置统计显著性承诺。若 B 在累计可见依据或严格新增相关依据上有净改善，有至少一题两次重复都体现相应改善，且没有明显增加无依据关系断言、持续重复退化或成本，才考虑保留这三句提示词。来源率上升但可见依据和下一步行为没有改善，只能视为有限发现，不直接宣布成功。

若效果接近、改善与退化抵消，或优势主要来自单次偶然输出，则沿用当前提示词，结束本轮 Query 优化并进入观察管理设计。指标有冲突时解释取舍，不为过线追加案例规则、多 query 或额外模型调用。不要求这个节点解决 gap、候选纠正或整题所有约束，也不以本轮结果阻挡后续 Harness 工作。
