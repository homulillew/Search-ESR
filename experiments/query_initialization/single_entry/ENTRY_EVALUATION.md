# entry_v1 预先确定的对照与审阅规则

本规则在首批 entry_v1 API 请求前保存并随运行快照归档。

- 对照：现有 minimal 与五条通用原则的 entry_v1。两者都自由选择入口，评估整套策略，不能将差异归因于单句指令。
- 开发题：786、551、1072、1117、583、591、645、183。每组每题两次，32 次初始请求，修复另计。模型参数、输入、Search top6、每窗口标题与正文 400 tokens、总预算 2400 一致。
- 只做初始化和一次 Search，不执行后续 Agent 回答，不向生成模型输入答案或检索反馈。
- 不修改 Search–Open、原题编号、观察账本及 handoff 协议。默认策略不自动升级。

## 离线审阅

逐条对照完整原题、实际 query 与 basis_refs。允许省略完整条件、多个实体围绕同一搜索目的、原题支持的改写和角色描述；不要求覆盖全题。

分别记录：

1. 明确语义错误：主体或关系改变、错误日期归属、时间/否定/数量/比较范围改变、无依据具体化未知身份。原句和 query 引句一起保存。
2. 表达歧义：有多种合理读法时单列，不能直接计为确定错误。
3. 引用覆盖：依据缺引与事实编造分开；有效编号不能证明语义忠实。
4. 入口与结果：有用文档和实际窗口展示有用证据分开；历史已知正例仅为下界，未匹配文档不自动作为负例。
5. 执行与成本：全部尝试进入主统计，记录首次格式成功、修复、空输出、失败与 token。按题汇总两次重复，不把重复当独立题目。

亲属、参考文献、发表日期等历史错误是审阅用例，不逐条加入运行提示词。必要的新标注在结果出现后形成，需显式标为事后、与历史标注区分。

## 停止与扩大测试

开发接口检查全部通过，并审阅语义与入口。若 entry_v1 的同类明确语义错误在重复中持续出现（同题两次或跨题重复），先保留结果并停止扩大，不追加生产禁令或立即重跑掩盖失败。可重复的明确入口退化也阻止升级。

若没有阻断项，冻结提示词、代码、参数，再抽 20 道未用于本地调参的问题，两组各重复两次；修复另计。保存排除清单、种子和抽样结果。若据此调参，该批不再是留出测试。

无论格式通过还是已知文档命中，都不自动视为策略成功。没有可靠改善时保留现有默认；不要求首搜解决整题，也不要求所有合理入口都命中。
