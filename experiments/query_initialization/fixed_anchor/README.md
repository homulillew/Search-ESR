# 固定原题线索的 Query 表达诊断

已完成 [首批 35 次检索与完整轨迹](runs/20260918T064507.877529Z/README.md)。分析见 [固定线索对照报告](../../../全链路排查报告/Query固定线索表达对照与根因验证.md)。

本实验固定搜索对象及原题线索，区分关系改写、信息省略与检索匹配。独立于默认运行时和 v003 初始化器，不修改 Search–Open。

## 预先确定的三种查询

|组|查询来源|每题执行数|目的|
|---|---|---:|---|
|full|人工依据原题写出的完整关系表达|1|查看保留关系的输入能否取得入口|
|delete|从 full 严格删除一整段预定关系或辅助信息|1|避免把删除条件误做成改写条件，观察整段省略的结果|
|model|强模型根据相同原题线索生成紧凑 query|3|检查关系是否改变、信息是否省略，以及重复波动|

7 道已知开发题：1117、551、645、786、1072、583、591。共 21 次初始 API 请求、35 次 Search；格式修复若发生另计。所有控制查询、删除范围、问题和假设在 cases.json 中运行前固定。full/delete 是人工诊断干预，不是待部署策略，也不计作模型生成成功。

模型仅接收完整原题（用于指代上下文）、固定搜索对象、精确原题线索；不会看到手工 full/delete 查询、标准答案、其他重复或检索结果。选定对象固定，但语义忠实性仍需审阅。query 最多 512 Unicode 字符，不强制词数；输出上限 1536 tokens，thinking 沿用当前配置，SDK 不自动重试，最多一次格式修复。

每次 Search 均为 top6，标题与正文每窗口最多 400 tokens，总上限 2400；四线程 API 与单线程共享检索器。相同问题的三个模型重复不是三个独立题目。控制组每题只执行一次，不能把总体命中次数直接与三倍尝试的 model 组比较。

## 运行与复核

从仓库根目录执行。run 会产生真实 API 请求，凭据沿用现有环境。

```bash
python -m experiments.query_initialization.fixed_anchor.run
python -m experiments.query_initialization.fixed_anchor.audit <run_directory>
python -m pytest -q experiments/query_initialization/fixed_anchor/test_fixed_anchor.py
```

运行前保存 cases、schedule、源码和提示词哈希，以及旧实验的正例参考标注快照；完成后保存每次 SDK 请求响应、查询、原始窗口、观察账本和可读轨迹。

机械审计检查控制查询未改变、删除范围一致、模型输入不含控制答案、查询生成先于检索、来源/引用/预算及账本一致。参考片段计数只是已有正例复核：qid645、qid786 没有对应旧正例，未匹配窗口不是负例。它不能替代新结果的完整相关性标注。

这个模型表达提示词比自由初始化更严格：要求保持选定线索的实质内容，禁止自行换入口。与以前运行的差异同时包括固定对象、显式线索及任务指令；即便改善，也不能单独断言某一个因素导致改善。
