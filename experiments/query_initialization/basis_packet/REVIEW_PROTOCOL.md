# Fixed BasisPacket 第一阶段审阅协议

本协议在本轮 API 请求前制定，与 cases、提示词和源码一起快照。用途是诊断输入隔离与查询表达；六题均为开发案例，不能作为独立泛化测试。不会根据结果改 packet、改标尺或把新增正例说成预注册正例。

## 1. 对照与审阅范围

A 原文直送每题一次；B 保守编译、C packet 内完整表达、D 与 C 相同表达指令但提供完整原题，各重复三次。C/D 的 system prompt 必须相同。A 不是三个独立样本；B/C/D 的重复属于同一道题，结果按题归纳。

Compiler 不输出 refs，Harness 记录实际输入来源。B/C 的输入来源是 packet，D 的输入来源包含完整原题。因此“不需要模型回填引用”是工程性质，不能直接折算为查询语义正确。D 引入未选但原题已有的事实属于越过选定依据的使用；不是凭空捏造，且不能被误报为请求泄漏。

B 允许省略完整条件；C/D 要求保留选定片段的实质条件。审阅同时记录保留与省略，不用单一错误率掩盖策略差别。省略和修改要分开：整个不使用时间条件可以是 B 的合法选择，将区间变成某一年则是改变条件。删去必要的主体或关系造成含混，单独记 context_loss 或 ambiguous。

## 3. 每条 query 的语义记录

每条保存 session、原始 query、诊断条件状态及引句说明。状态至少区分 retained / omitted / ambiguous / mutated。异常可以多标签，主统计按出现异常的尝试数计，不累计标签冒充多个失败。

- `subject_mutation`：属性附着到另一个人物、作品、论文或属种层级。
- `relation_mutation`：亲属、参演、导演、参考文献、因果或同名关系改变。
- `temporal_mutation`：区间缩窄、截止日期改为事件日期、日期被移动到另一事件。
- `quantity_negation_mutation`：数量、比较、否定或含端点条件改变。
- `outside_packet_question_fact`：使用未选但完整原题支持的事实。B/C 再记 outside_actual_input；D 实际输入支持但越过选定依据。
- `unsupported_specific_fact`：原题和 packet 都不支持的具体身份、关系或事实；与上述类别分开。
- `context_loss` / `ambiguous`：表达无法可靠确定原关系，但不足以断言模型明确作出相反陈述。
- `condition_omitted`：完整省略，注明 B 允许或 C/D 未遵守完整表达要求。
- `target_change`：从可选依据对应的对象/来源转向另一对象。仅凭 refs 不能唯一固定意图，因此记录变化及检索影响，不一律当作错误。

明确失真须给出原文与 query 的对应片段。关键词并置如 “retired 2020” 如仍有两种合理解读，记 ambiguous；明确 “retired in 2020” 才是时间改变。不将所有短语自动解读为最坏关系，也不因为检索碰巧命中就豁免事实改变。

不发送标准答案给任何生成/修复请求。离线审阅如果使用答案辅助定位，须标明其用途；答案不能替代文档证据。实际人工审阅若能看见组别，应说明未盲审，不宣称双盲。

## 4. 工程审计

1. 快照哈希、question 单元切片、来源版本和 packet refs 可确定性复核；packet 文本必须来自保存的原题，不接受人工改写。
2. B/C 初始与修复消息均不含完整原题、编号、其他题目、Selector 历史或未选文本；C/D 除完整 question_context 外使用同一输入与同一 system prompt。
3. A 无生成 API；每条查询最多一次 Search；生成和修复先于 Search；没有依据搜索结果改变 query。
4. 查询预算使用相同本地 embedding tokenizer 与前缀；无静默截断；每次 top6、每窗口标题加正文不超过 400 tokens、总量不超过 2400。
5. window 正文与 SQLite 原文区间、document_sha256、标题区间、window_ref 一致，观察账本与事件流一致；恢复后的 Open 引用检查只作接口验证，不纳入此次 Search 可见证据。
6. 无效、API 失败、弃答、修复均记入全部计划尝试的分母。正常执行不等于语义正确。

## 5. 检索效用与正例池

冻结 `reference_annotations.json` 中已有正例。当前只覆盖六题中的四题：1117、551、645、1072。786 与 1172 无已知正例，不能将它们的零命中解释成检索失败。

已有池来自 `fixed_anchor/runs/20260918T064507.877529Z/reference_annotations.json` 与该轮 supplemental_q645.json。qid1072 的 museum_year/doc21375 对应完整原题的未选线索，标为 outside_selected_basis，与 selected_basis 命中分开。qid1117 的 journal_owner 只是入口线索，不证明目标人物或最终答案；qid645 的第一参考文献或研究目的也不是全部约束的证明。

按题汇总本轮所有组的文档池；新增有用来源需要本地原文引句、精确区间和文档摘要。注明 post-run pooled annotation，保存审阅范围。尽量隐去来源所属组别和排名；若不能做到，明确未盲审。未标注来源是 unassessed，不是 irrelevant。

每个尝试分开报告：

- 已核实 selected_basis 来源是否进入 top6、其中最好排名；以及全题其他有用入口的命中。
- 已标注依据是否在实际返回窗口可见；标题与正文的原始区间分别判定，不能拼接后假造相邻原文。
- 有用文档已命中而标注依据不可见，区别于未命中文档。标注是有限正例，不能排除窗口内另有未标注的有用证据。

依据可见逻辑复用旧审计的 proof_alternatives：任一 alternative 内每一 proof 至少有一次原文出现完全落入实际标题或正文区间；不是仅凭文档 ID 或关键词命中。正例文档排名与窗口可见性是不同指标。

旧池与新增池结果分别展示。若合并结果也展示，标明是局部已核实正例下界，不能称为全库召回率、最终答案正确率或端到端完成率。

## 6. 决策与报告

报告先列工程有效性、全部尝试状态与 API 实际用量，再按 qid 展示四组表达差异、条件保留情况和已核实来源/窗口。成本包含修复；人工 packet 成本不等于自动 Selector 系统的成本。

C/D 的差别用于观察完整原题暴露的影响；B/C 是整个表达策略的比较，不能归因到单条提示词。A/B 是否需要 Compiler 必须同时看忠实度与检索效用，不能仅以无生成错误或更短 query 决定。

若 A 已提供足够入口且 B 无可重复增益，优先保留原文路径。若 B 能稳定改善局部来源或可见依据且关系保持，可讨论新 packet 验证。混合结果如实列出，不强行选赢家。六个开发题不能支持冻结泛化行为或直接切换默认初始化器；自动 Selector 留在下一阶段，不在同一批实验中混入新的选择变量。
