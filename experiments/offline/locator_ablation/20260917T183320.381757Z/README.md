# 文内定位的两组独立消融

固定真实轨迹的 75 个 query–文档对、召回顺序、标题与窗口构造，保持每篇标题加正文不超过 400 tokens。没有新增在线轨迹、文档召回或标准答案输入。

## 方案

A 为当前原方案：BM25 选择第一父块，在该块内部选择锚点，再从完整文档展开。

B_pool3 保留前三个正分父块，将其中句子/行合并为候选，精确相同原文范围去重，再统一计算 BM25 并选一个锚点。不是返回三个窗口，最终仍只展示一个窗口。候选范围与局部 BM25 统计同时变化，不能将效果仅归因于范围扩大。

C_scores 保留 A 的两阶段 top-1 流程，但将数字连字符对正规化为一个词项，并移除该数字对拆出的单独数字。4-3 与 4–3 归一，4–3 与 0–3 区分；数字次序保留。它是词法原型，会把年份区间等也视为数字对，不具备体育比分语义，不适合未经检查直接上线。

## 总体结果

| 方案 | 改变窗口数 / 75 | 标题＋正文 tokens |
| --- | ---: | ---: |
| A | 0 | 25,776 |
| B_pool3 | 16 | 25,758 |
| C_scores | 8 | 25,849 |

A 完全复现原观察。所有新窗口通过原文一致性、400-token 上限断言。两项词法测试通过，验证横线归一、顺序保留、年份单值保留及错误数字组合的区分。统计中的窗口变化不是语义改善率。

## 517：扩大候选使角色表进入竞争

第五次搜索 `Peter King actor The Constant Gardener role policeman`，文档 67431，A 返回人物简介 [0,1299)。B 的锚点变为 `The Constant Gardener | Policeman 1` 表格行，窗口为 [1299,2601)，保留表头和角色记录；文档标题仍独立提供 Peter Nzioki 身份。

这为“第一父块过早截断定位候选”提供了实际支持。无需为 policeman 手工加权，扩大候选并在新的候选集合中排序就能在这个实例中定位角色。C 对本查询不产生变化。

但该结果来自已用于设计的案例，不代表其他角色 query 一定改善。

## 扩大候选也扩大元信息竞争

546 第二次搜索在 60119 中，B 选中的锚点为 `next: 2023`。原文标题明确是 2022 Masters，字段含义是下一届年份，而非当前赛事年份。另一个文档 55362 的锚点为 `2023 =39`，同样不能直接表达查询要求的比赛关系。

这揭示现有局部排序把标题、元信息字段、论坛内容和正文放在同一竞争集合。候选扩大后，短而集中匹配的字段可能更容易胜出。短字段缺乏上下文并不总会被 BM25 低分处理。

这些是定位质量的反例，不根据它们断言全部新窗口都比旧窗口更差。需要保留字段所属结构，检查它是否只是辅助定位信息，而不是独立的正文阅读锚点。

## 546：比分词法改善仍不等于关系满足

第一次搜索的 4975，C 不再仅依赖独立数字匹配，窗口移动至同时包含 4–0、4–3 的比赛结果附近。但这两个比分属于 2010 和 2013 年记录，不属于 query 中的 2023。查询词分散在邻近不同记录时，词袋排序仍可能把它们累加为相关。

38231 在 C 下完全不变，仍位于旧赛季。B 则移动到另一段 2016/2017 内容，也没有满足 2023 条件。

因此需要区分三个层次：数字表达是否保留、是否匹配 query 词项、匹配词是否属于同一条事实或记录。本轮 C 只触及第一层，不能宣布时间与比赛链定位已解决。

## 优化判断

1. 扩大父块候选是值得继续验证的方向，517 给出了具体正例。暂不直接替换当前在线排序。
2. 下一步先固定 B 的候选范围，单独比较“结构字段能否独立成为锚点”。保留字段作为标题或周边上下文，不应简单删除所有包含年份的字段。
3. 比分正规化另行保留为词法实验。应补充年份区间、日期、反向比分和不同比赛记录的检查，避免用新数字规则引入新误匹配。
4. 不立即加入年份硬过滤或针对特定 query 的权重。年份可能写在上级标题，硬过滤句子会误删相关记录。

后续需要用未参与设计的固定 query–文档对复核。当前没有有效率、准确率或长链路收益结论，不改动 Open、研究状态或停止策略。
