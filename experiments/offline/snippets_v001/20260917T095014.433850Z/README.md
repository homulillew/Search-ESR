# 文档内片段定位 v001：离线对照结果

已完成 546、1094、517 的全部真实 search 对照：27 次搜索、135 个文档返回条目、59 篇不同文档。没有调用大模型 API，没有重建向量索引，没有更改在线 Agent。数据来自 64 轮批次 `20260917T090903.022551Z`。

## 方法

- 冻结原始 query、top-k 文档及顺序、文档分数。
- A：按本地 Qwen3-Embedding-8B tokenizer 截取文档开头，最多 400 tokens。
- B：全文切成至多 400 tokens 的原文片段；优先段落边界，其次换行，超长单行才硬切。仅在换行边界保留约最多 50 tokens 重叠。
- 对每篇文档的候选片段独立使用 BM25（k1=1.5、b=0.75），返回一个最高分片段。重复 query 词项不累加；同分选靠前片段。
- 分词为小写英文/数字词项及单个汉字；未加入停用词、词干、同义词、短语/实体/日期约束，未使用 gold。
- 无词项匹配时回退开头。原始 HTML 单独标记并回退开头，第一版不清洗 HTML。本次这些回退均未触发。
- 每个片段带 docid、来源 URL、原文字段范围、原文哈希与稳定 chunk_id。返回原文，不生成摘要。工具外壳不计入文本 token 预算。

“等预算”是相同上限，不是两边强制填满。B 为保留段落边界可能更短；A/B 实际 token 均记录。历史版本按 1600 字符截断，与 A 不完全相同，因此这不是原 rollout 的严格重放，也不是 Agent 答题效果实验。

## 发现

### 546：能交付后文，但词面排序不能判断候选关系

第 5 次搜索的 query 为 `"Mark Selby" 2023 Players Championship snooker results`。

- 在 55516 中，B 从位置 34,885 选出 Selby 2023 年赛事经历，提供比开头一般简介更具体的资料。但是这一段并没有确证 query 猜测的 Players Championship。
- 在 84585 中，B 从位置 52,080 选出 Mark Williams 对 Ding Junhui 的赛果。它虽然恰好包含与标准答案相关的线索，但得分来自 `mark`、`2023`，没有匹配 `selby`。不能把这个结果当成可靠识别正确实体的证据。
- 第 4 次搜索针对 Bingham 时，片段开头只是上一场比赛的尾部，后面接另一场比赛。按换行切分保住了单行，却没有保证比赛记录完整。

### 1094：词面匹配会选错具体事件

23800 在第 2、6 次搜索选中位置 16,139 的后文，含 `free`、`kick`、`minute`，内容却是 117 分钟及加时末尾的情节，不是查询中的 95 分钟。片段自身保留了时间，不能将它解释成符合全部条件。

同一文档在第 3、7、8、9、10 次搜索又选回开头，主要匹配赛事名称。说明仅 BM25 最高分不稳定地对应模型真正缺少的事件。

### 517：角色信息更可见，但人物身份与家庭信息被挤掉

第 6 次搜索 `actor played policeman in The Constant Gardener 2005` 在 67431 中选中位置 1,426 的片段，包含 Policeman 1 和 2013 影视角色表格。这部分此前需要 get_document 才看到。

但所选片段没有开头完整姓名、父母职业等信息；当前返回外壳只有 docid/URL，标题也未单独保留。原轨迹正是依靠这些家庭信息识别候选后才阅读，因此不能断言替换后还能保持成功。第 7 次 query 选回简介，只是冻结轨迹的结果，不能假定新 Agent 一定会发出同一条 query。

## 当前结论与下一步

第一版证明了无需全库重建索引就能定位后文，也暴露了单个关键词片段的不足。建议先不接入在线 Search。

下一小步优先处理证据完整性：文档标题/身份上下文、比赛记录与表格边界，明确同样的总 token 上限如何分配。暂不同时增加 embedding、reranker、replan。否则无法判断改善来自哪里。

三项有意义的测试已通过：分块原文覆盖、位置/ID/预算约束；定位后文与无匹配回退；可容纳表格行不被切断。后者不等同整张表或一场比赛语义完整。135 个对照项均检查选中片段与 SQLite 原文切片一致，且两臂不超 token 上限；同时检查原 1600 字符视图与当前语料一致。
