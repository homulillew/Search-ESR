# v003：单个 query 下的单块与多块对照

本轮只评价当前 query 的信息需求，不要求 Search 覆盖原题全部约束。身份、表头和指代仅在影响当前片段理解时纳入评价。沿用历史 query，没有另行构造严格的单约束题集。

## 设计

固定 v001 的 27 次搜索、135 条返回项、59 篇去重文档、400-token 分块和 BM25 排序。A 返回原 top-1；B 保留同一 top-1，再添加最高分、得分大于零且与第一块没有字符重叠的候选。没有合格候选时只返回一块。全部 top-1 ID 和分数均与 v001 校验一致。

本轮采用增加预算的第一步实验：A 每篇最多 400 tokens，B 最多 800 tokens，未做固定总预算的比较。每块独立保留 docid、位置、分数、原文与排名，不把不连续片段拼成连续原文。没有调用大模型、重新召回或使用标准答案。

## 结果

| qid | 返回项 | 获得第二块 | A 文本 tokens | B 文本 tokens |
| --- | ---: | ---: | ---: | ---: |
| 546 | 50 | 45 | 16,818 | 31,887 |
| 1094 | 50 | 36 | 14,711 | 27,022 |
| 517 | 35 | 24 | 11,185 | 19,224 |
| 合计 | 135 | 105 | 42,714 | 78,133 |

105/135 条返回增加了第二块，文本总量增加约 82.9%。返回数量与 token 数不是相关性指标；JSON 和元信息开销未计入。

对 240 个实际输出片段调用了现有 `BCPlusTools.get_document`，按保存的位置读取并逐字符校验，全部一致。该检查证明位置能够衔接现有 Open，不代表模型会主动打开、选择正确读取范围或完成推理。本轮没有在线 Agent 轨迹。

## 单个信息需求下的案例

### 1094：第二块提供赛事身份及不匹配信号

第二次搜索 `Champions League final 95th minute free kick` 的 23800，第一块只有加时末尾和任意球描述，第二块补出了文首的 2005 年决赛、球队与赛事日期。这有助于判断描述属于哪场比赛，但仍未证明 95 分钟的任意球。

第六次搜索在 query 中指定了 2008 年，同一第二块则提供明确的年份不匹配信号。这是当前 query 内部的核查价值，与覆盖原题其他约束无关。能否由此促使模型纠偏，尚未通过在线实验验证。

### 546：第二块也可能只有词项相关性

第五次搜索 `"Mark Selby" 2023 Players Championship snooker results`，55516 的第二块主要是外部链接和人物分类，没有补充所要求的赛事结果。增加块数会把排序中的噪声一并带入上下文。

同次搜索的 84585 增加了 Selby 的半决赛统计，比第一块的其他选手记录更贴近当前候选，但所选片段不足以确认它属于 query 指定的 Players Championship。不能因为出现 Selby 和比分就认定该信息需求得到满足。

### 517：严格排除字符重叠误删有用候选

第六次搜索询问 `actor played policeman in The Constant Gardener 2005`。67431 的第一块 [1426, 2634) 包含角色表，第二名 [0, 1427) 包含人物姓名、演员身份及电影介绍。两块只在一个换行字符上重叠，第二名仍被严格规则排除；第三块无匹配词，最终只返回第一块。

该例暴露的是去重规则缺陷：一个换行重叠不构成有意义的内容重复，却阻止身份信息与角色记录共同呈现。家庭背景不是本次 query 的评价要求。后续可以先单独比较允许纯空白重叠的规则，再考虑一般的重叠裁剪或合并，保留原文位置和预算约束。

## 判断

多块返回在个别实例中增加了当前 query 所需的文档身份或反证信息，但也增加了无关分类内容，且当前去重过严。本轮人工审查了五个特定条目，不能将案例结果推算为 135 条返回的整体有效率，也不能声称最终答案准确率提高。

下一小步先修正并独立验证纯空白重叠的处理，再考虑固定总预算对照。当前仍不替换在线 Search，也不引入问题拆分、gap 或其他研究控制模块。

## 复核

新增测试 `python -m pytest tests/test_snippet_multiblock.py -q`：2 项通过，覆盖 top-1 一致、得分一致、重叠跳过、无匹配回退。运行中的断言额外覆盖全部 135 条对照和 240 个 Open 原文读取。
