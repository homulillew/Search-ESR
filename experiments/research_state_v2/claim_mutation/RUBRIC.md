Routing positive means the new W could materially change a registered Claim's status, including evidence that only partially bears on a conjunction. Primary routing recall uses all valid Claim labels plus the two routing-only qid-186 Claims. A ref is valid only if observed in that packet, and N requires each selected Claim to cite the new W. Duplicate and unknown IDs invalidate the arm response. A routing false positive is selection of an unaffected Claim.

Mutation units match historical E1: existing Claim status, statement or refs-only change; new Claim; Gap status/content change. Required status changes must match reviewer status and cite the new W. Only valid, required units are correct. New Claims and unrelated mutations are churn. The two qid-186 malformed Claim status changes and their dependent gap changes are reported but excluded from primary numerator and denominator. A verifier error leaves the previous status unchanged and counts as a miss where a change is required. Gap `all_supported` closes exactly when all linked existing Claims are supported; it reopens when the condition no longer holds. Broad gaps do not close from one local Claim. NoGain is T4, at-risk false closure is T3/T4/T7. T7's ambiguous title equivalence is reported separately.

Each arm receives one fresh first-stage call per case, in deterministic SHA-256 case order. Arm order alternates N/W. W uses the exact historical updater prompt, schema, triggered verifier and reject/retain commit. N uses the frozen router prompt and one verifier call per routed Claim. No retries or selective replacement; failures remain as null outcomes. This is a paired 41-case, 12-qid diagnostic with correlated sibling packets, not an independent population estimate.
