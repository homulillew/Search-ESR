# V1 natural-Finding Direct versus Verify

The 52 single-pass Reader outcomes and all 55 natural Findings are immutable. `ANNOTATIONS.json` is a single-reviewer prefix-only audit frozen before verifier calls. D commits every natural Finding with a Harness-assigned C# and the current W#; there are zero extra LLM calls. V sends each exact Finding and the exact current Observation to DeepSeek once, with no Question, Gap, Claims, search history or Actor text. The only output is `{"supported": true|false}`. Invalid/failed output is a rejection; no retry, repair or best-of.

Primary truth dimensions remain separate. Source precision tests the W support relation. Full Claim precision additionally requires Gap relevance and novelty, which this Question/Gap-blind verifier cannot assess. D/V supported recall and unsupported false promotions/rejections use the same 55 frozen candidates. Added calls, token usage, latency and cache telemetry are reported.

Decision A: D source precision ≥97% and fewer than five natural unsupported Findings makes Verify necessity unproven; prefer D if full Claim precision is also deployable. Decision B: when D has ≥5 unsupported Findings, V must remove ≥60% of those with supported recall ≥95%. Decision C: V supported recall <90% forbids deployment even if precision rises. For cases between A and B, report an inconclusive mechanism result; no policy is assumed deployable for R1 unless source precision ≥97%, full Claim precision ≥95%, and supported recall ≥95%. These additional R1 admission targets prevent an untested off-Gap Claim stream from entering integration. No threshold is revised after Verify calls.
