### 1.2 四条具有区分力的真实 bad case

**517/C/r2：错误备忘与提前作答叠加。** Reviewer 的decision_effect允许把policeman放宽为宽泛角色，引用只涉及导演/作品，没有建立候选的家庭和角色关系；Actor随后无新工具观察就输出Idris，并在正文承认2013关系不匹配后仍为题目找“混淆”解释。next_need非null、tools仍可用，因此不是代码将null需求解释为完成。直接归因是来源归属和条件保留失效，叠加Actor证据不足时仍提交；不能只靠强化服从解决。

**776/B/r2：合理提醒确实可以被忽略。** Reviewer明确说anthropologist/folklorist职业假设无支持、人物和报告未确定，Actor却再次断言目标期刊，并提出 `"mistaken for a shaman" 1915 anthropologist`。这里备忘含普通语言提醒，即使补引用索引，也不能保证改正下游。应把它保留为独立的需求到动作诊断。使用未验证职业作为一次探索假设本身不必然错误；问题在重复已尝试路线、没有说明新分岔，且将假设重新确定化。

**546/C/r2：要修订的是关系，不一定是整个人选。** Reviewer把“Selby在Players Championship不符合序列”写成必须排除Selby。原题没有指定该赛事，故不匹配可以反驳 `人选×赛事` 的绑定，却不必排除人选在其他赛事的可能性。这是方案/推理层的作用域问题，不是JSON格式错误。后续State应允许上游关系撤回，而不是只存一个candidate字段。

**776/C/r1：截断与需求失败必须分开。** 原响应列出大量basis_refs，在512token处停于未闭合JSON。实际Actor精确回退原请求，不能把其重复Query标为“正确gap没有驱动Actor”。当前回退实现符合冻结方案。下一轮不同时升额度或自动修复；来源合同要求引用实际支持保留断言的依据，若因此缩短引用列表，只能算该合同的整体效果。

517的原历史轨迹后来能纠偏，但最新E0两个A仍然保留1975过滤。因此它是“历史存在恢复行为的病例”，不是本轮稳定成功基线。C/r2可被诊断为提前无支持提交，但不能描述成把本轮一个正确答案破坏了。

## 2. “实现是否标准”应拆成三个层次

没有一个通用 Agent Harness 标准能自动保证研究正确。本次检查三个可以明确约定的层次：

| 层次 | 应验证的合同 | 不能由此推出 |
|---|---|---|
| API/工具协议 | 消息角色、工具调用 ID 配对、完整批次、完成原因、预算 | 模型选对了动作 |
| 实验与数据交接 | Actor 实际收到固定前缀；引用可定位；提示词/配置/版本冻结；失败保留 | 引文支持了命题，或 gap 有因果收益 |
| 研究语义 | 主体、时间、关系和原题条件得到材料支持；未知/反证/冲突不混淆 | 单次通过能代表 BC+ 泛化能力 |

OpenAI 官方 function calling 文档把工具调用描述为应用与模型间的多步交互：应用需要处理模型提出的调用并把结果交回；这不意味着任意兼容服务都遵守同样的 `finish_reason`。参考：[官方文档](https://developers.openai.com/api/docs/guides/function-calling)。本仓库旧 Agent 对有工具调用但返回 `stop` 的响应拒绝执行，E0 已把动作意图与旧运行时兼容性分别记录，本次保留该行为，未静默规范化服务端响应。

旧 E0 的合理基础包括：固定真实 request、完整工具批次校验、窗口/观察引用只来自已见材料、A 原请求深拷贝、B/C 使用同一模型和审查预算、无效审查回退、保留失败分母、不执行新工具。本次是在这个基础上修复合同缺口，没有引入新的 Agent 框架。

## 3. 五个已复现的实现缺口与修复

以下全部是合成故障注入，不是新增模型 bad case。

### 3.1 Reviewer 到 Actor 的引用交接不完整

旧 Reviewer 能看到 `event:<seq>:doc:<docid>` 到 `message_index/path` 的索引，Actor 却只收到审查文本。旧工具消息不包含事件 seq，Actor 虽可根据 docid 猜测，却没有足够信息可靠定位某次具体观察。

新 `indexed_json_v1` 交接把 `review_text` 和同一份 `reference_index` 一起交给 Actor。索引先机械解析到真实 tool 消息，不读语料库或未见全文；原題引用也不能重绑定。B/C 使用相同索引和包装，不注入选点说明或标准答案。原三份提示词不变，新包装位于 `prompts/memo_indexed.txt`。

该索引包装保留为独立可选模式，默认和本次E0.1继续用legacy_text，不与来源提示词一起启用。这是**显式的输入设计变化**，会增加上下文和影响注意力，不能声称只是日志修复或已提高搜索准确率。保留 `--memo-mode legacy_text`，可单独比较交接方式；同一正式批次不能混用。JSON 包装只明确数据边界，不保证消除 prompt injection 或备忘锚定。

### 3.2 打印过计划，不等于执行被该计划约束

旧代码允许先 plan 为 512-token 审查、再 execute 为 1024 而不拒绝，计划内容没有成为执行前置条件。

新计划保存 `plan_sha256`，绑定准备清单、实际前缀哈希、模型覆盖、审查额度、重试数、调度、交接模式、提示词和实现源码哈希。正式 CLI 必须提供 `--plan-file` 和 `--expected-base-url`；变化在首次调用前拒绝。执行使用同一份已验证的内存快照，不再先计划一次、随后重新读取另一份准备数据。

`plan_approved` 仅表示执行内容匹配提供的计划文件，不是密码学签名，也不能证明人已经完成科学审查。同名远端模型也可能被提供商更新，故保留完整响应和用量，不承诺位级重现。

### 3.3 审阅导出检查了 checkpoint，却未核对实际 Actor request

旧导出在模拟篡改 Actor 的题目后仍报告零导出错误。只核对 sample_id 和 checkpoint 哈希不足以证明模型实际收到的是这个前缀。

带e0_audit_v1版本标记的新运行导出重建预期 Reviewer/Actor 请求，核对分支请求与逐事件日志、备忘是否实际注入、响应及分类是否一致；冻结提示词或运行设置变化也报错。completed 结果缺失日志不能通过。原始输出仍保留供审计，但完整性失败不进入“模型语义错误”统计。

### 3.4 破损日志尾部可以让总结再次崩溃

旧 summarize 对每行直接 `json.loads`，进程中断造成半行时会抛 JSONDecodeError，遮盖已完成调用和分母。

新读取器保留连续可解析前缀，遇到破损 UTF-8/JSON、重复序号或中段损坏停止并标记，而非越过损坏继续拼接。JSON 检查点原子替换并 fsync；事件落盘也 fsync。损坏后未知的成本明确标记，不能当作零。文件系统或机器故障仍可能造成无法恢复的尾部，不声称绝对无损。

### 3.5 已记录 Reviewer 响应可能在导出时丢失

旧流程先校验后赋值；若校验阶段中断，原始响应存在 events，但 result.review 为 null。导出优先使用 result 文件，不恢复已支付的审查响应。

新流程在校验前保存响应引用，并支持从日志恢复缺失阶段。没有实际完成的校验标为 `unvalidated_partial`，不补造 valid，也不算成 Actor 已使用需求。局部校验或适配器异常标为 `harness_error`，API 错误和模型输出无效分开记录。

附带补齐：按 arm 汇总全部分母、实际调用、失败/回退、用量与耗时；技术失败返回非零退出码；生成不含分支答案的 `prefix_cards.jsonl`，供先写合理动作清单再看输出。0 退出码仅表示机械完成，不表示答对。

## 4. 历史 bad case 的链路归因

主要材料：[64轮真实轨迹分析](../../batches/20260917T090903.022551Z/bad_case分析.md)。原文窗口范围必须按实际 tool 消息确定，不能把事后全文当成模型已读。

| 病例 | 可以确认的现象 | 更直接的解释与干预位置 | 尚不能确认 |
|---|---|---|---|
| 546 | 赛事/候选假设进入 Query；一般统计被当成比赛链支持；最终补全未经观察建立的对阵 | 旧前缀存在呈现不足；同时有未证实关系固化、支持范围扩大。检查赛事绑定与连续比赛关系，不只改候选名 | 当前 Search/Open 下是否仍同样失败；更强模型是否必然解决 |
| 776 | 没有稳定候选也循环；年份范围和职业被额外缩窄 | 搜索路线依赖未经证实过滤，且没有从失败结果修订过滤。需求应回查原题范围，不能只写“证明候选” | 是 gap 描述不好、Actor 忽略需求，还是检索确实困难：原轨迹没有独立 gap 节点 |
| 324 | 答案端名称出现，但中间实体—赛事—年份链未建立；原题语义被改写 | 关系保持与局部解释修订问题，叠加召回/片段缺口。允许反向检查答案端，但不能直接输出见到的姓名 | 名称出现是否意味着可答：显然还缺关键关联 |
| 517 | 能解除初始人物绑定、沿角色取证并主动阅读 | 说明同一模型至少在该状态具备纠偏行为；必须保留为不被干预破坏的对照 | 整题解释完全正确：材料内出生年份冲突、附加说明仍有问题 |

546 的[实际终答事件 seq42](../../runs/v000_baseline/qid_546/20260917T090903.079976Z/events.jsonl)直接显示“verification”中夹杂对失利对手的摇摆，最后又未经新工具观察将其写为确定答案。这是可观察的证据约束失效，不是仅由最终实体错误倒推。

### 4.1 Harness 设计、方案设计与模型能力并不互斥

旧运行时提供工具循环和预算，但没有语义证据账本、关系撤回或提交审核。这是能力范围，不应把每次错误都叫代码 bug。方案层如果只问“还缺什么来证明 A”，会鼓励确认式取证；若把“无新 docid”当无进展，或把“无 gap”当充分证明，也会误判。

模型确实出现了读漏、限定改变和无依据补全等行为错误。但有限病例不足以证明能力上限：输入缺口、交接缺口和控制缺失都尚未排除。先修合同，再固定证据和提示做同模型重复；必要时另立“只替换 Reviewer”或“只替换 Actor”的模型比较，不同时换模型、证据和预算。

### 4.2 不能用这批数据诊断“充分仍不提交”

该旧批次六题都自然结束，包含弃答和错误回答。自然弃答不是 API 不提交；命中参考文档不是窗口已建立全部关系。用户在其他 rollout 观察到的拖延需要对应的新前缀。停止诊断应在同一已见材料下做禁止工具的作答探针，分别评价答案和精确引文支持；一次猜对不能成为上线停止规则。

## 5. 针对真实结果落地的最小 E0.1

**首个语义干预只改C Reviewer的来源归属合同。** 原 `need_review.txt` 完全保留，新增 `need_review_source_grounded.txt`：要求将原题/实际tool观察与历史assistant假设区分，命题支持范围限于可见的主体、关系和限定；不得因候选不符而放宽原题，或把未验证上游绑定当作排除候选的依据。不增加State字段、不改变Actor/工具/schema/输出额度、不强制Open或提交。

保留基础ABC入口，但下一轮推荐 `--comparison source_contract_pair`：同一前缀、同模型、同legacy备忘、同512token上限下，随机交错比较 **C0原合同 / C1来源合同**。3题×2重复×2合同=12分支，每分支Reviewer+Actor，合计**24次逻辑调用**。每个样本的contract写入冻结计划；结果在 `by_contract` 中分别汇总。程序禁止把这个配对实验与indexed交接改动同时启用，避免一次改变两处。

这是提示词整体效果对照，不是单句归因，也不依赖旧批次与新批次的跨时比较。首先评价 `review_source_attribution_correct`，再看需求和Actor。补充 `tool_action_direction_acceptable`、`assistant_assertions_supported`、`final_answer_supported`，避免全0总指标遮住失效位置；旧完整响应主指标保留。

原题、候选初始化、Search/Open、正文预算和默认聊天运行时均不变。原方案无需复杂化初始化；错误的初始想法仍允许存在，但不能在缺少来源时逐轮升级为事实。

| 配对实验后观察到的失败 | 下一轮只改一处 |
|---|---|
| C1仍把历史猜测当观察 | 固定事实清单/角色分离输入做读取诊断；或单独替换Reviewer模型，其他条件固定 |
| 审查来源正确，需求仍过宽或只为证明候选 | 只改Information Need的粒度和决策作用域 |
| 需求合理但Actor不响应 | 固定证据注入两种合理需求测方向变化，或单独测试indexed交接；不自动要求服从 |
| 方向合理但正文持续伪造关系 | 单独测试Actor证据使用合同/模型，不删除正文来掩盖错误 |
| 审查与动作都合理 | 才执行真实工具E1，不能使用原轨迹未来观察替新查询结果 |
| 证据充分但持续搜索 | 另选对应前缀做停止探针；本轮出现的是提前提交，不能据此训练式推动更早停止 |

模型能力是待排除其他因素后的解释之一。若仅换强Reviewer能改善而Actor仍失败，再分别测试Actor；不要同时更换两个模型与预算后归因“State无效”。不存在充分证据表明加图结构、更多字段或强制换候选能自动修复当前语义问题。
