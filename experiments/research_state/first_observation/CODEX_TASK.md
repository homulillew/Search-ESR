# Codex任务：只推进原题首搜与首次来源笔记

先读本目录README、两个prompts和`全链路排查报告/原题直搜与首次Observation来源笔记节点设计.md`。本任务不接入默认Agent，不回到goal/query生成，不执行完整rollout。

## 执行边界

第一交付点：真实原题首搜O1及自动来源笔记的保真分析。完成后先报告；不要自动运行Actor。用户明确继续时，按README另生成actors计划执行A/B。完整两阶段最多6次Search、18次模型，初始化0次、后续工具0次；实际失败保留，不补到“成功数量”。

1. 记录当前commit、工作树和实际环境；遵循AGENTS.md（如有）。不要覆盖用户修改。运行新增离线测试和可运行的既有相关测试，明确哪些未运行。
2. 在看到首搜结果之前锁定六题。建议517、546、776、519、191、71；都是开发题。使用当前数据集原query字段，从零开始。不要使用旧s21/s29/s53前缀、gold、旧最终答案、手工候选或先前笔记。
3. 先检查真实BCPlus脚本、metadata query_prefix、查询最大长度与tokenizer一致；接口应为当前Search/Open baseline。代码的1024查询token保护沿用既有检索实验假设，必须在实际外部脚本上核实，无静默截断。环境不兼容时报告并暂停，修改需另留版本。
4. 检查profile的model/endpoint、输出cap、timeout、sampling和推理参数实际含义。示例不是已验收推荐值。SDK重试0；首次正式请求前冻结，不根据某题结果选择profile。必要的服务兼容pilot单列计费/失败，不混入节点效果，也不重试直到全成功。
5. 运行select和collect。检查实际请求query与原题字符串完全相同，初始生成模型调用0；确认每题账本和原文版本、范围、窗口预算。不额外Open，不用全文替代未见窗口。保留query_over_budget/search_error，不筛掉难题。
6. 生成notes计划并逐项核对真实请求，不含qid等评价标记或任何答案。执行一次notes批次、导出卡片。先看Q/O1写支持范围，再看交付笔记，记录已知历史病例及评阅者身份。代码检查quote存在不等于statement成立，尤其检查主体、时间、否定、同一对象、缺失≠不存在。
7. 无效/截断/超时均如实保留，不修改JSON或扩大预算后补采。合法空notes同时评价是否漏掉重要内容。报告API交付与语义质量两个层次，不能把无输出全记语义0分，也不能只报成功子集。

## 显式授权的后续A/B

使用冻结的同一O1和完整notes原始记录，不手工修正笔记。A只给原文，B多一条可错笔记。无效/空/API失败回退应逐对象与A请求一致，memo_injected=false；本地中断/篡改先修复记录，不伪装回退。只记录下一完整响应，所有工具都不执行。多工具批次整体评价，不能挑最好一条。

逐题报告：原题→原题query→O1实际支持什么→笔记记录/越界/遗漏→A/B完整动作→具体信息是否被使用→成本/失败→下一次只改哪里。合理背景推导用于探索与冒充来源事实分别标注；相似query不直接判无收益。没有同期初始化比较，不宣称原题直搜普遍最优；没有执行后续工具，不报告新证据率或答题成功；立即加笔记的收益不等于跨步记忆收益。

## 交付

保存题目选择、采集计划/记录、完整模型计划/源码/请求/响应/错误、用量与未知字段、首轮标注和中文节点排查报告。SQLite可能包含完整文档，留在执行环境供恢复；推送时检查体积及许可，不默认把整份数据库/索引/权重提交。不得提交密钥、.env或认证头。若本次有推送授权再提交记录；否则提供结果等待明确指令。未执行的测试、真实调用和工具不得写作已完成。
