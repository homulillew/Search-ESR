# Stage C: ActiveGap → action class

Twenty-five pre-call reviewer cases contain five each of source, location, context, closure and complete uncertainty. They are low-ambiguity controlled Progress Views made from actually observed checkpoints. The complete class is a **local diagnostic subtask** with its local claims explicitly verified; it does not say the full original question was answered. D#/W# for legacy histories are new packet-local aliases, with raw source identity recorded separately. Orthogonal Search handles remain literal. The eight cases listed in `stage_d_preselection.json` were fixed before any Stage C response: two each for Search, Find, Open and Verify.

Each case is sampled twice with alternating C-A/C-B order. C-A has no tools and must output one action class plus parameters. C-B has the existing Search/Find/Open declarations and one experiment-only Verify declaration; a no-tool final response is Submit/Stop. The default runtime and backend are unchanged. One response per arm/case, no tool execution, zero retries. The first proposed action is the primary classification; all batch calls and argument validity are retained. No action is masked.

The Stage C practical gate applies to **C-A abstract routing**: ≥75% overall correct and ≥60% in each uncertainty class. C-B is the free-action diagnostic, especially `P(Verify | closure)`. A low C-B Verify rate alone does not block Stage D: closure cases then compare free choice against harness-triggered Verify. Report C-A and C-B separately; neither action count nor a correct-looking tool call is useful-evidence gain.
