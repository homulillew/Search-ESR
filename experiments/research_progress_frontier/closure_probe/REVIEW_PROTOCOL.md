# Stage A case and label review

The case bank was assembled before DeepSeek calls from exact windows present in eight historical qids. Each qid contributes one directly supported local claim, one explicitly contradicted local claim and one conjunction or missing-detail claim that the selected windows cannot close. Five additional claim-level stale cases use historical continued actions at already observed checkpoints. Selection is fixed in `case_specs.py`; `build_cases.py` only copies historical text and checks handle provenance. The model receives none of the labels, review reasons, prior plans, historical continued actions or answer keys.

`supported` requires the listed excerpt to establish every part of the claim; `refuted` requires explicit incompatibility; `open` covers relevance without enough evidence, including a single matched clue in a larger conjunction. Absence from a snippet never refutes a claim. Historical articles are treated as observed sources, not as ground truth about the world beyond their text. The supported/refuted pair for several qids deliberately tests sensitivity to the claim wording over the same observation; these sibling cases are correlated. Stale-gap cases test recognition of closure for a narrow subclaim even while the full research question remains open. `stale_1034_model` has medium ambiguity as a stale-*action* example because the historical query included other unresolved clues; keep it in the frozen set and report sensitivity without it.

Older histories preserve raw `docid`/`w_...` refs, while Orthogonal Search histories preserve D#/W#. `ref` and `doc_ref` contain the original observed handles for each protocol. Every full excerpt in `review_cases.json` must match the specific historical search result or R1 prefix preview. A private `provenance.json` records exact source files and stale-action provenance. No later tool observation, full document audit, final answer or future trajectory is used to decide the semantic label.
