# 观察摘要最小对照：预设方案

固定 baseline 原文窗口、检索器、系统提示词、工具描述和 schema。两组均使用 ObservationStore，唯一干预为每次 API 请求末尾是否附加一条机械生成的观察摘要。摘要作为独立 user-role 上下文消息传递；原系统消息与工具返回不改动。摘要不累积到持久 messages，不指示 Search、Open、候选切换或提交。

摘要记录上次 API 请求后返回的窗口、新增正文区间、重复引用、正文重叠字符，以及最近三次 Search 的新增来源字符数。新字符不等于新证据；标题与正文按账本算法计数。摘要最多 1200 个本地 tokenizer tokens，超长时省略部分窗口明细并显式记录省略数，保留总计。token 数用于控制干预长度，不冒充 API 的计费 token 数。

## 样本与预算

- 自主轨迹：此前预选新题前六题 580、905、1034、593、177、387，使用已归档的真实首轮 query/top5。两组各重复两次，共 24 次。后续检索实际执行。
- 局部控制：完整重复、部分新增、信息已充分、信息尚不足四类，两组各两次，共 16 次。使用真实文档与真实窗口构造器生成相同历史。人为预置重复是诊断干预，不代表自然出现频率。
- 每次最多四轮后续工具调用，再强制终答；API completion 上限 2048 tokens，单次超时 120 秒，无 SDK 自动重试。失败如实保留，不静默补跑。API 并发四，检索串行共享模型。
- 模型及 thinking 沿用配置。任务和顺序种子 20260918，在取得结果前保存。参考答案及参考区间仅用于离线检查，不发送给模型。

## 主要指标

1. 自主轨迹：后续 Search 零新增比例、连续零新增次数、正文重叠比例、工具调用数、强制终答率、API token 消耗。
2. 新旧判断控制：完全重复时能否说明没有新增；部分重叠时引用的新增原文是否确实属于新增区间。人工审阅与原文位置核对，不能仅用出现“新增”一词自动判错。
3. 信息充分控制：核心事实正确且已观察支持，是否增加无必要工具操作。
4. 信息不足控制：原本不可见的参考片段是否取得、核心回答是否正确。Open 次数只描述动作，不当作成功指标。
5. 所有会话：工具原文一致性、摘要与账本一致性、无摘要组不出现摘要、来源引用合法、错误状态。

自主 BC+ 六题不以四轮最终答题准确率作为主指标。核查关键支持材料作为探索性结果，不将更多新字符等同于更好的证据。小样本重复不构成泛化证明。若两组波动较大、控制任务退化或成本明显上升，不升级默认运行时。
