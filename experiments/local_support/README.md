# 局部信息支撑测试

目标：Search–Open 为模型提供适量、相关、可解释、可继续读取的原文。此处不要求完成 BC+ 原题，不测试 gap、候选纠偏或停止策略。

`python experiments/local_support/run.py` 冻结当前工具代码，对 20 个手工局部信息需求运行旧前缀与新窗口两组阅读会话。文档预先固定，不测试召回；模型可最多继续读取两次，再交接观察到的信息。只使用模型实际接收的原文，参考片段另存于 tasks.offline.json，不发送给 API。

样本包括 11 个已用文档上的正向回归需求、1 个不匹配控制、8 个未用于窗口调优的新需求。它们是人工挑选的便利样本，非随机 BC+ 评测集；新增样本也不应被称为严格独立的泛化基准。

旧方案为 1600 字符前缀，get_document 默认 8000 字符。新方案为标题＋正文最多 400 本地 tokenizer tokens，Open 使用现有预算。两组不是严格等 token 对照，实际正文与序列化返回量分别记录。

`python experiments/local_support/analyze.py <运行目录>` 计算参考片段可见性、一次预设读取的可达性、实际读取、API 用量、返回 payload token 估计与无效窗口引用。单个参考片段不是完整语义标签，同一事实可能在其他位置表达；自动可见性仅是窄代理指标，不等于证据支持率或答案准确率。

每次运行独立目录，保存源码、完整请求/响应、实际读取和模型信息交接。不得把初次带有测试协议问题的运行与修订后的复跑混算。
