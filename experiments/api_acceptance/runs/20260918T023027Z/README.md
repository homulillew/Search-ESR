# Search–Open真实API接口验收

## 结论
当前工具实现可继续冻结为研究基线；当前系统提示词与模型的信息使用行为不能判为全面验收通过。工具原文及参数接口工作正常，但本实验没有观察到自主Open，且发现漏读、引用缺失、错误增补和新旧观察混淆。不能宣称此前三个原型问题已经解决。

## 实验设计与配置
沿用仓库真实AgentSession、TOOLS、Config.system_prompt + AGENT_PROMPT、全库dense检索和当前Search/Open；工具描述和系统提示词未修改。模型qwen3.7-flash，enable_thinking=false，无内置websearch。原始8个局部短查询各2次，共16次独立会话，最多64轮工具调用请求，随后强制终答，保留完整SDK请求响应。未向模型提供参考片段、目标文档ID或标准答案。生产文件与冻结清单全部哈希一致。

8类需求：Constant Gardener角色、Peter King生日、Fifth Estate角色、Shevchenko117分钟事件、Riise末段任意球、丁俊晖首轮对手、What-a-Mess正式名、Gromenkova决赛对手。

事前PLAN.md规定机械接口与实际证据使用分开验收，Open次数不是成功指标。实验不比较新旧模型表现，也不声称泛化收益。

## 原始16次会话

- 16次均生成最终回答，但只有15次自然结束；local_04_r1达到64轮后由harness强制终答。
- 共122次Search，0次Open。未发生工具执行错误；返回正文全部与数据库指定区间一致。
- 只有2/16最终回答给出完整window_ref；这两次引用均已在该会话返回。没有引用不能算作引用正确。
- SDK报告累计8,355,861 tokens，其中local_04_r1占6,823,360；为各次请求累计输入输出，不是唯一信息量，也不换算费用。

零Open本身不表示失败。Fifth Estate在另一篇演员表中直接找到Oscar Kamau Kingara，Gromenkova也直接找到Anh Le，这些无需额外阅读。但Constant Gardener两次都已取得67431，却只回答minor role或否定Peter King身份，没有读取紧邻后文中的Policeman 1。这是已有相关文档而未继续阅读的明确坏例。

## 分层坏例分析

1. local_01_r1/r2：初始窗口458–2044包含参演描述，角色表在后方；模型分别Search 3次和1次后结束，没有Open。r2还把Peter King与Peter Nzioki分开理解。工具能继续读，不代表模型会采用。
2. local_08_r2：初始材料包含117分钟double save，模型却写成penalty，并追加未被观察支持的得分者。信息已出现，事件关系仍可能读错。
3. local_09_r1：正确复述任意球被挡，却追加Riise在该场常规时间任意球得分的错误说法。核心事实正确不能替代整段回答的依据审查。r2把end of extra time精确化为120th minute，属于超出片段原文精度的推断。
4. local_18_r2：正确说出Anh Le，但把参赛者上过的WSOP Academy课程名称挪到赛事名称上。属于邻近事实归属混淆。
5. local_04：原始Peter King birth date没有指定身份，被模型解释成政治人物，Search分别64与25次。返回中出现过肯尼亚演员生日，但模型仍围绕政治人物继续查找，并在终答给出未由观察核实的日期。这不能作为窗口对演员生日的失败率；它暴露的是问题歧义、候选选择和重复搜索。
6. local_14：原始短查询分别搜索6与13次，均未检索到原固定文档78848。一轮追向乐队，另一轮追向Top Cat并生成错误身份。不能把未发现目标文档归咎于文内窗口。

逐会话证据见audit.json、各目录events.jsonl、trajectory.md和answer.md。这里只人工核查核心事实及明显附加错误，没有宣称逐句全面语义评分或答案准确率。

## 事后消歧补测，单独统计
目录：/tmp/search-esr-api-acceptance-disambiguated/20260918T023410Z。
两条查询分别明确写出Peter King Nzioki Kenyan actor、What-a-Mess cartoon Afghan hound dog，各重复2次。4次均仅Search一次、无Open，均返回目标信息，说明短查询歧义对原实验存在实质影响。此为观察失败后追加的诊断，不与原16次混算。

生日回答发现两来源分别记载25 May 1978和14 June 1979，来源冲突确实存在；模型关于“广泛认可”及来源可靠性的判断并没有由这些片段独立证明。What-a-Mess两次均给出Prince Amir of Kinjan，但r1把相邻Bump条目混入其作品介绍。原文是列表，窗口内邻接不等于事实属于同一主体。这是可复现的观察归属风险，不应通过在工具内猜测身份来遮蔽。

补测仅1/4回答包含window_ref；累计19,159 tokens。

## 四个明确要求阅读的接口探针
probes/保存完整请求响应。历史Search由脚本预置真实builder返回，不是真实API自行搜索；随后明确要求读前、读后、扩展或检查边界。仍使用现有系统提示词、TOOLS和AgentSession。它们只检验接口使用，不能证明自主阅读策略。

|探针|实际行为|解释|
|---|---|---|
|before|正确引用及before，15709–17331 → 10602–15709|接口正确，但把初始窗口里的Riise句子称为新增摘录|
|after|正确引用及after，458–2044 → 2044–2790|读到Policeman 1并正确使用|
|around|正确引用及around，458–2044 → 0–2790|读到角色，但所称新增摘录其实已在初始窗口内|
|complete|对完整0–372文档请求after，返回相同ref和document_boundary|无新内容；模型随后正确说明无下文，没有循环|

三个方向均调用成功，无不存在窗口引用。2/3实质续读探针误把旧文本标作新增。边界探针的一次冗余读取不是严重接口故障，也不能当作有效信息增益。

## 冻结判断与下一步
冻结工具实现是合理的：返回可追溯、方向及边界接口可执行，此次没有需要立即修补的切片或引用执行错误。冻结不等于自主阅读和证据使用已经通过。保持这份工具实现，后续把模型如何决定继续读取、如何区分已观察与新增内容、如何约束结论依据作为独立模块研究。

最近的一步可做最小提示词对照：只澄清窗口局部性、周边继续读的触发条件及引用要求，不强制每次Search后Open，不加入gap状态机；同一批冻结观察上比较是否取得角色行、是否减少无依据否定、是否正确引用。必须单独版本化，不把工具和提示词同时修改。本轮未实施此提示词变更。

全部结果因/data分区已满暂存在/tmp；未删除旧文件，未修改生产配置或冻结代码。
