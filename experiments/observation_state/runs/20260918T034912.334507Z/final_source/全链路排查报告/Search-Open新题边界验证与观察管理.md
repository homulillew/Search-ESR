# Search–Open新题边界验证与观察管理

## 本轮问题与范围

此前的表格入口修复解决了一个具体截断：Peter King 的作品表只展示表头，角色所在的首行被截在窗口之外。但真实触发收益的文档只有一篇，尚不能说明该规则在其他文档上同样合适。另一方面，模型仍可能重复 Search，或将已经展示的内容称作新增。这需要来源与观察记录支持后续 harness 判断。

本轮分别验证呈现边界和接入观察管理。窗口侧继续检查预算、原文区间和结构取舍；观察侧记录已经返回的来源范围，并支持进程重启后的 Open。问题拆分、gap、候选纠错和提交判断仍由后续实验处理。系统提示词、工具描述及模型可见字段未修改。

## 新题选择与边界验证

使用固定种子 919，从 BC+ 中排除此前讨论的七道题，再预先选择 12 道新题：580、905、1034、593、177、387、729、496、49、645、1224、802。API 只接收问题，不接收参考答案。每题由真实 API 产生首轮 query，再使用现有 Qwen3-Embedding-8B 检索器取得 top 5 文档。

共取得 60 个不同文档，其中 5 篇包含可识别的 Markdown 表格，17 篇命中列表行格式检测。首轮窗口在 baseline 与原表格入口候选之间全部相同。这个结果说明修复在这批自然首轮检索中没有触发，不能计为候选收益。

|检查|结果|解释范围|
|---|---:|---|
|自然首轮窗口|60 个|两版全部相同|
|before / after / around|180 次|原文切片与方向位置约束通过|
|重复窗口记账|60 次|再次返回相同窗口时，新增原文为零|
|首尾落在既有分段单元边界|60/60|机械边界正确，不等于语义上下文充分|
|真实表格上人为构造入口截断|10 个，来自 5 篇文档|原候选均在预算内修复并保留锚点|

最后一项专门把窗口结束位置放到真实表格入口，用于检查实现能否处理其他文档的结构。它属于压力测试，不能并入自然检索命中率。重复运行中曾复用过观察数据库，相关目录标记为 `boundary_audit_reused_excluded`；表中结果来自重新创建数据库的正式审计。

## 新发现：补齐下一张表可能裁掉上一张表

随后选择上述预选列表的前六题，对 baseline 和原表格入口候选各跑一次短轨迹。qid=905 的一次后续搜索召回文档 40817《List of actor-politicians》。这篇文档包含连续的多张表，旧规则为了补齐下一张表的首行，需要从窗口左边腾出预算，因而裁掉了上一张表已经展示的数据行。

|后续 query|基线区间|原候选区间|观察到的取舍|
|---|---|---|---|
|`"father represented a state" "mother was an actress" politician`|[60154,61531)|[60443,61681)|裁掉先前演员政治人物记录，加入下一表 Bobi Wine 行|
|`"mother was an actress" father politician state assembly house parliament`|[59683,61128)|[60018,61307)|裁掉先前表格记录，加入下一表 John Dumelo 行|

这些返回发生在一次最终 API 请求失败的轨迹中，但窗口已经实际生成并进入请求，原文位置可以独立复查。现有证据证明结构取舍存在风险，尚不能证明它导致了最终答案错误。

原规则保护了定位锚点，却没有保护窗口内已经展示的其他表格记录。下一表首行只是结构上的第一条记录，不天然比上一表的数据更有价值。因此增加一条保守限制：**如果补齐表格入口需要从左侧裁掉任何已有表格数据行，就放弃这次修复，保持基线窗口。**

该规则独立保存为 `table_entry_safe`。它不比较人物、关系或答案相关性，也不尝试重新分配多个表格的语义权重。原 `table_entry` 与 baseline 均保留。当前 CLI 默认窗口仍为 baseline，安全候选需要显式启用。

回归结果为：20 个旧局部案例中，带参考片段的 19 个案例仍由首次可见 16/19 提升到 17/19，无退化；60 个新题首轮窗口不变；上述两处风险均回退为基线。它保留了已知角色题的局部收益，但不是无损裁剪保证：在其他情形中，预算内补齐表格仍可能裁掉普通段落。

## 观察管理如何接入

新增运行时在工具返回后校验并保存来源、区间和引用。模型收到的工具对象保持原样，新增字段只存在于观察账本。

覆盖范围按文档 ID 与原文 SHA-256 分开管理。每次返回计算正文和显式标题的区间并集，再与此前有效观察相减，得到新增原文范围。完全重复的窗口和不同引用但重叠的窗口因此能够分别识别。全文缓存用于恢复 Open，只有实际返回的正文和标题计入观察覆盖。

|能力|实现后的行为|
|---|---|
|来源验证|正文、标题、窗口引用与原文位置一致后才落盘|
|新增与重叠统计|记录新字符区间、重复引用、正文重叠字符数|
|进程恢复|加载最后完成的对话轮，旧引用沿保存的原文继续 Open|
|来源版本变化|不同 SHA 分开记账，旧引用不切换到新来源|
|失败轮处理|恢复上轮对话与有效覆盖，失败事件保留审计|
|会话清空|清空有效观察与 messages，保留历史事件|
|并发保护|同一状态文件只允许一个写入会话|

这一步记录“系统返回过什么”。它没有认定模型已经理解这些内容，也没有把新增字符数定义成研究进展。重复返回可能用于复核，新段落可能与任务无关，后续 harness 仍需结合模型的语义判断。

## 真实 API 验证与解释边界

模型沿用 qwen3.7-flash，关闭 thinking，系统提示词与工具 schema 保持原版。每个短轨迹预置同一真实首轮 query 及其返回，然后允许最多四轮后续工具调用，再要求终答。后续 Search/Open 实际执行。这是工具链与观察状态验证，没有运行 64 轮完整求解，也没有用参考答案评定 BC+ 正确率。

原定 12 次短轨迹中，11 次完成，1 次在最终请求出现 `BadRequestError`。该失败保留，另建目录重试后完成，不将重试隐藏在原结果中。初次 12 次尝试共审计 260 个返回窗口，包含失败尝试产生的窗口；所有已发送工具对象与账本原始返回一致，原文及 SHA 校验通过，未发现工具执行错误。260 不是成功会话的有效观察总数。

11 个首批成功会话及单独重试均完成进程重启后的引用恢复检查：使用新窗口构造器，通过旧引用执行 Open，结果与重启前一致。该检查是程序直接调用，不能用来证明模型会主动扩大阅读。

另外从 qid=387 的已完成状态复制数据库，用真实 CLI/API 请求模型执行一次指定方向的 Open。调用成功，但模型称之为“新增内容”的摘录，账本记录 `new_chars=0`，因为这些字符之前已通过其他窗口返回。这提供了一个可复核案例：**账本可以识别零新增，模型的文字描述仍可能错误。** 当前未向模型注入账本，因此不预期这一错误自动消失。

安全候选还在真实 CLI 中复测角色题，模型经过两次 Search、一次 Open，最终回答 Policeman 1 并给出窗口引用。这是运行链路检查，单次结果不代表 Open 行为已经稳定改善。

补充的 qid=905 安全候选轨迹完成了四次后续 Search，但最终回答请求发生 `APITimeoutError`，没有取得终答。其 25 个返回窗口均通过原文和传递一致性审计，工具执行错误为零；该失败单独保留，不能计为安全候选成功完成新题。它与前述 12 组实验的独立重试属于不同尝试。

## 当前结论与后续接口

本轮完成了新题呈现边界检查、一个由新文档暴露的保守修正，以及可恢复的观察管理。49 项自动化测试通过。原冻结清单中的代码、工具提示词、窗口实现及测试文件保持原哈希；新运行时和候选单独存放，CLI 接入观察管理。

目前可以据此继续构建后续 harness：它已经能够查询某个文档版本返回过哪些区间、一次工具调用是否带来新原文，以及某条引用对应哪个来源。下一轮应独立比较是否向模型提供紧凑的观察摘要，以及该摘要能否减少把旧内容当作新增、重复搜索和无依据的全文否定。指标应分别记录重复原文比例、有效新增、任务相关证据取得及 API 成本，避免仅用 Open 次数评价进步。

尚未验证的边界包括复杂表格变体、超长结构单元、更多自然截断以及长期状态文件增长。当前没有自动删除重复工具文本、上下文压缩或缓存回收，也没有加入强制 Open、候选切换和提交拦截。
