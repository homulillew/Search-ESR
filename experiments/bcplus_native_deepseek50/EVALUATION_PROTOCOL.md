# Offline evaluation protocol

Evaluation starts only after `runs/BATCH_END.json` and all 50 per-question summaries/events exist. The online runner imports `ONLINE_INPUTS.json`, never the dataset JSONL or any gold/earlier answer. Each frozen qid stays in the denominator regardless of failure, empty answer, or emergency cap.

The upstream BrowseComp-Plus repository contains `BCPlus/upstream/scripts_evaluation/evaluate_run.py`, a Qwen3-32B LLM judge with a published answer-equivalence prompt, and `evaluate_with_openai.py`, a GPT-4.1 variant. The upstream `docs/llm_as_judge.md` identifies Qwen3-32B as the submission judge. These sources are audited and their SHA256 is frozen below. The Qwen3-32B weights and `vllm` are absent locally; installing and running that judge would introduce a separate model and evaluation cost. This experiment's primary reported score is therefore explicitly a **conservative project deterministic score**, not an official BC+ leaderboard score. An official judge result, if produced separately, must carry its own model/version and must not silently replace this frozen score.

Deterministic primary: Unicode NFKC, case folding, whitespace collapse, and safe punctuation normalization. The scorer examines the first answer line after fixed, anchored prefixes such as `Answer:` and `The answer is`; it removes a trailing citation. The normalized candidate must equal the normalized gold. No fuzzy rescue, free substring search, LLM judging, or post-hoc manual changes to primary correctness. Empty answers and failed runs are incorrect. All 50 qids remain in the denominator. The implementation is `evaluate.py`; tests cover exact correct, case, obvious wrong, alias mismatch, empty answer, and failed-run handling via status gating.

All nonempty deterministic mismatches enter `MANUAL_ADJUDICATION_QUEUE.json`. Its cards contain exactly question, gold answer, final answer, and a blank decision; they omit qid, trajectory, and experimental arm. A reviewer can mark `correct`, `incorrect`, or `ambiguous`; ambiguity is not primary correct. Manual decisions may be reported as an adjudicated secondary upper bound, with no modification of the deterministic primary.

The 95% confidence interval is the Wilson score interval for `correct/50`. Natural/completed/emergency conditional accuracy is secondary. `gold_answer_string_observed` checks whether normalized gold occurs within any Search/GetDocument observation after the 50 online runs; it is explicitly a heuristic, not retrieval recall. Citation fidelity is a separate diagnostic using observed docids and URLs. Post-hoc failure labels are explanatory and never change correctness.

Estimated DeepSeek cost uses response token usage, cache hit/miss tokens, request time in Asia/Shanghai, and the provider's 2026-09-28 published peak/off-peak CNY prices. Current published rates per million Flash tokens are peak: ¥0.04 cache hit, ¥2 cache miss, ¥8 output; off-peak: ¥0.02, ¥1, ¥4. Peak is China time weekdays 09:00–12:00 and 14:00–18:00. Any missing or inconsistent cache usage is reported and left unpriced. This is an estimate, never a billed amount. Source: <https://api-docs.deepseek.com/zh-cn/quick_start/pricing/>.

Official judge source SHA256 values are recorded in `GRADER_SOURCE.json`. This protocol and evaluator are frozen before paid online calls.
