# 当前项目的最小实验路线

本方案依据 [远程审计](01_ESR远程仓库审计报告.md) 和 [逐例复核](02_典型bad_case与证据边界.md)。此文件是后续实验建议，本次尚未修改或运行新的 harness benchmark。

## 1. 从可审计基线开始，首先检验证据获取

第一步不是复制旧 environment，也不是给系统提示词叠加纠偏句。先把当前已经可用的 `qwen3.7-flash + Qwen3-Embedding-8B + search/get_document` 固定下来，保证每一步实际输入可以追溯。

当前基线已有分页读取，不受旧 baseline 的 directory 门禁影响；因此旧报告的提交率和效率不能作为当前基线的替代测量。

先完成最小实验记录：

- episode：qid、question、配置快照、代码版本、最终答案、终态；gold 不进入 agent/runtime/verifier。
- API：角色（research/replan/verifier）、model、请求消息、响应、usage、耗时、重试次数。
- 工具：query、参数、返回 docid、展示原文、字符区间/hash、缓存命中、耗时。
- 预算：分别记录模型请求、工具动作、输入/输出 token、总时间；本地 embedding 耗时单独计。
- 失败：区分 API、格式、工具、上下文、预算耗尽与正常回答。

无需先创建通用事件框架。逐行 JSONL + 配置 JSON + 不可变片段文件，足够支撑第一轮。

## 2. 样本与金标隔离

- 开发诊断集：120、186、324，加 533 检查停止路径；这些题已经在讨论中暴露答案，不能作为未见泛化证据。
- 另固定抽取小规模随机 pilot 集，例如 20 题，保存 qid 清单和抽样种子；先不读其答案和轨迹调参。
- 小样本用于发现实现缺陷与估计成本，不宣称统计显著。
- 同题同配置有重复运行，记录服务端实际返回 model 标识；若模型不支持可靠 seed，不声称确定性复现。
- 正式结果保留独立测试集，gold 只用于运行结束后的评测。

旧 bad cases 的正确 docid 可以用于**工具可见性单测**，但应与 question-only 的端到端搜索实验严格区分。

## 3. 第一个单因素对照

研究假设 H1：在固定一级文档检索器与返回文本预算下，query-relevant chunk 比固定文档前缀更容易获得支撑答案的材料。

| 项目 | A：当前工具 | B：只改观察内容 |
|---|---|---|
| API / thinking / 提示词 | 固定 | 相同 |
| 文档索引、embedding、top-k | 固定 | 相同 |
| search 返回 | 每篇前缀 | 每篇 query-relevant chunks |
| 展示总预算 | 固定近似 token/字符上限 | 尽量匹配，并记录实际值 |
| get_document 分页能力 | 保留 | 相同 |
| Compact / Replan / Verifier | 不新增 | 不新增 |

先使用确定性的文档内词项排序实现候选 chunk 选择，记录算法和参数；不同时加入额外 LLM 摘要或 reranker，否则无法区分收益。chunk 引用绑定原文区间和 hash，不生成改写证据。原始片段保留上下文，避免截断否定或限定条件。

分两种观察：

1. **固定 query 与候选文档的离线比较**：检查正确段落可见性、截断、provenance、处理耗时。这里 gold/证据标注可用于离线评估，不进入运行时。
2. **自动 Agent 对照**：允许新观察改变后续 query，测端到端答案与成本。不能假设两组会走同一条 trajectory。

报告至少包括总体正确率、终态分布、搜索/读取次数、总 token、耗时、观察到的支持/反证、重复结果情况。新文档数只作为描述性指标，不视为语义进展。

## 4. 第二步才引入 Compact Research State

H2：有界状态能保留关键证据与未解问题，并减少长历史成本，且不明显损害答案质量。

先保留原型中的五个字段：question、criteria、candidate、known_facts、open_questions。candidate 可为空和撤销；known_facts 可表达矛盾、关系与限定条件，并引用不可变 chunks。

需明确三件事：

- archive 保存全部观察，但 working state 只保留有用部分，不能要求全目录 coverage。
- state update 输入包括旧状态和本 cycle 的实际观察；校验引用确实存在且曾展示，不替模型判断语义真假。
- 每个字段和总状态设可记录的长度预算；仅规定字段数不保证状态有界。

先定义 cycle 边界，例如局部自主调用达到小预算或模型产生语义更新时结束；局部 search/read 顺序不固定。状态维护的额外模型调用必须计入总成本。

## 5. 第三步测 NO_PROGRESS → REPLAN

H3：连续状态无实质变化时，一次独立的重新规划能增加有效转向，收益超过额外调用成本。

v0 使用规范化状态差异作为代理信号，名字明确为“状态停滞”，不冒充已测到语义进展。排序、空白、重复事实、仅换 citation 的更新不能轻易重置计数；候选变化和问题列表变化也需要在人工分析中核对是否真有效。

对照：有 Compact 的版本 vs 同版本加停滞 Replan。保持工具、状态预算一致，并另提供匹配总 token/请求预算的比较。

记录：触发前后 candidate 是否变化、关键问题是否解决、有效证据是否新增、最终答案是否改善、误触发是否打断有效搜索。replan 接收压缩状态及简短轨迹摘要，输出语义调整，不由 runtime 强行判候选错误。

## 6. 最后加入独立 Final Verification 与自动结束

H4：独立审核减少错误回答，且额外修复成本与误拒率可接受。

Verifier 输入必须包含原问题、候选、criteria/claims 和**实际展示过的 citation 文本快照**。不能动态重跑 chunk 检索重建“它应该看过的内容”。

输出保持简单：PASS / REPAIR 及 missing issues、contradictions。格式错误、服务错误、上下文超限在 runtime 内处理，不进入 open_questions。

- PASS：runtime 自动 DONE，返回已审核候选；避免另一次自由生成把答案改坏。
- REPAIR：把缺失语义问题交回研究过程，避免将错误候选固化为“寻找证明它正确的证据”。
- 预算耗尽：明确输出 budget_exhausted_unverified 等终态，保留 best candidate 供离线评估，不伪装成 PASS。
- 同一 candidate/证据快照的重复拒绝不自动推定 verifier 错；不采用“拒绝 N 次就放行”或 gold token 命中兜底。

单独报告 false pass / false repair 的人工抽查、纠错成功率、额外调用、总正确率和覆盖率。新 API 更强不代表 verifier 不需要校准。

## 7. 首阶段建议修改范围

以下是后续候选清单，不代表已经实施：

| 文件 | 最小改动 |
|---|---|
| `llm_chat/client.py` | 统一请求记录与 usage、错误类别；保持 key 不落日志 |
| `llm_chat/agent.py` | episode 轨迹、终态、工具原始结果快照；不先引入全套控制器 |
| `BCPlus/scripts/search_bcplus.py` 或新的薄 adapter | 文档内 chunk 返回对照；一级检索不变 |
| 新 `experiments/run_pilot.py` | 固定样本和配置、逐题隔离、结果落盘 |
| 新 `experiments/evaluate.py` | 运行后评测，与在线 verifier 分离 |
| 对应小范围测试 | 工具 schema 一致、分页可达、片段 hash、同输入同快照、错误不改语义状态 |

如果后续加入完整 Thin Harness，可用 `state.py / evidence.py / runtime.py / verifier.py` 小模块组织；在 H1 完成前不需要搭好全部架构。

## 8. 设计裁决原则

- 旧轨迹用来提出假设和 regression，不作新模型的效果结论。
- 工具和提示词、状态、预算一次只改一个主要因素；架构收益与更多计算量分开分析。
- 修复协议 bug 是建立公平实验的前提，不必包装成新的研究机制。
- “Search 返回 Evidence”“No-progress 检测”“Verifier PASS”都需要明确可测定义。
- 先有实际失败证据再增加对象与分支；可达成功路径、稳定成功率、统计泛化是三个不同层次。
